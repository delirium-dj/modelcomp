# RULES.md — ultimate project rules (precedence #1)

If any other doc, task file, script message, or commit message conflicts with
this file, **this file wins**. `.agents/rules.md`, `tasks/research.md`, and
`tasks/sync-data.md` hold the detailed procedures — they elaborate, never
override.

## Identity roster — single point of reference (generated, never restated)

- `model-aliases.generated.md` (repo root, regenerated by `pnpm sync` from
  the code lists in `scripts/lib/validate.mjs` and `scripts/lib/average.mjs`)
  is THE roster of every forbidden or redirected identity: parked (retired)
  slugs, merged-and-deleted duplicate slugs, retired vendor aliases,
  merged-and-deleted duplicate findings-file stems, and kept-tracked
  alias-family records (tier-alias families like Muse Spark, access-tier
  families like Nemotron, composite records like Union Alpha). Anything
  listed there is never scaffolded, queued, researched, or written to —
  resolve to the canonical target the entry names.
- No prose file restates the roster. Restatements drift (the 2026-10
  `longcat-2.5` parking reached the code lists but not the prose copies);
  rule files POINT here. Evidence history for each entry lives in git
  history and `REPORT.md`.

## Research rules (absolute — no exceptions without explicit user sign-off)

- **Path contract (STEM/slug conflation guard):** a research agent's file is
  always `model/<subject-folder>/<YOUR_STEM>.md` — the FOLDER names the model
  being researched (the subject), the FILENAME is always the agent's own
  reporter STEM. Example: STEM `North_Mini_Code` researching `gpt-5.5` writes
  `model/gpt-5.5/North_Mini_Code.md` — NEVER `model/gpt-5.5/gpt_5_5.md` or
  `model/gpt-5.5/GPT_5.5.md` (the 2026-10 incident: an agent wrote files
  named after the model it was researching). `pnpm sync` FAILs any findings
  file whose `Provided by: **...**` signature names a foreign model
  (signature-vs-stem tripwire, `checkSignatureStem` in
  `scripts/lib/validate.mjs`); a per-instance exception for a legitimate
  spelling variant is recorded there, never in prose.
- `model/<subject>/<YOUR_STEM>.md` must never be deleted, overwritten,
  renamed, or moved — by any agent, orchestrator, script, or "cleanup" /
  "align the dataset" pass. The only sanctioned rename is `pnpm sync`'s
  `QUAR` quarantine (`.md` → `.md.excluded`, content preserved).
- A file may only live as `<YOUR_STEM>.md.excluded` when there is not enough
  verified data to compute the `Overall` score (self-exclusion). `pnpm sync`
  enforces this automatically (QUAR); no human or agent "cleans up" beyond it.
- A research agent skips `model/<subject>/<YOUR_STEM>.md` when that file
  already exists. When it finds its own `<YOUR_STEM>.md.excluded` twin, it
  researches deeper; only with genuinely new verified evidence does it write
  the fresh `<YOUR_STEM>.md` — and only that own twin may then go. Nothing
  else, ever.
- Below-gate and out-of-top-10 reports stay on disk, in git, and on the site;
  the rater gate only filters `average.md` means. Enforcement is automatic:
  `pnpm sync` FAILs on any git-tracked `model/**/*.md(.excluded)` missing
  from disk — except sanctioned survivals (own-twin retirement with a fresh
  sibling present; user-directed relocation with the same path alive under
  `models_voice/` or `models_finance/`, logged as INFO pending commit). The
  committed pre-commit hook (`.githooks/pre-commit`, activate with
  `git config core.hooksPath .githooks`) rejects commits that delete them.
- `model/<slug>/` folders are permanent too: never moved out of the tree or
  deleted, even with zero qualifying raters (a `FALLBACK` notice is an
  accepted standing signal — never a failure). Reporting-agent folders are
  dataset infrastructure — the gate reads the agent's own `average.md` from
  its folder, so a below-gate rater becomes eligible once its model is
  peer-rated above the gate.
- **Parked slugs are never researched (absolute):** any slug in the Parked
  section of `model-aliases.generated.md` must not be queued, researched, or
  written to by any agent or audit pass — dropped even when the audit finds
  the folder on disk missing the agent's file. `model-queue.md` omits parked
  slugs automatically; treat its absence as the queue duty. On encountering
  a parked slug, skip it and surface it — a user only un-parks it by removing
  it from both `RETIRED_SLUGS` lists (`src/data/models.ts` +
  `scripts/lib/average.mjs`). Rationale: every parked folder is a duplicate
  alias or phantom entry already resolved — researching one burns agent
  tokens with zero dataset value.
- **Voice/speech routing (absolute):** a model whose core capability is voice
  or speech (realtime voice API, TTS/STT-first, voice-assistant I/O — name or
  modalities say so) lives under `models_voice/<slug>/`, never under
  `model/<slug>/`. Same permanence, same file conventions — only the parent
  differs. (`models_voice/` sync/site wiring is pending; until then
  `pnpm sync` scans `model/` only.) The retired `voicemodels/` name
  (pre-2026-09-28) must never be recreated: any `voicemodels/` directory on
  disk is a forbidden duplicate of `models_voice/` — merge its contents into
  the matching `models_voice/<slug>/` and remove it; `pnpm sync` FAILs loudly
  while `voicemodels/` exists.
- **Finance domain routing (absolute):** a model designed specifically for
  finance or financial tasks (e.g. `ling-3.0-flash-fin`, ending in `-fin`)
  lives under `models_finance/<slug>/`, never under `model/<slug>/`. Same
  permanence and file conventions (sync/site wiring pending like
  `models_voice/`).

## Identity rules (general — every specific case lives in the generated roster)

- **Tier identity:** a pricing, subscription, or reasoning-effort tier
  suffix (`Contributor`, `Free`, `Standard`, `Max`, `Highspeed`, …) is never
  a separate model. Every tier-suffixed name resolves to its base folder
  (covered by the alias-family entries in `model-aliases.generated.md`);
  whether a tier-suffixed name IS a distinct model is decided per vendor
  evidence (distinct weights/specs), never by analogy to another vendor.
  Removing a forbidden tier-duplicate folder is a sanctioned
  `model/<slug>/` removal, and only with explicit per-instance user sign-off
  (pre-commit bypass `ALLOW_MODEL_DELETE=1`; the sync tripwire clears on the
  deletion commit itself). These exceptions never extend to real model
  folders.
- **Vendor-prefix identity (absolute):** a leading vendor name is never part
  of the slug. A folder named `<vendor>-<rest>` whose `<rest>` already exists
  is a forbidden duplicate, never a new model: strip the prefix and check the
  unprefixed folder first (both trees in full mode), then write into it. A
  vendor-prefixed *API route* (e.g. `opencode/google-gemini-2.5-flash-lite`)
  is still fine to cite as a provider ID inside a report — it just never
  becomes a folder. Enforcement is automatic: `pnpm sync` FAILs
  vendor-prefixed duplicates and writes nothing for them; the pre-commit
  hook blocks staging them.
- **Slug identity (absolute):** version numbers use `.` not `-` (`gpt-5.5`,
  never `gpt-5-5`). Normalize every freshly derived slug before creating or
  comparing anything — each digit-hyphen-digit join becomes a dot — the only
  exceptions are param sizes, never versions (digits immediately followed by
  `b`/`B`, e.g. `gemma-4-31b`, `qwen-3.5-0.8b`, `qwen-3.5-122b-a10b`); single
  majors with codename/experimental suffixes (`gpt-6-astra`) never match.
  Canonical logic: `normalizeSlug()` in `scripts/lib/naming.mjs`. Always
  check for the existing dotted folder first — a hyphen-versioned folder is
  a forbidden duplicate: merge contents into the dotted folder, then remove
  it (explicit per-instance user sign-off). Enforcement is automatic
  (sync FAIL + zero writes; pre-commit blocks staging).
- **Findings-stem identity (absolute):** version numbers inside a findings
  STEM use `.` between the digits, never `_` (`Laguna_XS_2.1.md`, never
  `Laguna_XS_2_1.md`). Normalize every freshly derived STEM before writing —
  each digit-underscore-digit join becomes a dot; param sizes stay
  underscored (`Gemma_4_31B_IT`, `Qwen_3.8_27B`, `Xing_4.0_29b_a4b`).
  Canonical logic: `normalizeStem()` in `scripts/lib/naming.mjs`. An
  underscore-versioned findings file is a forbidden duplicate of its dotted
  twin, never a second source (a resurrect silently double-counts the rater
  in averages): merge the newer content into the dotted file, then remove
  the variant (user sign-off; pre-commit bypass `ALLOW_MODEL_DELETE=1`).
  Resurrected variants FAIL sync, are never quarantined/parsed/averaged/
  registered, and the pre-commit hook blocks staging them
  (`MERGED_SOURCE_STEMS` in `scripts/lib/validate.mjs` is the permanent
  never-resurrect list). A merged-stem variant deleted from disk is a
  sanctioned permanence survival while its canonical sibling exists (either
  `.md` or `.md.excluded`).
- **Family-shorthand identity (absolute):** a bare family, generation, or
  base name with no distinct vendor ID is never scaffolded as a new folder.
  Before creating a folder for a short/base name, verify a distinct vendor
  route exists (vendor docs, gateway listing, weights repo); when every
  cited ID, spec sheet, and price resolves to an already tracked suffixed
  folder, write into that canonical folder instead. A bare name for a
  generation whose members are tracked goes to the member folder for the ID
  actually cited; a bare name the vendor does not ship (phantom
  unsuffixed-name) resolves to the suffixed SKU that exists — never drop a
  suffix when citing it. A parked alias folder on disk is skipped entirely
  and surfaced, never queued or written. A new suspected alias is parked
  (never deleted) only with per-instance user sign-off citing the resolving
  IDs; the parked slug joins both `RETIRED_SLUGS` lists (rendered in the
  generated roster).
- **Coding-suffix identity (per-vendor evidence, never analogy):** whether a
  `-coding`-suffixed name is a separate model is decided by vendor IDs alone.
  A `-coding` label that reflects positioning or a subscription plan is not
  a model — verify a distinct vendor route (vendor docs, gateway listing,
  weights repo) before scaffolding any `-coding` folder; when every cited ID
  resolves to the base folder, write into the base folder instead. Renamed
  `-coding` slugs never come back (`MERGED_MODEL_SLUGS`).
- **Retired-alias identity (absolute):** a slug the vendor lists as an alias
  of a tracked model is never a folder — it is recorded in
  `RETIRED_ALIAS_SLUGS` (`scripts/lib/validate.mjs`, rendered in the
  generated roster) with the same never-scaffold enforcement; benchmark
  figures measured under the retired slug are lineage data, cited only
  labelled with the ID actually measured, never silently merged into the
  canonical model's scores. A genuinely new alias case needs per-instance
  user sign-off with the vendor alias list cited before it joins the map.
- **Serving-profile / revealed-stealth identity:** a vendor-stated serving
  profile (speed/latency tier of the same weights at a different price) is
  never a separate model — research belongs in the base folder. A revealed
  stealth name resolves to the revealed model by MERGE, never parking (user
  rule 2026-10-24): the stealth folder and all its research files are renamed
  to the revealed model — unique findings move into the revealed model's
  canonical folder (revealed-folder's file wins on colliding stems; a fresh
  `.md` retires its `.md.excluded` twin), the stealth slug is deleted and
  joins `MERGED_MODEL_SLUGS` (`scripts/lib/validate.mjs`, rendered in the
  generated roster) — never scaffolded again; the revealed model's
  `meta.json` `aliases` carry the stealth names so searching the old name
  still resolves (the stealth name is an alias, never a model); findings
  written BY the model keep their stealth-era rater stems as frozen history,
  and their rater keys deep-link to the revealed model's page
  (`SOURCE_OVERRIDES` in `scripts/sync-data.mjs`). Figures measured under the
  stealth/alias name are cited labelled with the ID actually measured.
- **Qwen 3.5 397B identity (user-confirmed 2026-10-08):** `Qwen/Qwen3.5-397B-A17B`
  and `opencode/qwen-3.5-397b` identify the same model; research belongs in
  `model/qwen-3.5-397b/`. The `397B` suffix is a parameter count, not a
  version — never replace the hyphen with a dot and never create another
  folder for the upstream name. A scaffolded `meta.json`'s generic defaults
  (`128K total`, `Text in/out`) come from `buildScaffoldMeta`, not provider
  evidence — never infer a separate model from them.

## Scoring rules

- Source-file `Overall` = half-up mean of the five quality dims (Tool use,
  Reasoning, Context window, Multimodal, Coding). `Cost efficiency` is scored
  but never counted toward any Overall. `pnpm sync` auto-corrects a drifted
  Overall number (logged as `AUTO`); only unparsable score lines fail.
- `model/<slug>/average.md` = mean of source Overalls over the top-10
  qualifying cohort (highest Overall first); only raters whose own model
  averages above 84.9 qualify. Recomputed by `pnpm sync` only — never by hand.
- **Crown rule: every model folder gets an average, gate or not.** When no
  rater clears 84.9, the average is computed from all available reports
  (top-10 cap still applies) and labeled as a below-gate fallback — in the
  sync log and in the file's Agreement notes. The gate filters *which reports
  count whenever a choice exists*; it never removes a model from the site.
- Example 1: a model with `Overall` = 92 counts toward other models' averages
  (while in their top-10 qualifiers). Example 2: a model with `Overall` = 92
  that does NOT count toward some average (below that folder's top-10 cut) is
  still displayed for that model and must never be deleted for any reason.

## Model roster & Overall scores (single point of reference — no self-investigation)

- `model-queue.md` (repo root) is THE single point of reference for "which
  models exist and what is their Overall score": one `<Overall> <slug>` line
  per model, highest first (ties A-Z), regenerated and committed by
  `pnpm sync` (`buildQueueFile` in `scripts/lib/average.mjs`). Any question
  of the form "list the models" / "what did X score overall" is answered by
  reading that ONE file — never by listing `model/`, walking folders, parsing
  every `average.md`, or opening any findings/research `*.md` file.
- **No self-investigation:** a delegated agent never derives its own identity,
  STEM, or score from the repo — the kickoff message supplies the STEM
  (identity resolution: `tasks/research-assign.md`) — and never reads peer
  findings files to learn scores (zero-influence: `tasks/research.md`). The
  queue file is the only permitted roster/score source; in fallback (queue
  missing/stale) read only the single `- **Overall Score:` line of each
  `average.md`. Forbidden/redirected identities have their own single file:
  `model-aliases.generated.md`.
- Full per-rater dimensions live only in `src/data/scores.generated.ts`
  (numbers only, ~500 KB — grep targeted keys, never read whole); the
  human-facing overview table is `model-comparison.md`.

## Agent git-restore rule (absolute — no exceptions without explicit user sign-off)

- An agent restores a file from git only one file at a time, and only the
  single file it demonstrably needs. Restoring the whole tree or session
  (`git checkout HEAD -- .`, `git restore .`, `git reset --hard`,
  `git checkout <commit> -- .`, or any equivalent) is strictly forbidden
  without explicit user interaction — this is what wiped the working tree on
  2026-10-05.
- Every single-file restore requires prior user permission via a confirmation
  popup: name the exact file, state why it is needed, and proceed only after
  the user confirms. No confirmation → no restore.

## Agent file-deletion approval rule (absolute — trial from 2026-10-10, review after a couple of days)

- An agent never deletes, overwrites, renames, or moves any
  `model/**/*.md(.excluded)`, `models_voice/**/*.md(.excluded)`,
  `models_finance/**/*.md(.excluded)`, `models_health/**/*.md(.excluded)`,
  or any `meta.json` / `average.md` — via `bash` (`rm`, `Remove-Item`,
  `del`, `git rm`, `git clean`, `git restore`, `git checkout --`), via
  `edit`/`write`, or any equivalent — without prior user permission via a
  confirmation popup. No confirmation → no delete.
- One file per popup: name the exact path, state why the deletion is needed
  (own-twin retirement, user-directed relocation, merged stem per
  `MERGED_SOURCE_STEMS`, forbidden duplicate with `ALLOW_MODEL_DELETE=1`),
  and proceed only after the user confirms that exact file. Batch deletes
  and whole-tree operations (`git clean -fd`, `Remove-Item -Recurse`,
  `git reset --hard`) are strictly forbidden without explicit user
  interaction.
- A sanction (twin rule, relocation, merge list) only makes a `Yes`
  possible, never automatic.
