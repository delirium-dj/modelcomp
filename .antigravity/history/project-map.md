# ModelComp — Project Map

High-level GPS map of components, routes, data flow, scripts, and relationships for AI agents.
Refreshed 2026-10-05 (2026-10-04 version missed `.opencode/plugins/` runtime retry suite).

## Architecture & Data Flow

```text
model/<slug>/<Source_Name>.md      Per-agent research findings (model card, raw benchmarks, 1–100 scores)
model/<slug>/average.md            Arithmetic means (recomputed by scripts/sync-data.mjs)
model/<slug>/meta.json             Curated display metadata (name, pricing, context window,
                                   optional category: "generative" default, "decision" for
                                   typed-decision System-One models like Jev)
models_voice/<slug>/               Same conventions for voice/speech models (RULES.md routing rule;
                                    NOT scanned by pnpm sync — model/ only; retired
                                    `voicemodels/` name must never be recreated)
models_finance/<slug>/             Same conventions for finance models (.agents/rules.md routing
                                    rule; user-directed relocation e.g. ling-3.0-flash-fin;
                                    NOT scanned by pnpm sync — model/ only; wiring pending)
models_cybersecurity/<slug>/       Same conventions for cybersecurity specialists (RULES.md routing
                                    rule; slug ends in `-cyber` e.g. gemini-3.8-flash-cyber,
                                    gpt-5.6-cyber; NOT scanned by pnpm sync — model/ only; wiring pending)
models_health/<slug>/              Same conventions for health/life-sciences models (RULES.md routing
                                    rule; e.g. ling-3.0-flash-sante; NOT scanned by pnpm sync —
                                    model/ only; wiring pending)
           │
            ▼ pnpm sync (scripts/sync-data.mjs)
src/data/scores.generated.ts      Pre-parsed numbers-only scores bundle
src/data/verified.generated.ts    Newest live findings-file date per slug (`YYYY-MM-DD`, Last-verified display)
src/data/evidence.generated.ts    Benchmark figures cited by 2+ independent files per slug (Verified-benchmarks section)
src/data/sources.generated.ts     Reporting-agent registry + SourceKey union (auto-registered)
                                   + managed RATER_GATE export (single source: scripts/lib/parse.mjs)
model-queue.md                    Single point of reference for model roster + Overall scores (auto-sorted `<Overall> <slug>`; agents read this one file — never scan average.md/findings, RULES.md § Model roster & Overall scores)
model-aliases.generated.md        Single identity roster for research agents: parked slugs, deleted phantom folders, merged duplicate
                                   slugs, retired vendor aliases, merged duplicate stems, alias families —
                                   auto-generated by pnpm sync from the code lists (validate.mjs/average.mjs);
                                   prose rule files point here, never restate (drift-proof, 2026-10 compaction)
public/robots.txt                 Generated Sitemap pointer (absolute URL from SITE_ORIGIN knob)
           │
           ▼ import
src/data/models.ts                 Hydrates MODELS, SOURCES, DIMENSIONS arrays & source selectors
                                   (~370 lines; ModelCategory + isDecisionModel live here)
           │
           ▼ consumed by
src/components/ & src/routes/      v2 section components (src/components/v2/*) & SSG pages
```

Site origin for prerendered canonical URLs + sitemap is `SITE_ORIGIN`
(`adapters/static/vite.config.ts`, localhost default — deploys must set it).

## Component & Layout Directory

- **Routes (`src/routes/`)**:
  - `layout.tsx`: Layout for plain pages (`/contact`) — theme init + `V2Header`/`V2Footer` chrome.
    The v2 homepage, model profiles, the Providers page and design studies are standalone
    canvases that render their own header/footer (the layout skips them).
  - `index.tsx`: Main comparison page (`/`, v2 design). Owns the shared state (theme, results
    source, compare slots, search/leader rotation) and composes the section components under
    `src/components/v2/` (HeroSection, FactsStrip, CompareSection, MethodologySection,
    ModelsSection, DecisionShelf) + `V2Header`/`V2Footer`.
  - `model/[slug]/index.tsx`: Per-model detail page (`/model/<slug>/`, v2 canvas). Model meta, hex
    bars, best-first reporting table. Per-model `<title>`/description via a `DocumentHead`.
  - `providers/index.tsx`: Providers page (`/providers/`, v2 canvas) — per-provider billing plans
    (each price links its claimant page) and covered models (derived from `idPrefixes`/`hosts`),
    sourced from `src/data/providers.ts` (data curated in `providers/<slug>/meta.json`). Cards are
    grouped **Free tier first, then Paid only**, each group ordered by covered-model count; free
    plans are derived from plan name/price (`isFreePlan`), never a separate flag.
  - `contact/index.tsx`: Contact page (unconfigured inbox — see audit B12) — the only page using
    the shared layout chrome.
  - `design-6sol/`: standalone design-study canvas (own CSS, own theme toggle).

- **Components (`src/components/`)** — v1 chrome was removed 2026-10-20 (the v2 tree is the only
  design; deleting it was user-ordered to kill the double-source confusion):
  - `v2/V2Header.tsx`: Sticky header shared by the whole v2 tree (theme toggle driven by the
    page-owned theme `Signal`, desktop anchor nav — Compare/Scoring/Models/Providers — and a
    mobile hamburger drawer). Takes `theme` + `navBase` ("" on homepage, "/" on subpages).
  - `v2/V2Footer.tsx`: Shared v2 footer.
  - `v2/theme.ts`: `usePageTheme()` — the single light/dark initialiser + writer (signal +
    `<html>.dark` + both storage keys) used by every v2 canvas.
  - `v2/hex.ts`: Shared radar geometry (`hexPoint`, `hexPolygon`, `barWidth`, `HEX_GAMMA`) used by
    the hero, the compare chart and the model profile.
  - `v2/modelView.ts`: Shared view helpers — dimension labels/short names derived from
    `DIMENSIONS`, per-dot tooltip, list-search predicate, best/worst cell highlighting.
  - `v2/HeroSection.tsx`, `v2/FactsStrip.tsx`, `v2/CompareSection.tsx`,
    `v2/MethodologySection.tsx`, `v2/ModelsSection.tsx`, `v2/DecisionShelf.tsx`: the homepage
    bands, rendered by `routes/index.tsx`.
  - `VendorIcon.tsx`: Brand icons inlined from `vendorIcons.generated.ts` (no `<img>`, no network
    requests).
  - `freeZenLink.tsx`: Links "Free OpenCode Zen tier" strings to the Zen catalog.
  - `router-head.tsx`: Owns `<title>`, canonical link, `og:`/`twitter:` tags, tab favicon
    (`/avatar.png` Vercel PNG) + apple-touch/PWA icon (`/favicon.svg` brand SVG), manifest.

- **Data Layer (`src/data/`, 8 files)**:
  - `models.ts`: Core data logic, zero hardcoded model entries.
  - `providers.ts`: Provider (seller/console) data — curated `providers/<slug>/meta.json`, derived covered-model lists + free-tier flags.
  - `evidence.ts`: Thin `getEvidence()` wrapper so list pages never bundle `evidence.generated.ts`.
  - `scores.generated.ts`: Pre-parsed numbers-only scores as positional `[tool, …, overall]` tuples (wire order in `SCORE_FIELDS`, `scripts/lib/codegen.mjs`), auto-generated by `pnpm sync`.
  - `verified.generated.ts` / `evidence.generated.ts`: newest findings date per slug, and 2+-file agreed benchmark figures — auto-generated by `pnpm sync`.
  - `sources.generated.ts`: Reporting-agent registry + `SourceKey` union + managed `RATER_GATE`, auto-generated by `pnpm sync`.
  - `vendorIcons.generated.ts`: Inlined brand-SVG artwork (hand-maintained; source SVGs vendored under `assets/vendor-icons/`, kept out of `public/` so they are not deployed).

- **Scripts & Admin**:
  - `scripts/sync-data.mjs`: Data sync script executed via `pnpm sync`.
  - `scripts/lib/` (7 modules + 8 `*.test.mjs` suites, zero-dep `node:test`): `parse` (score parsing, `RATER_GATE`, signature extraction), `quarantine` (evidence-free exclusion), `benchmarks` (agreed-figure extraction), `naming` (stems/slugs/scaffold), `validate` (tripwires, meta gates, signature-vs-stem conflation tripwire `checkSignatureStem` 2026-10 — FAILs a findings file whose `Provided by:` signature names a foreign model; `buildAliasesFile` renders the identity roster), `average` (means, queue), `codegen` (registry surgery incl. stale-key prune, scores/verified/evidence/robots emit).
  - `tasks/`: `research-assign.md` (canonical delegator — the agent resolves its own STEM via its Identity resolution chain), `research.md` (research workflow), `research-brief.md` (compact ~5k-token brief for sub-200k-context runtimes, kickoff `BRIEF: small-context` — same rules as the full corpus, which it replaces for small models; embeds the STEM/slug conflation guard), `sync-data.md` (sync workflow).
   - `.opencode/plugins/`: OpenCode Desktop 2.x runtime retry suite (NOT part of the Qwik build) — 14 top-level **V2** ports (`Plugin.define` from `@opencode/plugin`) sharing `.opencode/lib/plugin-retry/engine.ts` + `match.ts`; V1 originals parked in `plugins/v1/`. Members: `budget-retry`, `deepseek-continue-retry`, `fledge-endpoint-retry`, `gpt-sol-budget-retry`, `bang-drop-retry` (silent-drop `session.idle` rescan), `api-connect-retry` (DNS/network/provider-transport, incl. gateway "response headers timed out"), `model-turn-retry`, `gemini-quota-retry` (standalone V2, Gemini 429 + `retry in Ns` hint), and the `provider-*` family on the full 3-shape pattern (payload error / silent `session.idle` / embedded in a generic error) — `provider-content-filter-retry`, `provider-headers-timeout-retry` (2026-10-27, gateway + AI-side "Timed out waiting for response headers"), `provider-high-demand-retry`, `provider-invalid-request-retry` (2026-10-17, stable tail; 2026-10-27 bare-form; 2026-10-29 bare runtime "Invalid request"), `provider-returned-error-retry` (2026-10-27, generic wrapper; 2026-10-28 "upstream provider returned an error"; the bare Phala prefix stays with `provider-invalid-request-retry`), `provider-rate-limit-retry` (2026-10-28, 429/rate-limit, payload-only); each waits then nudges (`continue`/`please continue`) with a consecutive-failure brake. 2026-10-28: all ports verified loading on Desktop 2.2.0 after the V1-shape load failure (`PluginModule.LoadError: ... missing key "default"`) was found in the server log — see `.agents/rules.md` § OpenCode plugin suite. 2026-10-28 (later): the engine now listens to the real 2.2 event names (`session.step.failed` / `session.execution.failed`; 2.2 does not emit `session.error`) and reads 2.2 message shapes (`idle.outcome`, `message.error`), so the Phala "The request was rejected as invalid" failure nudges `continue` instead of dying silently.
  - `.agents/`: Rules, tech-stack, rate limit guidelines for agents.
  - `.antigravity/`: Antigravity-specific rules and local cache workflows.
