## 0. Identity — your STEM (zero tool calls)

Your STEM (your reporter identity, your filename stem) comes from the kickoff
line `AGENT_SOURCE_STEM: <value>` (a display form with spaces counts —
convert spaces to `_`). A pinned STEM is FINAL: never re-derive it, never open
the registry to validate it. Display name = STEM with `_` → space.
No pin anywhere → STOP and ask the orchestrator. Never guess a filename.

## 1. Path contract — the conflation guard (memorize before writing anything)

- Your file, in every folder: `model/<subject-folder>/<YOUR_STEM>.md`.
- The **folder** is the model you research (the **subject**). The
  **filename** is always **your own** name. They are different roles — the
  subject's name NEVER goes in your filename.
- Example: STEM `North_Mini_Code` researching `gpt-5.5` writes
  `model/gpt-5.5/North_Mini_Code.md`.
- Anti-example (the 2026-10 incident — NEVER do this):
  `model/gpt-5.5/gpt_5_5.md`, `model/gpt-5.5/GPT_5.5.md` — a file named after
  the model being researched. `pnpm sync` FAILs such a file on the next run
  (signature-vs-stem tripwire) — it will name you.
- **Pre-write self-check, every file:** "filename = MY stem; folder = the
  subject." If the filename you are about to type is the folder's own name
  and you are not literally that model — stop, re-resolve your identity.
- Voice/speech models go under `models_voice/<slug>/`, finance models under
  `models_finance/<slug>/` — production scope: park them (note in your final
  summary, do not create or research now), never place them under `model/`.

## 2. Startup (2 tool calls, then write)

1. Read `model-queue.md` (repo root): roster + Overall scores + processing

Your queue = queue-file slugs minus folders holding your file, in file

## 4. Slug + stem hygiene (before creating ANY folder or file)

- Slugs: version numbers use `.` not `-` (`gpt-5.6-terra`, never
  `gpt-5-6-terra`; `gemma-4.12b-unified`, never `gemma-4-12b-unified`).
  Exceptions: param sizes stay hyphenated — digits immediately followed by
  `b`/`B` (`gemma-4-31b`, `qwen-3.5-0.8b`, `qwen-3.5-122b-a10b`); single
  majors with codenames (`gpt-6-astra`) never match. Always check the dotted
  folder first, and strip a leading vendor prefix (`google-`, `openai-`,
  `anthropic-`, …) and check the unprefixed folder first.
- Stems: version numbers use `.` not `_` between digits (`Laguna_XS_2.1.md`,
  never `Laguna_XS_2_1.md`); param sizes stay underscored
  (`Gemma_4_31B_IT`, `Qwen_3.8_27B`).
- OpenAI GPT display names hyphenate (`GPT-5.6 Terra` — model card + meta
  name only); stems keep underscores, slugs keep dots.

## 5. Per-folder loop

1. ONE folder at a time. Fresh public web research only — NEVER read peer
   findings files (`model/<slug>/*.md`): zero influence. `model-queue.md`
   (or, only in fallback, the single `- **Overall Score:` line of each
   `average.md`) is the only permitted peek.
2. Draft fully per `model-report-TEMPLATE.md` (read it once): model card →
   raw benchmarks → normalized scores → signature
   `Provided by: **<Your_Display> (<your vendor/model-id>)** — <YYYY-MM-DD UTC>`
   — YOUR name in the signature, never the subject's.
3. Score contract: exactly 7 lines `- **<Label>: <N>/100.**` with labels
   `Tool use`, `Reasoning`, `Context window`, `Multimodal`, `Coding`,
   `Cost efficiency`, `Overall Score`. `Overall Score` = half-up mean of the
   five non-cost dims (tolerance 0.51). Never invent numbers — missing
   benchmark = `no verified public score found`; every number carries a
   source.
4. Write immediately to `model/<subject>/<YOUR_STEM>.md`, then advance
   (incremental save = interrupt-safe). Skip folders already holding your
   file. Never overwrite, edit, or delete in-pass.
5. Zero verified benchmarks → self-exclude as `<YOUR_STEM>.md.excluded`
   (notes only, never scored).
6. Your own `<YOUR_STEM>.md.excluded` twin: draft fresh FIRST (zero
   influence), only then compare — same verdict → write nothing; genuinely
   new verified evidence → write the fresh file, then retire the twin (one
   file, one user confirmation popup). Never touch another agent's twin.
7. Your own file >7 days old (Signature date) + genuinely new evidence → do
   NOT overwrite; emit
   `ENRICH-PROPOSAL: <slug> | old <date>/<Overall> | new evidence <URLs> | delta`
   in your final summary and advance.

## 6. Never-do list (absolute)

- Never delete, overwrite, rename, or move any findings file or model folder
  — permanence (RULES.md). Every deletion needs a per-file user
  confirmation popup first; no confirmation → no delete.
- Never read peer findings files before/during research.
- Never stop early: the task ends only when the queue is empty or the user
  revokes it. Quiet periods and "enough files" are NOT stop conditions.
- Never run `pnpm sync`, `pnpm build.types`, `pnpm build`, or `pnpm dev` —
  hand them over in the final summary.
- Never edit task/rule files (`tasks/`, `RULES.md`, `.agents/`, template).
- New model discovered: normalize the slug (§4), check dotted + unprefixed
  folder + the generated roster, then scaffold `model/<slug>/` EMPTY (no
  `meta.json`, no `average.md` — sync generates those) and append it to the
  END of your queue. Never scaffold a bare family name, a tier suffix, a
  `-coding` label, or anything in the generated roster.
- Reporting-agent backfill: an agent with no `model/<slug>/` folder gets one
  scaffolded on the spot (folder + verified-facts `meta.json`, schema
  `model/README.md`) and is queued like any other folder.
