## Model card

- **Name:** Qwen3.8 Flash Next (open-weights preview; distinct from the hosted `Qwen3.8-Flash` API)
- **Short description:** Alibaba's open-weights preview of the architecture that will underpin Qwen4 — a multimodal MoE that plays the same "release the architecture early" role Qwen3-Next played for Qwen3.5. It is **not** the Qwen Cloud `Qwen3.8-Flash` product: that managed SKU is a different build on top of it, with 1M context by default and official built-in tools. Flagged as a variant sibling, not an alias — different SKU, same architecture family.
- **Provider / access:** open weights on Hugging Face (`Qwen/Qwen3.8-Flash-Next`) and ModelScope; served OpenAI-compatible via SGLang / vLLM / TokenSpeed (`http://localhost:8000/v1`, Chat Completions). **First-party hosted route now exists for the checkpoint itself** — Artificial Analysis benchmarks Qwen3.8-Flash-Next through **Alibaba Cloud** as its single tracked provider. Hosted production sibling `qwen3.8-flash` on Qwen Cloud (`https://maas.qwencloudapi.com/compatible-mode/v1`, Chat Completions + Responses API). Zen exposes it as `qwen-3.8-flash-next`.
- **Release / knowledge:** HF stub posted 2026-08-24, full card 2026-08-26; ModelScope formal release 2026-08-26 (weights and blog same day, HF card dated 2026-08-26; OpenCode's data page records 2026-08-27). Knowledge cutoff **not published — unknown**.
- **IDs:** `opencode/qwen-3.8-flash-next` (Zen); `alibaba/qwen3.8-flash-next` (OpenCode data page); `Qwen/Qwen3.8-Flash-Next` (HF / ModelScope); `qwen/qwen3.8-flash` (the **hosted sibling**, on OpenRouter). No Free ID on Zen — scored on paid pricing.
- **Context window — and a genuine source conflict that this pass could not resolve.**
  - Native **262,144**, extensible to **1,000,000** via YaRN RoPE scaling (HF model card, verbatim: "Context Length: 262,144 natively and extensible up to 1,000,000 tokens"). Qwen's own card states all its agentic benchmark rows were run at **256K context**.
  - Measured hosted routes: **Artificial Analysis's model page reports a 256k context window**; OpenCode's data page reports **262K**; LLMReference reports 256K; Opper's gateway lists **262K context / 66K max output**; an independent self-host report (ahnguyen17/flashnext-vllm, 2026-09-02) serves at 262,144 native with 786K via YaRN factor 3.0.
  - **But Artificial Analysis's own Alibaba Cloud provider table lists Qwen3.8-Flash-Next at 1M**, and OpenRouter's `qwen/qwen3.8-flash` listing reports 1.0M. The first pass's lead asserted that "every measured hosted route reports 256K, not 1M"; that is **too strong** — AA's provider row says 1M. Recorded as an unresolved conflict: the model page and the provider table disagree inside the same source. **262,144 is the number I score on**, because that is what the weights natively support and what the majority of measured routes report.
  - Max output **131,072** — **confirmed**, and an upgrade from the first pass's "128K reported by LLMLearner". OpenCode's data page records "Max output 131K"; OpenRouter's Qwen3.8 Flash page states "supports up to 131,072 completion tokens"; the HF card recommends exactly `Final Response: 131,072` alongside `Reasoning Content: 262,144` within the 1M envelope. The hosted sibling allows the same 131,072 with a 262K max-reasoning budget. (Opper's gateway lists 66K max output for its EU routes — a further conflicting figure, recorded.)
- **Modalities:** text, image, video in; text out (HF `pipeline_tag: image-text-to-text`). Reasoning: on by default, `<think>` blocks, configurable via `enable_thinking` / `preserve_thinking` / `reasoning_effort` (`xhigh` default, `medium`, `low`). Tool calling: native `qwen3_coder` tool-call parser; a community vLLM deployment reports the parser string as `qwen3_xml`, matching the model's XML template. Structured/JSON output supported on the Qwen Cloud build.
- **Pricing (as of 2026-10-17):** **$0.15 in / $0.47 out per 1M — now a first-party price for *this* checkpoint**, not just for the hosted sibling. Artificial Analysis lists it under the Qwen3.8-Flash-Next model page and states explicitly it is "**based on Alibaba's API**", with a cache-hit discount of 89%, a blended 7:2:1 rate of **$0.09/M**, and **$0.37 cost per Intelligence Index task**. Alibaba Cloud is its only tracked provider, and it is also AA's **#2 cheapest** model by blended price across 28. OpenCode's data page carries the same $0.15/$0.47. **This corrects the first pass**, which stated the open-weight Next "carries no published hosted list price of its own". For completeness: the hosted sibling `qwen3.8-flash` is priced identically ($0.15/$0.47, cache read $0.016, cache write $0.20) but Alibaba's blog quotes ¥1/¥3 ≈ $0.16/$0.47, and Alibaba Cloud Community quotes $0.16 — a rounding presentation difference, not a price change. Opper's EU routes (Lyceum, TensorX) list $0.20/$0.50.
- **Architecture:** 176B total — a 125B main MoE plus a 51B n-gram embedding table — with **6B active** per token, and a further 4B in the MTP head. 48 layers (12 × (3 × Gated DeltaNet → MoE) → 1 × Qwen Sparse Attention → MoE), hidden dimension 2560, 512 MoE experts (10 routed + 1 shared, expert intermediate dim 640), 20M bigram/trigram n-gram embeddings applied at layer 2, Gated DeltaNet + Qwen Sparse Attention hybrid, 4-branch Gated Residual (bottleneck rank 320), 1-layer MTP, QSA indexer budget 512 blocks / 2048 tokens. Open weights under **qwen-community-1.0** (commercial use with conditions); BF16 and FP8 (128-block fine-grained) checkpoints published. (Artificial Analysis reports 180B total / 6B active — minor discrepancy with the HF card's 176B, both recorded.)

### Raw benchmarks found

- Performance: **52.8 output tok/s (#53/78)**, TTFT 2.03s, time-to-first-answer 39.94s, end-to-end 50.12s. Against Claude Fable 5.1 and GPT-6 Astra (the two v4.3 leaders) both at **53**, it sits well below.

Independent — Qwen Team technical report (arXiv 2608.30320, *vendor-reported but methodologically published*). **This is the correction that most changes the Context window row.**

- The first pass, and the lead I was given, both stated that **no long-context retrieval benchmark exists at any length**. That is **false.** Qwen's own architecture paper publishes RULER and 8-needle MRCR for this exact model across the full length range. Released configuration ("w/ QSA"), against a full-attention baseline:
  - **RULER** (averaged over sequence-length ranges): ≤128K **99.89** · 128–256K **99.62** · 256–512K **98.95** · **512K–1M 93.00** (full attention baseline: 99.84 / 99.81 / 97.65 / 90.08)
  - **MRCR 8-needle:** 128K **95.98** · 256K **93.00** · **512K 40.53** · **1M 26.44** (baseline: 97.14 / 94.20 / 30.66 / 20.71)
  - Macro-average across both: **80.93** vs full attention 78.76
  - Read carefully: RULER holds up beyond the native boundary, but **MRCR collapses from 93.00 at 256K to 40.53 at 512K to 26.44 at 1M** — precisely where YaRN scaling begins. Simple needle retrieval survives; multi-needle retrieval does not. Third-party self-host reports agree in shape: needle/key-value/multi-hop lookups hold to 900K under YaRN, while **aggregation and counting degrade** (a code-definition count falls from 10/25 at 128–240K to 6/25 at 900K under factor 4). One independent operator recommends YaRN **factor 2 up to ~500K** rather than factor 4 to 1M.
- Qwen's own warning, retained: "All the notable open-source frameworks implement static YaRN… potentially impacting performance on shorter texts."

### Normalized scores (1–100)

- **Tool use: 76/100** (unchanged). New independent evidence is genuinely two-sided and nets out. Up: AA-Briefcase **1587 Elo**, GDPval-AA v2 **1647 Elo** and AutomationBench-AA **56%** are strong agentic knowledge-work results, and TB4.0 **25%** is mid-field. Held by: OSWorld binary **19.4%**, τ³-Banking 45.4%, and a **−2.87% agent task success rate on arena.ai's 98,466 sessions (#34/45)** — a large real-traffic measurement that argues for caution on exactly the unattended-agentic use the other numbers invite. Vendor TB2.1 86.1% remains vendor-only.
- **Reasoning: 82/100** (was 78). Raised on the arrival of a real independent composite. The first pass scored this from GPQA 91.7% (vendor) against HLE 35.9% and CritPt 11.1%, and could find no independent overall figure at all. There is now **AA Intelligence Index 40 (#8/120)** with AA's own components: **HLE 38%**, SciCode 51%, CritPt 11%, GDP.pdf 16%, AA-Briefcase 1587, Omniscience −10. That is a top-decile independent read. Not higher: AA-Omniscience is **negative** (−10, i.e. more wrong than right), CritPt and GDP.pdf remain weak, and the model sits 13 points below the v4.3 leaders (53) on AA's own scale.
- **Context window: 76/100** (was 88). Cut, and the reason is now **evidence rather than absence of evidence — in both directions.** In the model's favour, the claim "no retrieval benchmark exists at any length" was wrong: Qwen's own technical report publishes RULER and MRCR out to 1M, and RULER holds **93.00** at 512K–1M. Against it, MRCR **falls off a cliff exactly at the native boundary** — 93.00 at 256K → 40.53 at 512K → 26.44 at 1M — and independent self-host reports reproduce the same shape, with aggregation/counting degrading rather than needle retrieval. Only **262,144** is native and only 262,144 is what most measured routes report (AA's own provider table disagrees and says 1M; recorded, unresolved). The 1M path is opt-in static YaRN with a vendor-stated short-prompt penalty. This is a genuinely large window with a genuinely poor multi-needle far end, and 76 reflects both.
- **Multimodal: 89/100** (unchanged). Text/image/video in with strong vendor vision numbers — MathVision 95.7%, CharXiv-R 90.6%, RealWorldQA 88.5%, LVBench 76.6%, Vision2Web 64.0% — capped by GDP.pdf 15.6% (#29/82) on document/PDF reasoning and OSWorld binary 19.4%. **No new independent vision benchmark was found this pass**; Artificial Analysis lists MMMU-Pro among its evaluation set but published no Inkling/Qwen-Flash-Next value. Held on unchanged evidence rather than raised.
- **Coding: 85/100** (unchanged, but now with an independent anchor). LiveCodeBench v6 91.9% and SWE-bench Multilingual 81.0% are elite-tier vendor figures, SWE-bench Pro 62.5% and DeepSWE 58.7% are solid, NL2Repo-Bench 48.1% is its one clear regression against DeepSeek-V4-Flash-0731 (54.2), and there is still **no SWE-bench Verified figure**. The new **AA Coding Index of 73.1** and **AA SciCode 51%** are independent and sit squarely mid-tier — consistent with the vendor table rather than confirming it. Neither raised nor lowered.
- **Cost efficiency: 97/100** (was 94). Raised because the premise changed: this is now a **published first-party price for this checkpoint** ($0.15 / $0.47 via Alibaba Cloud, explicitly attributed by AA to Alibaba's API for Qwen3.8-Flash-Next), with an 89% cache-hit discount, a $0.09/M blended rate that is **#2 cheapest of 28 on Alibaba Cloud**, and $0.37 per Intelligence Index task. Not 100: it is a paid list SKU, there is no free tier, and the model is the most verbose in its comparison class (240M output tokens on the Index, 108k per task) — real money is consumed per solved task even where the headline rate looks like a rounding error.
- **Overall Score: 82/100.** Best-fit as a cheap, wide-window multimodal agentic/coding workhorse with elite algorithmic coding and a now-genuinely top-decile independent intelligence composite — not a frontier reasoning or knowledge model, and not a model whose 1M window is safe for multi-needle retrieval. Mean of the five non-cost dims: (76 + 82 + 76 + 89 + 85) / 5 = 81.6 → 82.
