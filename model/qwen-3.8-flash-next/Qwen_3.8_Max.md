## Model card

- **Name:** Qwen 3.8 Flash Next (**Qwen3.8-Flash-Next**)
- **Short description:** **Alibaba Qwen's open-weight research preview of the architecture it will carry into Qwen4** — released **2026-08-26**, and explicitly **a checkpoint, not a product** (the managed, production version is the hosted **Qwen3.8-Flash** on Qwen Cloud, which ships 1M context by default and built-in tools). The bet is efficiency-through-new-architecture: **180B total parameters but only 6B activated per token**, via three novel pieces — **Qwen Sparse Attention (QSA)** paired with **Gated DeltaNet** (3:1, micro-block-level selection to cut long-context latency), **Gated Residual connections** (four data-dependently-gated branches), and a **51B-parameter n-gram embedding table** (20M bigrams/trigrams at layer 2, offloadable to host RAM). On Alibaba's **own** numbers it is a genuine efficient-coding/agentic standout: it **leads open-weights on SWE-bench Pro (62.5%)**, posts **LiveCodeBench v6 91.9%** (above Claude Opus 4.6-Max's 88.8%), **GPQA Diamond 91.7%**, **DeepSWE 1.1 58.7%**, **Toolathlon 73.5%**, and tops **8 of 10 published multimodal benchmarks** (incl. GUI-agent **AndroidWorld 84.5** and **OSWorld 2.0 52.3**) — all while activating fewer parameters than nearly every model it beats. ⚠ **Three honest counterweights: (1) every benchmark is first-party** — akash.network states "independent, third-party reproductions were not available," and Morph's SWE-bench Pro leaderboard flags the 62.5% as "neither a Scale standardized entry"; there is **no Artificial Analysis Intelligence Index and no Vals AI row for Flash-Next itself**; **(2) it is experimental** — a preview lane with expected churn before Qwen4 ships; **(3) the license is restrictive** — **qwen-community-1.0**, *not* Apache 2.0 (unlike sibling Qwen3.8-27B): >100M MAU / >$20M-monthly-revenue products must display the model name, and any **Model-as-a-Service or "AI Work Assistant" business needs a separate Qwen license**. Self-hosting also needs a **multi-GPU node** (FP8 checkpoint 172.78 GiB) or a quality-lossy GGUF CPU-offload — the 6B-active figure speeds inference but does **not** shrink the memory footprint.
- **Provider / access:** **Alibaba Qwen team.** Open weights on **Hugging Face** (`Qwen/Qwen3.8-Flash-Next`, qwen-community-1.0), served via **Vercel AI Gateway ($0.12/$0.40 per 1M)** and other hosts; **vLLM recipe**, **SGLang**, **TokenSpeed** support; **Unsloth** quantized GGUF builds for CPU/unified-memory. Production sibling **Qwen3.8-Flash** via **Qwen Cloud** (1M context, built-in tools). Listed here as `opencode/qwen-3.8-flash-next`. **No free-id tier** in this dataset (`noFreeId: true`).
- **Release / knowledge:** **2026-08-26.** An experimental open-weight preview of the Qwen4 architecture; knowledge cutoff not stated in the sources reviewed.
- **IDs:** `qwen-3.8-flash-next` / `Qwen/Qwen3.8-Flash-Next` (Hugging Face) / `opencode/qwen-3.8-flash-next` (this dataset).
- **Context window:** **262,144 (262K) native, extensible to 1,000,000 (1M) via YaRN** — confirmed. But YaRN is a **static** scaling factor that "can measurably hurt performance on shorter texts," so the *effective* served window is 262K unless you tune/enable YaRN. (The hosted **production Qwen3.8-Flash** ships 1M by default; the **open checkpoint** does not.) Qwen's agentic guidance at 1M: budget up to 262,144 reasoning tokens + 131,072 final-response tokens.
- **Modalities:** **Text, image, video in → text out; tool use.** A causal LM with a **vision encoder** (HF `image-text-to-text` task); accepts text, image URLs and video URLs in one OpenAI-compatible chat message. Strong vendor multimodal sweep (8/10 top) including computer-use (OSWorld 2.0) and mobile-agent (AndroidWorld) tasks.
- **Pricing (as of 2026-10-24):** **Vercel AI Gateway $0.12 input / $0.40 output per 1M** — among the cheapest hosted prices in the dataset; **open-weight self-host** otherwise. The **6B-active** footprint makes inference very cheap/fast (~2.5× faster prefill per community reports), but self-hosting the full checkpoint is a **six-figure capital decision** (multi-GPU H200/Blackwell node) unless using a quality-lossy GGUF build on 96GB+ RAM. **License caveat:** qwen-community-1.0 restricts large-scale commercial and MaaS/AI-worker use (see Short description) — a real cost for agent businesses, unlike MIT/Apache rivals.
- **Architecture:** **Hybrid MoE + n-gram-embedding causal LM with a vision encoder. 180B total = 125B language model + 51B n-gram embedding + 4B multi-token-prediction (MTP); only 6B active per token.** **48 layers, hidden dim 2,560, vocab 248,320, 512 total MoE experts (10 routed + 1 shared active).** Three architectural novelties: **QSA** (1 of every 4 blocks; micro-block-level attention selection) + **Gated DeltaNet** (the other 3), **Gated Residual connections** (4 gated branches), and **n-gram embedding** (20M bigrams/trigrams → 51B lookup at layer 2, cheap to offload to host RAM). **Hybrid thinking** with adjustable effort (`xhigh`/`medium`/`low`) that **preserves reasoning traces across turns**. Checkpoint: **FP8 172.78 GiB / BF16 335.28 GiB**; min validated deploy TP2 on GB300, recommended TEP8 on 8×H200. License **qwen-community-1.0**.

### Raw benchmarks found

⚠ **All benchmarks below are first-party (Alibaba's Hugging Face model card / blog). akash.network (updated 2026-10-22): "All figures below are first-party… independent, third-party reproductions were not available at the time of writing." There is no Artificial Analysis Intelligence Index entry and no Vals AI SWE-bench Verified row for Flash-Next itself.** The only quasi-independent signal is a **third-party leaderboard placement** (Morph SWE-bench Pro, Sept 2026) — and even that is flagged "neither a Scale standardized entry."

Vendor coding + agentic + reasoning table (**Qwen3.8-Flash-Next** vs sibling/comparators, per Alibaba's card):

- **SWE-bench Pro: 62.5** — **leads open-weights** (Morph leaderboard: #1 open-weight, GLM-5.2 62.1); beats Qwen3.8-27B (61.7), DeepSeek-V4-Flash-0731 (56.0), Claude Opus 4.6-Max (53.4)
- **LiveCodeBench v6: 91.9** — top of the set (Opus 4.6-Max 88.8, DeepSeek-V4-Flash 90.6, Qwen3.8-27B 90.3)
- **SWE-bench Multilingual: 81.0** — beats Opus 4.6-Max (77.5), Qwen3.7-Plus (75.8)
- **DeepSWE 1.1 (agentic coding): 58.7** — far above Qwen3.8-27B (42.2), DeepSeek-V4-Flash-0731 (54.4)
- **Toolathlon (real-world tool use): 73.5** — above DeepSeek-V4-Flash-0731 (70.3), Qwen3.8-27B (67.1)
- **CoWorkBench (long-horizon office work): 73.9** · **JobBench (professional job tasks): 55.7** (vs Qwen3.8-27B 33.4, DeepSeek-V4-Flash 41.3)
- **GPQA Diamond (scientific reasoning): 91.7** — beats Opus 4.6-Max (91.3), DeepSeek-V4-Flash (90.8)
- **HLE (multidisciplinary reasoning): 35.9** — above Qwen3.8-27B (30.8), DeepSeek-V4-Flash (33.8); below Opus 4.6-Max (40.0)
- **IFBench (instruction following): 81.3** — well above Opus 4.6-Max (62.5)
- **Multimodal:** top score on **8 of 10** published multimodal benchmarks — **OSWorld 2.0 (computer use) 52.3**, **AndroidWorld (mobile agent) 84.5**
- **Meta's headline "Terminal-Bench 2.1 86.1%"** — vendor figure, consistent with the card's coding strength but **not independently confirmed** in the sources reviewed; **LiveCodeBench 91.9% is confirmed** (akash + HF).
- **vs DeepSeek-V4-Flash-0731:** Flash-Next leads most coding/agentic rows with fewer active params (6B vs 13B), but **trails on repo-level generation (NL2Repo-Bench 48.1 vs 54.2)**.

Independent context (**not** Flash-Next itself — the surrounding Qwen3.8 family on the neutral **Vals AI SWE-bench Verified** ruler): **Qwen 3.8 Max = 93/84/64/67**, **Qwen 3.8 27B = 90/86/69/67** by difficulty band (<15 min / 15 m–1 h / 1–4 hr / >4 hr). Flash-Next shares the 3.8 generation and beats the 27B on every vendor agentic/coding row, but it was **not** separately Vals-tested, so this is lineage context only.

Meta's **LiveCodeBench 91.9% is confirmed**; its **Terminal-Bench 2.1 86.1% is vendor-only/unconfirmed**; 262K-native/1M-YaRN context, text+image+video modalities, Vercel $0.12/$0.40 pricing, and the "preview, not a product / expect churn" tradeoff are all **confirmed**. The **Qwen4-architecture-preview** positioning and **efficient-coding** standout are confirmed. **No benchmark was invented; the vendor-only status is stated throughout.**

### Normalized scores (1–100)

- **Tool use: 83/100.** Broad and strong on Alibaba's own agentic ruler — **Toolathlon 73.5** (beats DeepSeek-V4-Flash-0731), **DeepSWE 1.1 58.7**, **CoWorkBench 73.9**, **JobBench 55.7** (vs 27B's 33.4), plus GUI-agent marks (**AndroidWorld 84.5**, **OSWorld 2.0 52.3**) and built-in tool support in the production Flash. It **leads its whole comparison set on most agentic rows** — a broader, stronger vendor-agentic profile than DeepSeek-V4-Vision-Exp (82, which trailed Opus-4.8 on several rows). Held **at 83 rather than the independently-verified tier (Grok 4.7 88, Inkling 84)** because **every tool number is first-party with zero independent replication**, there is no AA Index, and it is an experimental preview.
- **Reasoning: 81/100.** Genuinely high vendor marks — **GPQA Diamond 91.7 (above Opus 4.6-Max 91.3 and DeepSeek-V4-Flash 90.8)**, **HLE 35.9**, **IFBench 81.3** — more and better reasoning evidence than DeepSeek-V4-Vision-Exp (which published none). But it is the **6B-active efficiency tier previewing Qwen4**, and — critically — there is **no independent reasoning anchor** (no AA Intelligence Index, unlike Kimi K2.6's Index 54 that earned it 85). Scored **above DeepSeek-V4-Vision-Exp (80)** on the strength/quantity of GPQA+HLE+IFBench, **below Kimi K2.6 (85)** for the total absence of independent verification.
- **Context window: 80/100.** **262K native, 1M via static YaRN** (with a documented short-text performance cost) — the *open checkpoint* is not 1M-native. Scored **above Kimi K2.6 (78, 256K)** for the YaRN-1M extensibility and the strong long-context architecture (QSA micro-block selection is explicitly built for long agentic sequences), but **below the confirmed-1M-native models (Inkling, deepseek-v4-vision-exp, 85)**. The production Qwen3.8-Flash ships 1M by default, but this slug is the 262K-native open checkpoint.
- **Multimodal: 82/100.** **Text + image + video** with a vision encoder, and a **strong vendor multimodal sweep (8/10 top scores)** including computer-use (OSWorld 2.0 52.3) and mobile-agent (AndroidWorld 84.5). Scored **level with sibling Qwen3.8-27B (82, same 3-modality set)** and Inkling (82) on breadth + strong-but-vendor-only quality; **above Kimi K2.6 (79)** and image-only DeepSeek-V4-Vision-Exp (80) on modality breadth and GUI-agent capability. Not higher because the multimodal numbers are first-party and unreplicated.
- **Coding: 83/100.** The standout vendor dimension: **SWE-bench Pro 62.5 (leads open-weights per the third-party Morph leaderboard)**, **LiveCodeBench v6 91.9 (tops the set incl. Opus 4.6-Max)**, **SWE-bench Multilingual 81.0**, **DeepSWE 1.1 58.7** — all with only 6B active. Discounted **below DeepSeek-V4-Vision-Exp (84)** because that model had an **elite independent Vals baseline by lineage (V4-Flash 91/87/90/67)**, whereas Flash-Next has **no Vals/Scale-standardized independent number for itself** (Morph explicitly: "neither a Scale standardized entry"), it **trails DeepSeek-V4-Flash on NL2Repo (48.1 vs 54.2)**, and it is experimental. The strong Qwen3.8 family lineage (27B Vals 90/86/69/67, Max 93/84/64/67) supports the score by association but is not a direct measurement.
- **Cost efficiency: 88/100.** Excellent on paper: **Vercel $0.12/$0.40 per 1M** (among the cheapest hosted prices here) and a **6B-active** inference profile (~2.5× faster prefill). Held **below the MIT/Apache open-weight leaders (DeepSeek-V4-Vision-Exp, Inkling — 92)** and just below Kimi K2.6 (89) because of two real costs: the **restrictive qwen-community-1.0 license** (>100M MAU/$20M-revenue naming clause + **separate license required for any MaaS or "AI Work Assistant" business** — a direct hit to agent startups), and the **heavy self-host memory footprint** (180B resident; FP8 172.78 GiB → multi-GPU node or quality-lossy GGUF). Scored but **not** counted in the Overall per methodology.
- **Overall Score: 82/100.** Mean of Tool 83 + Reasoning 81 + Context 80 + Multimodal 82 + Coding 83 = 409/5 = 81.8 → 82. Best fit: **cost-sensitive, high-throughput agentic/coding workloads** where a $0.12/$0.40 API or a self-hosted 6B-active model with leading-open-weight SWE-bench Pro, strong tool use (Toolathlon/AndroidWorld/OSWorld), text+image+video input, and preserved cross-turn thinking wins — provided the **qwen-community-1.0 license terms fit your business**. **Not** the pick for production-critical work needing independent verification (none exists), for MaaS/AI-worker businesses that can't clear the separate-license requirement, for single-GPU local deployment (use Qwen3.8-27B, Apache 2.0, ~28GB FP8 instead), or for guaranteed stability (it is an experimental Qwen4 preview with expected churn — the hosted Qwen3.8-Flash is the productized path). **Divergence note:** my 82 is **3.2 below the queue's curated 85.2**, driven by the **total absence of independent replication** (every headline number is Alibaba's own; no AA Index, no Vals row), the **experimental/preview status**, and the **restrictive license** — against genuinely strong and internally-consistent vendor results (leading open-weight SWE-bench Pro/LiveCodeBench/GPQA, an 8/10 multimodal sweep), a novel efficiency-first architecture (180B/6B-active with QSA + n-gram embedding), and a best-in-class hosted price.
