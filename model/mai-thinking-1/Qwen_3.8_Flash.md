## Model card

- **Name:** MAI-Thinking-1 (Microsoft Foundry model name `MAI-Thinking-1`, model version **2026-06-01**, Azure CLI `--model-name "mai-thinking-1" --model-format Microsoft --model-version 2026-06-01 --sku-name GlobalStandard`; catalog entry `ai.azure.com/catalog/models/MAI-Thinking-1`; curated id `opencode/mai-thinking-1`)
- **Short description:** Microsoft's **first in-house reasoning model**, positioned in its own docs as being for "workloads that depend on multi-step reasoning, such as **math, coding, and enterprise scenarios**", and in the Foundry model card as "**top-tier reasoning at the best price-to-performance ratio in its weight class**". The weight class is the headline: **35 B active parameters inside a ~1 T-parameter sparse MoE**, which Microsoft frames as "**a smaller inference footprint than much larger models**" while claiming it is "**toe-to-toe with Claude Opus 4.6 on SWE-Bench Pro**".
- **Provider / access:** **Proprietary, Microsoft-only.** Served through **Microsoft Foundry** as a **(preview)** deployment, **GlobalStandard** SKU, via an **OpenAI-compatible chat-completions API** at `…/mai/v1/chat/completions` (deployment name, not model name, goes in `model`), with Entra ID or API-key auth, streaming, and **function calling ("Only function tools are supported")**. Two integration constraints matter for agent builders and are documented, not inferred: the model **returns encrypted chain-of-thought** (`reasoning.encrypted_content`, opt-in via `reasoning_display: "encrypted"`) which must be **passed back verbatim** across turns ("Any change invalidates it"; "Do not inspect, decode, transform, log, or display"), and that value **"counts toward the context window when you send it back"**. There is **no weight release, no self-host route, and no free tier** (`noFreeId` correct). Third-party aggregators do **not** carry it: **Artificial Analysis has no page (404)** and **OpenRouter has no row** — every hosted measurement therefore comes from Microsoft itself.
- **Release / knowledge:** **Released June 2, 2026** at Microsoft Build (Foundry model version `2026-06-01`; launch coverage dated 2026-06-03; the Surge case study and the microsoft.ai announcement post were republished/updated later in the summer, which is why crawl dates on those pages read August–September). **No knowledge cutoff is published anywhere for this ID** (third-party trackers list it as "not specified"), and no training-token count or dataset mixture is disclosed beyond the qualitative provenance claim. The Foundry how-to doc was last updated **2026-08-12** and still carries the preview/no-SLA banner.
- **IDs:** `MAI-Thinking-1` / `mai-thinking-1` (Foundry), `opencode/mai-thinking-1` (curated), `Microsoft AI: MAI-Thinking-1 technical report` (`microsoft.ai/pdf/mai-thinking-1.pdf`) as the citation string BenchLM uses for every row. **Aggregator coverage:** **BenchLM has a page** — **"14 source-displayable benchmark rows but no public overall score. It remains unranked"** (Overall "Not computed", 14 of 625 tracks), classified **Proprietary / Reasoning / 256K context**; **all 14 rows are attributed to the Microsoft technical-report PDF**, i.e. **zero independent rows**. **Artificial Analysis: no page (404)** — so there is **no Intelligence Index, no speed, no cost-per-task and no verbosity measurement** for this model anywhere. BenchLM's sibling list shows the rest of the MAI family (MAI-Code-1.1-Flash, MAI-Cyber-1-Flash, MAI-Voice-2/2.1, MAI-Transcribe, Fara1.5-27B/4B, VibeVoice-ASR) as "not computed" too, and **none of them has a folder in this registry**.
- **Context window:** **256,000 tokens** — the technical report states "**After mid-training, MAI-Thinking-1 achieves a maximum context length of 256K**", Foundry documents 256K, Microsoft's own framing is "a 256k token window (enough to fit a **600 page document**)", and BenchLM classifies it as 256K. Curated `meta.json` says "**131,072 total (32,768 out)**": the input figure is **half the real window**. The 32,768 output figure is **not corroborated by any Microsoft page I could read** — the Foundry doc publishes no max-output number, so treat it as curation-only. Real caveat: because the **encrypted reasoning state is re-sent and billed into the window**, effective usable context in a multi-turn agent loop is materially smaller than 256K.
- **Modalities:** **text in / text out.** The Foundry API surface is chat completions plus function tools, with **no image, file, audio or video input documented for this model** (image/voice capability lives in other MAI models — MAI-Image-2.5, MAI-Voice-2.1, MAI-Transcribe — not in Thinking-1), and BenchLM/technical-report rows are all text benchmarks. Curated "Text in/out" is **correct**.
- **Pricing (as of 2026-10-08):** **$2.00 per 1M input tokens, $0.20 per 1M cached input, $8.00 per 1M output tokens** for `MAI-Thinking-1 Global` on the **Azure Foundry Models pricing page** — corroborated by the model's own launch coverage. Curated `meta.json` says "**$2.00/$10.00 per 1M in/out**": **the output price is $2.00/1M too high** (a 25 % error). Early launch-era write-ups describing "private preview, no public price" are now superseded — the price is published, but **no cost-per-task, tokens/s or verbosity figure exists for this ID** (no AA page), so its cost story is unverifiable beyond list price. Also note reasoning tokens **are billed as output**, and the echo-back requirement makes long agent loops consume both.
- **Architecture:** **35 B active / ~1 T total parameters, sparse Mixture-of-Experts** (announcement: "a 35B-active, ~1T-total parameters, sparse Mixture of Experts model"), reasoning model with **persistent chain-of-thought state** exposed only in encrypted form, **256K** max context, **function-calling** trained, tuned for **multi-step math/coding/enterprise** work. Training provenance is the most distinctive published claim: trained **"without distillation from third party models"**, "from the ground up on **clean, traceable and enterprise-grade data**", and co-designed with **Microsoft's own accelerators and in-house RL framework** — the framing Microsoft calls the "**Hill-Climbing Machine**". Reported infrastructure detail (third-party analysis of the report): **4,096 of 4,864 GB200s devoted to inference**, ~5× the learner allocation, which is consistent with a 35B-active MoE being cheap per token to run but heavy on serving capacity. Safety is stated to be trained **inside the same RL reward loop** ("unsafe compliance and unnecessary refusal [treated] as defects"), and Microsoft's enterprise pitch adds multi-layer instruction following and Foundry security/compliance wrapping.

### Normalized scores (1–100)

- **Tool use: 60/100.** It is unambiguously built to be used as an agent: **function calling is a first-class, documented path** ("Use MAI-Thinking-1 in agentic workflows that call tools or functions"), **encrypted chain-of-thought can be carried across turns** specifically for "multi-turn agent loops and tool-calling workflows", it is **OpenAI-Chat-completions-compatible** (so existing harnesses drop it in), and its agentic-adjacent numbers are respectable — **SWE-bench Verified 73.5 %**, **SWE-bench Pro 52.8 %**, **Terminal-Bench 2.0 46 %**, **Graphwalks BFS@128K 90 %**. What keeps it out of the mid-70s is that **not one tool-use accuracy row exists**: **no τ²/τ³, no BFCL, no MCP-Atlas, no Toolathlon, no AutomationBench, no OSWorld, no GDPval**, and — decisively for a model with no AA page — **no aggregator-measured agentic composite at all**. Terminal-Bench **2.0** at 46 % also predates the harder 4.x generation that now anchors this registry, so the strongest agentic evidence is both mid-tier and on an older bar. Two structural deductions: "**Only function tools are supported**" (no built-in browsing/search/code-execution surface — the application must supply it), and the **preview/no-SLA** status, which the methodology treats as a real limitation for the enterprise agent deployments this model is marketed into.
- **Reasoning: 72/100.** The math rows are frontier-grade and are the reason this folder ranks where it does: **AIME 2025 97.0 %, AIME 2026 94.5 %, HMMT Feb 2026 84.9 %** at only **35 B active parameters**. Graduate-level science is solid but not frontier — **GPQA Diamond 84.2 %**, **MMLU-Pro 85 %** — and instruction-following is strong (**IFBench 85 %**), consistent with the stated "multi-layer instruction following" design. Two things cap the score. First, **SimpleQA 31 %**: factual recall over the open web is weak, and there is **no AA-Omniscience row** to tell us whether the model *refuses* (a good 31 %) or *invents* (a bad 31 %) — an unresolved question the methodology does not let me assume away. Second, and heavier: **every one of those rows is self-reported**, with **no Intelligence Index from an independent lab** to anchor them; the registry's mid-band anchors (Index 20–35 → 55–65, GPQA 90+/HLE 40+ → 90–100) can't be applied cleanly because **GPQA is 84.2 and no HLE or Index row exists at all**. 72 is a strong-but-unverified composite: the **Surge human-preference win over Sonnet 4.6** nudges it up (real expert raters, real multi-turn tasks), the **absence of any published margin** nudges it back.
- **Context window: 74/100.** **256K**, triply confirmed (tech report, Foundry doc, BenchLM classification), which places it in the registry's **200K–500K band (65–84)** well above the 200K ≈ 70 floor thanks to the only genuine long-context measurement available: **Graphwalks BFS at 128K = 90 %**, an agentic traversal task that fails badly on models whose mid-window attention degrades. It is **not** higher because the evidence stops there: **no AA-LCR, no MRCR / AI-Needle, no 512K+ needle or multi-document retrieval run** — the "600-page document" framing is marketing, not a measured retrieval rate — and the curated record understates the window by half, which is the kind of curation error that must be fixed before sync (`contextWindow` → **256,000**). The output side is the other drag: the curated sheet asserts **32,768** (which would trip the sub-64K-output caveat), Microsoft publishes **no max-output figure at all**, and the **echo-back rule means the encrypted reasoning the model needs in order to reason long is itself charged against those 256K**, so the *usable* window in exactly the long-horizon work it's sold for is smaller than the headline.
- **Multimodal: 15/100.** **Text-only.** The Foundry API for this model documents text messages, function tools and encrypted reasoning — **no image, document, audio or video input** — and BenchLM/tech-report coverage contains no MMMU, no document-OCR, no screenshot and no speech row. Vision and voice do exist in the MAI family (**MAI-Image-2.5** at $5/$47 per 1M, **MAI-Voice-2.1**, **MAI-Transcribe-2**) but they are **separate models with no folder in this registry**, so nothing transfers. 10–20 band, no lift; for a model whose enterprise pitch is "read this 600-page document", the fact that you must flatten the document to text first is a genuine gap rather than a neutral one.
- **Coding: 76/100.** This is the dimension with real, hard numbers and the dimension the launch was actually built around. **LiveCodeBench v6 87.7 %** is a frontier-band competitive-programming result, **SWE-bench Verified 73.5 %** is a strong real-repository figure, and **SWE-bench Pro 52.8 %** — the row Microsoft stakes the "toe-to-toe with Claude Opus 4.6" claim on — is high in absolute terms on the harness that currently discriminates the leaders. **Terminal-Bench 2.0 46 %** and the deterministic, test-graded training environments ("reading code, editing files, running tests, observing failures, and recovering from intermediate mistakes") support the agentic-coding story. It is held below 80 by three things: **no DeepSWE, no SWE-Marathon, no SciCode, no AA Coding Index and no Terminal-Bench 4.x row** (the registry's anchors for the 90–100 band are DeepSWE 74+/TB 85+/SciCode 55+), **the harness used is OpenHands/Terminus-era on TB 2.0** rather than current, and **nothing here was reproduced by a second lab** — for a model with no AA page, a 73.5 % SWE-V is a claim, not a measurement.
- **Cost efficiency: 78/100.** **$2.00 in / $8.00 out per 1M, with cached input at $0.20 (a 90 % discount)** from the Azure pricing page — genuinely aggressive for a model posting Opus-class coding rows, and the **35 B-active-of-~1 T MoE** is the structural reason it can be: the announcement's whole argument is that "model size determines where advanced coding assistance can be deployed, how often it can be used, and whether it can move from exceptional tasks into daily workflows". Against the registry's price anchors it sits between $1.25/$4.25 (≈88) and $3/$15 (≈60), so the list price lands upper-mid, and the cache discount plus OpenAI-compatible drop-in (no re-platforming cost) keep it there. The deductions are what make this dimension *unverifiable* rather than merely expensive: **no free tier and no self-host route** (proprietary, Microsoft-only), **no tokens/s, no cost-per-task and no verbosity measurement exists** because Artificial Analysis has no page — so a buyer cannot tell whether an AIME-97 model is also a 40K-reasoning-token model. Two known multipliers push the same way: **reasoning tokens bill as output at $8**, and the **encrypted-CoT echo re-sends thinking as input on every turn**, so multi-step agent loops cost more than the flat table suggests; and a **preview with no SLA** is not a production price you can plan capacity against. Curated output price (**$10.00**) is wrong and must be corrected to **$8.00** before sync.
- **Overall Score: 59/100.** Mean of the five quality dimensions (60 + 72 + 74 + 15 + 76) / 5 = 297 / 5 = 59.4 → 59; Cost excluded per `RULES.md`. Best fit: **enterprise math-and-coding workloads already inside the Microsoft stack** — Foundry-governed deployments needing long-horizon verification, multi-step mathematical reasoning (AIME 97.0 / 94.5, HMMT 84.9), competitive-programming strength (LCB v6 87.7) and real-repo repair (SWE-V 73.5 / SWE-Pro 52.8) with Entra ID auth, compliance wrapping and **verbatim-preserved reasoning state across turns**, at **$2/$8** with a 90 % cache discount. Unfit for **multimodal work** (text-only; the vision/voice MAI siblings have no folders here), unproven for **factual open-domain Q&A** (**SimpleQA 31 %**, no omniscience row), and a poor choice for anyone who needs **verifiable agentic numbers** — there is **no AA page, no aggregator composite at all (BenchLM leaves it unranked)**, no τ/BFCL/GDPval row and no independent reproduction of anything in this report. Also not for production traffic under contract: **preview, no SLA, "doesn't recommend it for production workloads."** **Curation fixes before sync:** `contextWindow` → **256,000 (max output not published)**; `pricingNote` → "**$2.00 / $0.20 cached / $8.00 per 1M in/out (Microsoft Foundry, GlobalStandard)**"; `short` → name the **35 B-active / ~1 T sparse MoE** shape and the **preview** status.
