## Model card

- **Name:** MAI-Thinking-1
- **Short description:** Microsoft AI's **first in-house reasoning model**, introduced at Build 2026 (**2026-06-02**) and in **public preview on Microsoft Foundry as of 2026-08-12**; **still Preview, not GA, as of 2026-10-17.** A **35B-active / ~1T-total sparse MoE** whose selling point is that the *active* parameter count — not the trillion-parameter headline — drives inference cost. It is deliberately built on **clean, licensed, human-generated data with no third-party distillation and no AI-generated content in pre-training**, and Microsoft leans hard on that for enterprise provenance, auditability and control. Top use case: enterprise reasoning, agentic software engineering, and math/science work on Microsoft Foundry/Azure with compliance requirements.
- **Provider / access:** **Microsoft Foundry / Azure AI only** — "Direct from Azure," catalog version **2026-06-01**, lifecycle **Preview**. Gated to a Foundry private preview at Build, opened to public preview on 2026-08-12, and **still listed as Preview in the live Foundry catalog** (every neighbouring MAI entry in the catalog — MAI-Voice-2, MAI-Transcribe-1.5, MAI-Image-2.5 — carries the same Preview label, while non-MAI entries such as `gpt-6-astra` and `DeepSeek-V4-Flash` are marked "Generally available (GA)"). OpenAI-compatible **Chat Completions API**. Azure's region-availability table lists version `2026-06-01` as available across **all twelve listed global regions**. No OpenRouter, DeepInfra, or OpenCode Zen ID found.
- **Release / knowledge:** Announced **2026-06-02** (Build 2026); **public preview 2026-08-12**; Foundry catalog version dated 2026-06-01. **Knowledge cutoff: July 2025** — newly found this pass, stated in the official model card as "Training cut-off date: July 2025" (the first pass recorded it as not disclosed).
- **IDs:** `MAI-Thinking-1` (Microsoft Foundry / Azure AI model catalog)
- **Context window:** **256K tokens / 64,000 max output** — the Foundry catalog lists "Context window 256k, Token limits 64k output," and the official model card states "MAI-thinking-1 has a 256K context window." **New conflict to record:** Microsoft's own **Foundry Labs** page (dated 2026-06-03) describes "The **200K-token** context window." Prefer **256K**: the catalog quick facts and the model card agree and are the shipping configuration, while the Labs page predates both and reads as an early draft. This pass also **overturns the first pass's claim that no long-context retrieval benchmark has ever been published** — see GraphWalks below.
- **Modalities:** **Text in → text out only.** The Foundry catalog lists `Input type: text` / `Output type: text`; llmreference explicitly advises against using it for "vision or document-understanding workloads." Reasoning: yes — internal chain of thought before the final response, with reasoning effort **allocated adaptively to prompt complexity**. Tool calls / function calling: yes. Developer instructions: supported; the model was trained to follow multiple layers of instructions. **New this pass — an explicit vendor restriction:** the Foundry catalog's Key Use cases section states the model "is **not designed or evaluated for use as an autonomous decision-maker in consequential domains**" and should not be the sole basis for legal, financial, medical, employment, educational, housing, credit or safety-critical decisions.
- **Pricing (as of 2026-10-17):** **Now verifiable, and it is the most consequential correction in this report.** Microsoft's own **Azure Foundry Models pricing page** lists **MAI-Thinking-1 Global at $2.00 input / $0.20 cached input / $8.00 output per 1M tokens.** The first pass could not confirm any numeric tariff — the catalog renders pricing behind a JS control and the model card says only "Pricing is based on a number of factors" — and scored the model at 82 on positioning language alone. That gap is closed. For reference the same page lists MAI-DS-R1 Global at $1.35/$5.40 and MAI-Cyber-1 Flash Global at $0.60/$3.50. Azure also offers PTU reservation and Agent Commit Unit pre-purchase plans. Paid only — Preview, no Free tier.
- **Architecture:** proprietary closed weights — **weights not released**. Sparse MoE Transformer, **35B active / ~1T total**. Base model: **MAI-Base-1**, pre-trained from scratch on **8K GB200 GPUs** on a Microsoft-operated cluster inside Azure, using in-house distributed training infrastructure. Pre-training corpus: **30T tokens** of publicly available and licensed **human-generated** data — web, public GitHub code, books, academic papers, news, multilingual text, code, academic and PDF content, math/STEM web content, and structured knowledge sources — all processed in-house. Mid-training then emphasized STEM, math and coding ahead of reasoning RL climbs. Post-training: SFT on model-generated completions plus reinforcement learning across **verifiable reasoning, software engineering, tool-use and instruction-following environments**, using **8M+ reinforcement-learning environments**. **Chain-of-thought sequences were length-compressed while preserving task performance**, reducing the token cost of a typical response — which is the mechanical reason the model can plausibly justify an $8 output rate.

### Raw benchmarks found

> All figures below are **Microsoft-reported**, from the 109-page technical report *"MAI-Thinking-1: Building a Hill-Climbing Machine"* (`microsoft.ai/pdf/mai-thinking-1.pdf`), the official model card, the Foundry catalog and the launch blog. **This pass added a significant caveat the first pass did not record:** as of **2026-10-17 there is still no independent reproduction of any MAI-Thinking-1 benchmark number by anyone.** BenchLM's model record, updated 2026-10-16, attributes all 13 of its rows to "Microsoft AI: MAI-Thinking-1 technical report." The independent leaders that matter — Scale Labs' own SWE-Bench Pro board and llm-stats' SWE-bench Pro leaderboard — **do not list MAI-Thinking-1 at all**, or list it as self-reported among 60 such rows. So the first pass's citation of an "independent rank #35 of 46" was misleading: that ranking re-sorts Microsoft's own 52.8% against other vendors' self-reported numbers. It is not an independent measurement.

So 52.8% has **never been independently reproduced, and the one lab that does publish a standardized Pro board has not measured this model.** That is a material limitation on every coding score below.
- **SWE-bench Verified: 73.5%** — first-pass cited an "independent rank #47 of 81"; again a re-sort of the vendor number. For calibration, Claude Sonnet 4.5 scores 77.2% and GLM-4.7 73.8% on the same aggregator — i.e. this is a mid-pack SWE-bench Verified, not a strong one. Microsoft itself concedes Sonnet 4.6 and Opus 4.6 lead here.

### Normalized scores (1–100)

- **Tool use: 72/100** *(up from 70).* The new evidence is **IFBench at 85%, ranked #3 of 148 on BenchLM's instruction-following lane** — a top-tier result in the dimension that most directly predicts whether an agent completes a long multi-step task without instruction drift, and one this model scores better on than the GLM-4.7 it is routinely compared against. It joins tool calling as a first-class post-training target inside an 8M+-environment RL programme and **Terminal-Bench 2.0 at 46.0%**. Held well short of the frontier band by the near-total absence of published agentic benchmarks: no Tau3, no GDPval-AA, no OSWorld, no AutomationBench, no Claw-Eval, no MCP-Atlas, Terminal-Bench 3.0/4.0 unpublished, and 46.0% on TB 2.0 is itself below Claude Sonnet 4.5's 50.0% on the same aggregator.
- **Reasoning: 87/100** *(up from 84).* The second pass filled the single largest hole in the first pass's reasoning case. The first pass rested on three numbers (AIME 2025 97.0%, AIME 2026 94.5%, GPQA Diamond 84.2%) and explicitly recorded "no verified public score found" for **MMLU-Pro and MMLU**. Both **HMMT Feb 2026 at 84.9%** and **MMLU-Pro at 85%** are in the technical report and now surface in the raw section. Five elite maths/science results plus mid-80s GPQA and MMLU-Pro is a genuinely strong profile. Not higher because **HLE remains entirely unpublished** — a real gap given the methodology weights it alongside GPQA — because every number is vendor-run, and because llm-stats' aggregate Reasoning index is a modest 33.7 (#87).
- **Context window: 84/100** *(up from 80).* **256K in / 64K out**, with the 200K figure from the Foundry Labs page noted and preferred against. The load-bearing change is that the first pass's flat statement — *"No long-context retrieval benchmark — MRCR, RULER, LongBench or AA-LCR — has ever been published for this model"* — **is now false: GraphWalks BFS at 128K, 90.0%** appears in the technical report and is carried by BenchLM. That is a genuine retrieval result at half the advertised window, so it evidences real long-context ability rather than merely declaring intent. Top of the 200K–500K band; held there rather than higher because 90% at 128K is good, not excellent, it is vendor-measured, and no result exists at the full 256K.
- **Multimodal: 15/100** *(unchanged).* **Text-only**, confirmed by the Foundry catalog (`Input type: text`, `Output type: text`) and by llmreference's explicit advice against vision/document workloads — and reinforced this pass by Microsoft's own new catalog language barring consequential autonomous use. Floor score by methodology. Pre-training did include PDF-derived *text* content, which is not PDF input support.
- **Coding: 76/100** *(down from 78).* The underlying numbers are unchanged — SWE-bench Pro 52.8%, SWE-bench Verified 73.5%, LiveCodeBench v6 87.7% — but the second pass produced evidence that the first pass's framing overstated the model's standing. The first pass cited "#35 of 46" on SWE-bench Pro and "#47 of 81" on SWE-bench Verified as *independent* ranks; they are re-sorts of Microsoft's own figures, and the first pass said so nowhere. Against llm-stats' current 60-model board the model sits **48th, with the leader at 89.9%**. More decisively, **Scale Labs' own standardized SWE-Bench Pro leaderboard does not list MAI-Thinking-1 at all**, and Scale documents a regime in which top models score around 23% on the public set — so the 52.8% is harness-specific and has never been independently reproduced. Against that, LiveCodeBench v6 at 87.7% genuinely leads GLM-4.7 (84.9%), and Terminal-Bench 2.0 at 46.0% beats GLM-4.7 (41.0%) while losing to Sonnet 4.5 (50.0%). Net: a credible coding profile for the active-parameter class that is mid-pack, not leading, and entirely vendor-sourced.
- **Cost efficiency: 72/100** *(down from 82 — the largest single revision in this report).* The first pass scored 82 on Microsoft's qualitative positioning alone and flagged it as "the least-evidenced number in this report." The evidence is now in, and it is worse than the positioning suggested: **$2.00 input / $0.20 cached / $8.00 output per 1M** on Microsoft's own Azure Foundry pricing page. On the methodology's own anchors that sits well past the ~$1.25/$4.25 → ~88 point and materially better than the $3/$15 → ~60 point, landing near ~72. Microsoft's "mid-weight price" and "best price-to-performance ratio in its weight class" claims are about performance *per active parameter*, not per dollar of output; an $8 output rate on a reasoning model with length-compressed CoT is simply expensive per request. The **$0.20 cached-input rate is a genuine 10× discount** and matters enormously for long-context, repeatedly-rescored agent loops, which is the main reason this is 72 rather than lower. There is no Free tier and the model is Preview-only on a single Foundry route.
- **Overall Score: 67/100** *(was 65).* Arithmetic: **(72 Tool + 87 Reasoning + 84 Context + 15 Multimodal + 76 Coding) / 5 = 334 / 5 = 66.8 → 67.** Cost efficiency (72) is excluded by the v4 rule, so the verified $2/$8 tariff **does not move the Overall** — but it changes every deployment decision built on it, and the two genuine quality gains (Reasoning +3, Context +4) outweigh the coding revision (−2). Best fit: **regulated enterprise deployments on Microsoft Foundry where data provenance is a hard requirement** — Microsoft's no-distillation, no-AI-generated-pretraining-data, in-house-processed 30T-token corpus and fully in-house 8K-GB200 training pipeline are a genuine and rare auditability story, and AIME 2025 at 97.0% with MMLU-Pro at 85% and IFBench at #3-of-148 is a strong combination. Two caveats to carry into any procurement: **budget at $2/$8, not at the "mid-weight price" the marketing implies**, and note that Microsoft's own catalog bars the model from autonomous use in consequential domains — which rules it out for exactly the legal, financial and credit decisions its enterprise provenance story would otherwise suit.
