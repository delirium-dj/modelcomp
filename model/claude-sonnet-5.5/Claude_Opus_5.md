## Model card

- **Name:** Claude Sonnet 5.5 — the Sonnet-tier model of the Claude 5.5 family, described in Anthropic's docs as "the best combination of speed and intelligence" in the current lineup, with latency rated **Fast** against Opus 5.5's **Moderate**. No free API tier. Variant/alias flag: distinct from `claude-sonnet-5`; it sits between **Claude Opus 5.5** ($4/$20) and **Claude Haiku 4.5** ($1/$5).
- **Short description:** Released **2026-09-28**, six days after Opus 5.5 opened the family, as "a faster, lower-cost complement to Claude Opus 5.5" at **unchanged Sonnet 5 pricing**. The capability move is large: Terminal-Bench 4.0 went from 10.3% to 70.6% and Chartography from 15.6% to 61.6%. Anthropic's system card is unusually balanced about where it lands — Sonnet 5.5 "significantly outperforms Sonnet 5 across many domains" and "in a few areas, it rivals or exceeds Claude Opus 5.5", while also being **"broadly less capable than Opus 5.5 across domains"**; it crosses no new Responsible Scaling Policy thresholds.
- **Provider / access:** Claude API (`claude-sonnet-5-5`, Messages API), Amazon Bedrock (`anthropic.claude-sonnet-5-5`), Claude Platform on AWS, Google Cloud and Microsoft Foundry (all `claude-sonnet-5-5`), plus the Claude apps from launch day (where **default effort is medium**, versus **high on the API**). Third-party distribution is unusually broad for a launch: **Claude Code 2.1.284 made it the default Sonnet model**, **GitHub Copilot made it generally available** across Pro/Pro+/Max/Business/Enterprise in VS Code, JetBrains, Copilot CLI and the coding agent, and **Cursor** added it on day one, stating it performs "on par with Opus in many tasks".
- **Release / knowledge:** Released 2026-09-28 (release notes, model docs and system card agree). **Knowledge cutoff June 2026** (reliable and training-data cutoff). Retirement not sooner than 2027-09-28.
- **IDs:** `claude-sonnet-5-5` (Claude API / Google Cloud / Microsoft Foundry / Claude Platform on AWS); `anthropic.claude-sonnet-5-5` (Amazon Bedrock). **No free-tier ID.**
- **Context window:** **1,000,000 input tokens; 128,000 max output on the synchronous Messages API and 300,000 on the Batch API** with the `output-300k-2026-03-24` beta header. **The full 1M context bills at the standard rate** — a 900K-token request costs the same per token as a 9K one. The **minimum cacheable prompt drops to 512 tokens** from Sonnet 5's 1,024, making prompt caching viable on short system prompts, and the tokenizer is unchanged from Sonnet 5 so identical text yields identical token counts.
- **Modalities:** Input: **text and images only**. Output: text only. No audio or video in either direction. Reasoning: adaptive thinking, on by default, steered by `output_config.effort` across **`low` | `medium` | `high` (API default) | `xhigh` | `max`**. **`thinking: {"type": "disabled"}` returns a 400** — the lowest available setting is `{"type": "between_tools"}`, which removes up-front thinking and works only at high effort or below. Thinking counts toward `max_tokens` even when the text is not returned (Anthropic recommends `max_tokens=128000` with streaming for agentic coding). **Non-default `temperature`, `top_p` or `top_k` return a 400.** Tool calls: yes, but **forced tool use is retired** (`tool_choice` of `any` or a named tool returns 400) — use `auto` with `strict: true` definitions or structured outputs.
- **Pricing (as of 2026-10-03):** **$2.00 / 1M input, $10.00 / 1M output — identical to Sonnet 5**, i.e. the capability gain was free. 5-minute cache write $2.50, 1-hour cache write $4.00, **cache read $0.20**, Batch API $1 / $5. Batch and caching discounts stack. `inference_geo: "us"` adds a 1.1x multiplier, and **Bedrock and Google Cloud regional endpoints carry a 10% premium** over global endpoints. Notable quirk: cache reads cost $0.20/1M on *both* Sonnet 5.5 and Opus 5.5, because Opus uses a 0.05x multiplier instead of the usual 0.1x — so for cache-heavy agent loops the price gap between the two models narrows to uncached input and output only.
- **Architecture:** Proprietary, closed weights. Parameter count, active parameters and topology: not disclosed.

### Raw benchmarks found

> Two sets. **Vendor-reported** = Anthropic's launch table and system card §8 (Table 8.1.A), using adaptive thinking at **max effort averaged over five trials**, with competitor figures taken from those developers' own system cards or leaderboards — Anthropic footnotes that an OpenAI bug fix may not be reflected in some GPT-6 Sol scores. **Independent** = Artificial Analysis's own harness at max effort. Where Anthropic reports a better score at a different effort level, both are recorded.

Agent / tool use:

- Terminal-Bench 2.1: no verified public score found. **Terminal-Bench 4.0: 70.6%** (vendor; Sonnet 5 10.3% — a 60-point jump) — **beats Claude Opus 5.5's 66.4%**, and **independently confirmed as a win: Artificial Analysis's own run scored Sonnet 5.5 at 64% against Opus 5.5's 60%**. This is the headline result: the mid-tier model beats its own flagship on terminal agency under two separate harnesses.

- **GDPval-AA v2.1 (Elo): 1,844** (vendor; Sonnet 5 1,449, **Opus 5.5 1,846 — a 2-Elo gap**, GPT-6 Sol 1,487) — **above the methodology's ~1750+ frontier reference**

- Toolathon / MCP-Atlas / SWE Atlas Codebase QnA: no verified public score found

### Normalized scores (1–100)

- **Tool use: 93/100.** The strongest value-for-capability agentic profile in this dataset. **GDPval-AA v2.1 at 1,844 Elo clears the ~1750+ frontier reference and lands within 2 Elo of Claude Opus 5.5**, AA-Briefcase 1,811 corroborates on a private harness, and most notably **it beats its own flagship on two agentic benchmarks under two independent harnesses** — Terminal-Bench 4.0 at 70.6% vendor / 64% AA against Opus 5.5's 66.4% / 60%, and AutomationBench at 44.7% vendor / 71% AA against 42.5% / 70%. OSWorld 2.1 at 80.1% is within 1.7 points of Opus. Held at 93 rather than higher because **Tau3-Banking, Claw-Eval, Toolathon and MCP-Atlas are all unreported** (explicit methodology penalty), **forced tool use has been removed** which breaks existing agent patterns, and the best third-party AutomationBench figure (44.75% at $1.14/task) was achieved **with default fallbacks** — a system result rather than a clean model measurement.
- **Reasoning: 92/100.** **HLE at 56.9% without tools and 64.5% with tools** is far above the 40%+ frontier reference and a 13.8-point jump over Sonnet 5; the independent **Intelligence Index of 56 ranks #2–#3 overall and sits only 2 points behind the field leader**; and the hallucination picture is genuinely better than the flagship's — **47% against Opus 5.5's 59%**, which for retrieval-backed production systems is the more useful property. Capped at 92 by four things: the Index is still **below the 60+ marker**; **AA-Omniscience accuracy of 54% against Opus 5.5's 66%** means materially weaker unaided factual recall; **GPQA Diamond, MRCR/LCR and CritPt are all unreported**; and Anthropic's own system card states plainly that it is "broadly less capable than Opus 5.5 across domains".
- **Context window: 95/100.** A verified **1,000,000-token input window with 128K synchronous output (300K on Batch beta)** places it in the ≥1M tier (95–100), and the commercial terms are among the best here: **the full window bills at the standard rate with no long-context premium**, cache reads are $0.20/1M, and the **512-token minimum cacheable prompt** (halved from Sonnet 5) makes caching work on short prefixes. It sits at the tier floor because the 100 condition (≥98% retrieval at 512K+) has **no supporting evidence at all** — no MRCR, RULER or GraphWalks figure exists for this ID — and because the Claude tokenizer's post-4.7 behaviour means a nominal 1M window holds roughly 30% less text than the number implies.
- **Multimodal: 70/100.** Input is **text and images only** with text-only output and no audio or video path, fixing it in the methodology's "+image in = 60–70" band. It earns the top of that band on measured evidence: **Chartography rose from 15.6% to 61.6%** — a 46-point generational jump, the largest in the release — SWE-Bench Multimodal reached 54.3% from 28.1%, and OSWorld 2.1 at 80.1% is entirely screenshot-grounded computer use. Frontier-grade vision cannot lift it into the 75–90 band when there is no video, PDF or audio input path and no non-text output.
- **Coding: 92/100.** **SWE-Bench Pro 81.3% and SWE-Bench Multilingual 90.3%** are frontier-adjacent, **Terminal-Bench 4.0 at 70.6% beats Opus 5.5**, CursorBench 4.0 reaches 55.5% (from 34.1%), and most striking — **Vals AI's own Vibe Code Bench page puts Claude Sonnet 5.5 at 92.39%, ahead of Gemini 4 Argon's 91.9%**, making a mid-tier model the current leader on that benchmark. The FrontierCode gap to Opus narrows to **2.3 points at xhigh (52.1 vs 54.4)** once the right effort level is used. Deductions: **SWE-Bench Pro trails Opus 5.5 by 8.6 points** on the benchmark that best predicts real repository bug-fixing, SWE-Bench Multimodal at 54.3% is weak, and **SWE-bench Verified, DeepSWE, LiveCodeBench and SciCode are all absent**, so most of the band's references cannot be checked.
- **Cost efficiency: 62/100.** The list price is excellent — **$2 / $10 is better than the $3/$15 anchor that maps to ~60**, unchanged from Sonnet 5 despite large capability gains, with $0.20 cache reads, Batch at $1/$5, no long-context premium on the full 1M window, a 512-token caching floor, and Haiku 4.5 at $1/$5 for downward routing. But the **measured per-task cost contradicts the per-token story at max effort, and the evidence is independent**: AA recorded **~193,000 output tokens per task — the highest it has ever measured, ~60% more than Opus 5.5 — at $7.60 per task versus Opus 5.5's $5.98**. The nominally half-price model is **more expensive per task than the flagship it undercuts**, and 10x more expensive per task than GPT-6.1 Sol ($0.72) at the identical $2/$10 list rate. Add `inference_geo: "us"` at +10%, regional cloud endpoints at +10%, and the fact that **thinking cannot be fully disabled** (`between_tools` is the floor). Anthropic's "up to 30% cheaper per task" claim is plausible at medium effort but is unmeasured by any independent party. Net: a great rate card that only materialises as a low bill if you set effort deliberately.
- **Overall Score: 88.4/100.** Mean of the five non-cost dimensions (93 + 92 + 95 + 70 + 92) / 5 = 88.4 — the right **default** for most production agents and coding assistants, and the most defensible mid-tier pick in this dataset: within ~2 points of Claude Opus 5.5 on OSWorld, GDPval-AA, AA-Briefcase, CursorBench and the Intelligence Index, **ahead of it on Terminal-Bench 4.0, AutomationBench and HealthBench Professional under both vendor and independent harnesses**, current leader on Vals' Vibe Code Bench, with a lower hallucination rate than the flagship — at half the per-token price. Escalate to Opus 5.5 for hard multi-file software engineering (SWE-Bench Pro 81.3 vs 89.9) and unaided knowledge-heavy Q&A (AA-Omniscience 54% vs 66%); drop to Haiku 4.5 or `low` effort with `between_tools` for high-volume simple work. The one thing to get right is **effort**: leave it on `max` and an independently measured 193K output tokens per task will make this cheaper model cost more than the flagship. Budget an afternoon for the five breaking changes from Sonnet 5 — disabled thinking, forced tool use, append-only thinking blocks, the new computer-use toolset and advisor pairings are hard blocks, not rough edges.
