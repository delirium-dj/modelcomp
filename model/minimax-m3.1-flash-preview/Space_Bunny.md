## Model card

- **Name:** MiniMax M3.1 Flash Preview
- **Short description:** MiniMax's fast tier-preview text model for everyday agentic coding, launched 2026-09-27 inside MiniMax Code and the Token/M Plan subscription rather than as a pay-as-you-go API entry. It inherits MiniMax-M3's 1M context and native-multimodal stance, adds a five-rung `effort` thinking dial, and makes thinking mandatory (it cannot be switched off). **Variant note:** it is a sibling of MiniMax-M3, not a documented successor — no model card, no parameter sheet, no vendor benchmark table, and no per-token rate accompanied it.
- **Provider / access:** MiniMax Code (desktop + `mcode` CLI) and MiniMax **Token Plan / M Plan subscription key only** — not pay-as-you-go, not on third-party routers. The same model ID is served over MiniMax's Anthropic-compatible endpoint (`https://api.minimax.io/anthropic`, MiniMax's recommended path), its OpenAI-compatible Chat Completions endpoint (`https://api.minimax.io/v1`), and its OpenAI Responses endpoint. Chat Completions *and* Responses are both available; `thinking.type=disabled` and `effort=none` return an HTTP 400 on this model.
- **Release / knowledge:** 2026-09-27 (MiniMax developer documentation model table, `@MiniMaxAgent` post on X, same day; reached MiniMax Code and Token Plan 2026-09-28). Knowledge cutoff not published.
- **IDs:** `MiniMax-M3.1-Flash-Preview` (MiniMax developer documentation and the MiniMax agent-tools preview guide, which names this exact value as the API model ID). No Zen Free ID, no third-party router ID. One aggregator (apimaster.ai) explicitly warns that the `M3.1-Flash-Preview` label shown in the MiniMax Code UI is **not** a verified public API request ID and that no public route exists for it — this is consistent with MiniMax's own docs and is recorded as a caution, not a contradiction.
- **Context window:** **1,000,000 tokens** — the same ceiling MiniMax-M3 carries, and it is on MiniMax's own live supported-models table (platform.minimax.io/docs/guides/text-generation). **Max output: 128K recommended, 512K (524,288) maximum** per MiniMax's own docs, as reproduced by myclaw.ai's spec table citing MiniMax. This supersedes the first pass's reading, which treated 128K as a repository-fixture artifact and left max output unpublished — the 512K ceiling is a documented vendor limit, and the 128K figure is the *recommended* client setting. MiniMax's own third-party-tool configuration guidance (platform.minimax.io/docs/m-plan/other-tools) shows a sample client config with `contextWindow: 524288` and `maxTokens: 128000`, i.e. a deliberately conservative client-side pairing, consistent with "128K recommended, 512K maximum". A separate in-product measurement reports an effective window of only 131,072 inside MiniMax Code, which is a MCode artifact, not the API ceiling. No MRCR / RULER / GraphWalks retrieval measurement exists at any window length for this checkpoint.
- **Modalities:** text, image, and video in; text out, plus a separate `reasoning_content` thinking stream. Reasoning **yes, always on and non-disableable**. Five `effort` rungs — `low`, `medium`, `high`, `xhigh`, `max` — **defaulting to `max`**. Tool calling supported; prompt caching supported; JSON-mode support not separately documented for this ID. Hands-on testing confirms real image and video comprehension (hand-drawn fantasy-map terrain/landmark reconstruction, and a NASA NICER repair-training video transcribed into a timecoded service manual that separated dialogue-confirmed steps from unverifiable ones — woshipm.com, 2026-10-01).
- **Pricing (as of 2026-10-17):** **still no per-token rate published anywhere.** The model remains absent from MiniMax's pay-as-you-go price list. The only first-party numbers are the **Token Plan subscription tiers: Plus $22 / Max $55 / Ultra $132 per month** (MiniMax's own Token Plan pricing, cited by myclaw.ai and DataNorth), against published monthly quotas of roughly **1.7B / 5.1B / 12.5B M3-equivalent tokens** — an implied **~$0.011–0.013 per 1M tokens**. That implied figure is a *quota amortisation*, not a rate card: quota is metered in rolling 5-hour and weekly windows, clears monthly, and cannot be billed against a single request. Separately purchasable Credits ($1 per 1,000 credits) extend the same quota mechanism rather than creating metered pricing. **Note a source conflict on the tier prices:** eesel.ai publishes $20 / $50 / $120 monthly with annual figures of $220 / $550 / $1,320, while MiniMax's own pricing is quoted at $22 / $55 / $132 — the annual column in eesel's table is almost certainly the mislabelled source of the difference, and MiniMax's own numbers are used here. MiniMax's own Token Plan pricing footnote still lists M3, M2.7, image and speech but **not** M3.1, contradicting the model pages that say Token Plan is the only way in — an inconsistency first flagged on launch day and still live. For contrast, the shipped sibling MiniMax-M3 is on the pay-as-you-go table at **$0.30 / $1.20 per 1M (≤512K input) and $0.60 / $2.40 (>512K input), cache read $0.06 / $0.12, with a Priority tier at 1.5×**. Do not read the $0.00 figures aggregators show for this ID as "free" — they mean *unpriced*.
- **Architecture:** **conflicting public claims.** The MiniMax agent-tools preview guide describes a mixture-of-experts model with **428B total / ~23B active parameters**, sparse attention, and a native visual encoder. Independent trackers and launch coverage state the parameter count is undisclosed and treat 428B as a transcription of the parent M3's figure — a preview reusing M3's context ceiling and modality set is not thereby the same model, so the 428B/23B numbers are recorded here as **vendor-guide claims, not verified specification**. No weights: the MiniMaxAI organisation has no M3.1 checkpoint, so unlike MiniMax-M3 there is nothing to download.

- Qualitative agentic evidence only: hands-on MiniMax Code testers report the model decomposing complex tasks, using search and tools to fill gaps, and re-checking finished artifacts before handing them over (woshipm.com, 2026-10-01). This is workflow observation, not a harness measurement, and is not scored as one.
- **Latency / throughput (independent measurement, MiniMax Code client):** sustained **~100 tokens/s decode** at `max` effort with 1M context regardless of thinking length (woshipm.com, 2026-10-01); day-one developer reports put it in a **90–110 tok/s** band, faster than MiMo-V2.6-Flash and slower than DeepSeek-V4.1-Flash (eesel.ai quoting @AJ on X, 2026-09-28). MiniMax's own agent-tools preview guide lists **~150 tok/s**; that is a vendor figure and is treated as provisional against the two independent measurements. A community reproduction published 2026-10-02 (ai-zeekr-feng.cloud) reports **TTFT 212 ms at `low` / 315 ms at `medium` / ~800 ms at `high` / 1.39 s at `max`**, with throughput 134.5 / 121.2 tok/s at low and medium respectively, and states explicitly that these are community figures, not official benchmarks. It also cites an "official" TTFT of ~280 ms and 126+ tok/s streaming — a vendor figure not present on MiniMax's English docs and recorded as unverified.

This is a real independent measurement of *something*, but the task set behind the subscore is not disclosed, it is not a GPQA/HLE/CritPt measurement, and the model cannot be called by third parties outside MiniMax's own surfaces — so it is recorded as a supporting signal only and **not** used as a reasoning anchor.
- Documented finance-analysis task (qualitative): given MiniMax's 2026 interim and 2025 annual reports, the model built a local verification tool with sourced PDF ingestion and correctly decomposed the widening adjusted net loss (~1.39 → 2.93 USD H1) against the fair-value loss on financial liabilities (~-2.23 USD) and the R&D increase (~+1.73 USD), presenting the reasoning as an explicit listed chain rather than a bare conclusion (woshipm.com, 2026-10-01).
- Hallucination-resistance note (qualitative, same source): on the NASA NICER video the model explicitly separated what dialogue confirmed from what the frames could not verify, and flagged a suspected speech-recognition error instead of smoothing it over. That is the desired behaviour and it is noted as a qualitative signal, not a measured hallucination rate.

Coding:

- **KingBench 3: 66.25% (53/80 points across eight tasks)** — AICodeKing independent run, reported by [zoviai.com](https://zoviai.com/minimax-m3-1-flash-fully-tested-okay-this-model-is-pretty-good/) (2026-09-28) and independently written up by [volanea.com](https://www.volanea.com/blog/minimax-m3-1-flash-review). This is a **partial-credit** interactive-application suite: the 3D folding table scored 9/10 with a working fold mechanism, the contact-lens case 8/10, the dual-time-zone GMT watch 7/10 with correct London/Tokyo offset switching, the local Gemma-2B fine-tune project scored well (184 facts → 920 train / 184 validation examples, 600 iterations, validation loss 3.893 → 0.207, real LoRA adapters and a working Ailurupoda interface), the archery game 4/10 (misplaced targets, faulty leaderboard timer) and the elevator simulation 3/10 (the spawn button threw a browser error because a numeric x-position was called as a function; passengers never spawned). In the same comparison the model **still trails GPT-6 Sol, SWE 2 and Claude Opus 5.5** overall, and beat the earlier MiniMax M3 entry (31.25%) by 35 points. M3's 31.25% is a same-harness reference point, not an M3.1 result.
- **ModelDial harness (second independent partial-credit suite, new in this pass): overall 68.45 at `max`, rank 20 of 41 models tested.** Dimension sub-scores: **Backend engineering 75** (service logic/error handling/test verification 75), **Knowledge & Reasoning 75**, **Visual aesthetics 70**, **Frontend interaction 57**, **Maintainability 53**; evaluation time 54 m 7 s. All five effort rungs were run (backend: 30 low / 34 medium / 65 high / 50 xhigh / 75 max), showing a strongly non-monotonic effort curve — `max` is much better than `xhigh` on backend work even though `xhigh` beat `high`. **Provenance caution:** this is a commercial third-party harness whose task set and grading are not published, and it published no reference cost for the model, so it is treated as a second opinion on the *shape* of the result rather than as a peer of KingBench 3.

### Normalized scores (1–100)

- **Tool use: 42/100.** Unchanged. Lowest-confidence dimension in this report. The model still has no Terminal-Bench 2.1, Tau3, GDPval-AA, MCP-Atlas or AA-AutomationBench row anywhere, so the score cannot be anchored to the methodology's frontier or mid reference bands. It is set above the text-only floor only on documented capability and workflow evidence: tool calling is supported, MCode drives it through a Coder/Verifier agent triad, and independent testers observed it decomposing tasks, reaching for search and tools, then re-inspecting artifacts. **What caps it:** zero harness measurements means every standard agentic-tool anchor in `../../model-comparison.md` is unavailable, and the methodology's explicit rule is to note the gap and penalise rather than assume a mid-tier band. The only candidate new row — aiintoai's Terminal-Bench 4.0 76.5% — comes from a source rejected above on provenance grounds and is not counted.
- **Reasoning: 55/100.** Unchanged. No GPQA Diamond, HLE, LCR, CritPt or Intelligence Index value exists for this model, so this is the bottom of the methodology's mid band by default rather than a measurement. The two supporting signals are unchanged in kind (a correct 10/10 on the KingBench 3 combinatorics task; two documented multi-step analytical tasks producing explicit itemised reasoning chains), and the ModelDial "Knowledge & Reasoning 75" subscore is new but methodologically opaque — a 75 on an undisclosed knowledge/reasoning battery is not a substitute for a GPQA or HLE figure, and letting it move the score would be exactly the kind of anchor inflation this dimension's confidence does not support. **What caps it:** the entire band is unverified — a single correct maths answer is not a reasoning benchmark, and no knowledge-retention or long-context reasoning figure was ever published.
- **Context window: 95/100.** Unchanged. Tier mapping: ≥1M = 95–100, and the documented ceiling is exactly **1,000,000 tokens** on MiniMax's own supported-models table. Not 100 because that tier requires **≥98% retrieval measured at 512K+**, and no MRCR / RULER / GraphWalks run exists at any length. The first pass flagged the missing max-output figure as an unresolved caveat; that is now closed — **512K maximum, 128K recommended** is documented by MiniMax — but it moves nothing in the score, because the tier is set by the input window and the retrieval evidence, and neither changed.
- **Multimodal: 82/100.** Unchanged. Methodology band: text + image + video in, text out = 75–90. Placement is in the upper half of that band on demonstrated comprehension rather than vendor claims: independent testing shows it reconstructing terrain, orientation and art style from a hand-drawn map and naming unmarked features, and turning a professional NASA repair-training video into a timecoded procedure manual while explicitly marking what the frames could not confirm; audio *understanding* was exercised (a music player that visualises volume, drum hits and accents and responds live to level changes) but there is **no audio input and no non-text output**, which is what the 90–100 band requires. ModelDial's independent **visual aesthetics 70** is consistent with that read and does not change the placement.
- **Coding: 63/100.** Up one point from 62. Two *independent* partial-credit application suites now land in the same band: **KingBench 3 66.25% (53/80)** and **ModelDial overall 68.45 at `max` (rank 20/41)**. The second suite also independently reproduces the first suite's signature shape — strong on backend logic and visual/static output (backend 75, visual aesthetics 70), weak on interactive, stateful front-end work (frontend interaction 57, maintainability 53), which is precisely where KingBench 3 lost its points (elevator 3/10, archery 4/10). Two suites agreeing on both the level *and* the failure mode is a modest but real tightening of the estimate, which is what the one-point move reflects. **What caps it:** no SWE-bench Verified/Pro, LiveCodeBench, SciCode, Vibe Code Bench, DeepSWE or AA Coding Index row exists, so real-repository bug-fixing ability is entirely unmeasured; the ModelDial task set and grading are not published and it reported no reference cost, so it cannot be treated as a peer of KingBench 3; hands-on reports still split sharply, with one MiniMax Code tester recording multiple broken interactive deliverables and another finding front-end quality competitive with Claude Opus 5.5 on design tasks. A partial-credit suite score is not a task-completion rate, and the ModelDial effort curve (65 at `high`, 50 at `xhigh`, 75 at `max`) means the score is specific to `max`.
- **Cost efficiency: 55/100.** Up from 35, and still scored well below what the numbers alone would imply. **What changed in this pass:** MiniMax has now published a *price of some kind* — Token Plan tiers at **$22 / $55 / $132 per month** against roughly **1.7B / 5.1B / 12.5B M3-equivalent tokens per month**, an implied **~$0.011–0.013 per 1M**. If that were a metered rate card it would sit at the very top of the methodology's inverse-pricing ladder. **Why it is still only 55:** it is a **quota, not a rate card** — rolling 5-hour and weekly windows, monthly reset with no carry-over, and no way to bill a single request against it; the model cannot be reached at all through pay-as-you-go, so the metered price of the sibling it shares a context ceiling with (**M3 at $0.30 / $1.20, doubling to $0.60 / $2.40 above 512K input**) is the best available proxy for what the vendor actually charges for metered access, and that is 4–27× the implied quota figure; and MiniMax's own Token Plan coverage footnote still omits M3.1, so even the plan's applicability to this specific model is contradicted in the vendor's own pages. This is still **not** a $0 = 100 case — the $0.00 rows aggregators publish for this ID mean *unpriced*, not free, and treating them as free would be the single most misleading number in this report. **What would move this score:** a published pay-as-you-go rate card for this model ID, or a named third-party gateway with a verifiable per-token price and date.
- **Overall Score: 67/100.** Unchanged. Half-up mean of the five quality dims (42 + 55 + 95 + 82 + 63) / 5 = 67.4 → **67**. Cost efficiency is excluded from the mean by design, so the large move on that dimension does not move the Overall; the coding move (+1) is exactly cancelled by rounding. **Best fit:** a fast, cheap-to-try 1M-context multimodal workhorse for prototyping, front-end and multimodal-understanding tasks inside an existing MiniMax subscription — **not** a model to put in front of a benchmark-driven selection today, because four of the five quality dimensions above still rest on two partial-credit application suites plus qualitative observation rather than on standard harness rows, and because on the 2026-10-17 check BenchLM still lists it at 0 of 639 benchmarks covered. Best used as a candidate for private A/B testing against a priced, published model, not as a primary production route on current evidence.
