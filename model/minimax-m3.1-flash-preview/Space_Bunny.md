## Model card

- **Name:** MiniMax M3.1 Flash Preview
- **Short description:** MiniMax's fast tier-preview text model for everyday agentic coding, launched 2026-09-27 inside MiniMax Code and the Token/M Plan subscription rather than as a pay-as-you-go API entry. It inherits MiniMax-M3's 1M context and native-multimodal stance, adds a five-rung `effort` thinking dial, and makes thinking mandatory (it cannot be switched off). **Variant note:** it is a sibling of MiniMax-M3, not a documented successor — no model card, no parameter sheet, no vendor benchmark table, and no per-token rate accompanied it.
- **Provider / access:** MiniMax Code (desktop + `mcode` CLI) and MiniMax **Token Plan / M Plan subscription key only** — not pay-as-you-go, not on third-party routers. The same model ID is served over MiniMax's Anthropic-compatible endpoint, its OpenAI-compatible Chat Completions endpoint, and its OpenAI Responses endpoint. Chat Completions *and* Responses are both available; `thinking.type=disabled` and `effort=none` return an error on this model.
- **Release / knowledge:** 2026-09-27 (MiniMax developer documentation model table, `@MiniMaxAgent` post on X, same day; reached MiniMax Code and Token Plan 2026-09-28). Knowledge cutoff not published.
- **IDs:** `MiniMax-M3.1-Flash-Preview` (MiniMax developer documentation and the MiniMax agent-tools preview guide, which names this exact value as the API model ID). No Zen Free ID, no third-party router ID.
- **Context window:** **1,000,000 tokens** — the same ceiling MiniMax-M3 carries (MiniMax developer documentation model table; MiniMax agent-tools preview guide). Max output is **not published** for M3.1-Flash-Preview on the vendor's own public model table; MiniMax Code test fixtures carry a 128,000-token output cap and a 512K default / 1M selectable context pair, which is repository evidence rather than a published API spec. No MRCR / RULER / GraphWalks retrieval measurement exists at any window length for this checkpoint.
- **Modalities:** text, image, and video in; text out, plus a separate `reasoning_content` thinking stream. Reasoning **yes, always on and non-disableable**. Five `effort` rungs — `low`, `medium`, `high`, `xhigh`, `max` — **defaulting to `max`**. Tool calling supported; JSON-mode support not separately documented for this ID. Hands-on testing confirms real image and video comprehension (hand-drawn fantasy-map terrain/landmark reconstruction, and a NASA NICER repair-training video transcribed into a timecoded service manual that separated dialogue-confirmed steps from unverifiable ones — woshipm.com, 2026-10-01).
- **Pricing (as of 2026-10-02):** **no per-token rate published anywhere.** The model is absent from MiniMax's pay-as-you-go price list; cost is a Token Plan / M Plan subscription divided by usage, which cannot be expressed as $/1M. A double-points campaign ran 2026-09-28 → 2026-10-07 (temporary, not a price). For contrast only, the sibling MiniMax-M3 lists at $0.30 / $1.20 per 1M input/output. Do not read the $0.00 figures aggregators show for this ID as "free" — they mean *unpriced*.
- **Architecture:** **conflicting public claims.** The MiniMax agent-tools preview guide describes a mixture-of-experts model with **428B total / ~23B active parameters**, sparse attention, and a native visual encoder. Independent trackers and launch coverage state the parameter count is undisclosed and treat 428B as a transcription of the parent M3's figure — a preview reusing M3's context ceiling and modality set is not thereby the same model, so the 428B/23B numbers are recorded here as **vendor-guide claims, not verified specification**. No weights: the MiniMaxAI organisation has no M3.1 checkpoint (its most recent public repositories remain MiniMax-Music3 and MiniMax-H3), so unlike MiniMax-M3 there is nothing to download.

### Normalized scores (1–100)

- **Tool use: 42/100.** Lowest-confidence dimension in this report. The model has no Terminal-Bench 2.1, Tau3, GDPval-AA, MCP-Atlas or AA-AutomationBench row anywhere, so the score cannot be anchored to the methodology's frontier or mid reference bands. It is set above the text-only floor only on documented capability and workflow evidence: tool calling is supported, MCode drives it through a Coder/Verifier agent triad, and independent testers observed it decomposing tasks, reaching for search and tools, then re-inspecting artifacts. **What caps it:** zero harness measurements means every standard agentic-tool anchor in `../../model-comparison.md` is unavailable, and the methodology's explicit rule is to note the gap and penalise rather than assume a mid-tier band.
- **Reasoning: 55/100.** No GPQA Diamond, HLE, LCR, CritPt or Intelligence Index value exists for this model, so this is the bottom of the methodology's mid band by default rather than a measurement. Justification for not going lower: a correct 10/10 on the KingBench 3 combinatorics task, and two documented multi-step analytical tasks where the model produced an explicit itemised reasoning chain (financial loss decomposition from filings; timecoded service manual from video that separated confirmed from unverifiable steps). **What caps it:** the entire band is unverified — a single correct maths answer is not a reasoning benchmark, and no knowledge-retention or long-context reasoning figure was ever published.
- **Context window: 95/100.** Tier mapping: ≥1M = 95–100, and the documented ceiling is exactly **1,000,000 tokens** (MiniMax developer documentation; MiniMax agent-tools preview guide). Not 100 because that tier requires **≥98% retrieval measured at 512K+**, and no MRCR / RULER / GraphWalks run exists at any length. Max output is unpublished on the vendor table (128K appears only in MiniMax Code repository fixtures), which is noted as a caveat rather than scored separately.
- **Multimodal: 82/100.** Methodology band: text + image + video in, text out = 75–90. Placement is in the upper half of that band on demonstrated comprehension rather than vendor claims: independent testing shows it reconstructing terrain, orientation and art style from a hand-drawn map and naming unmarked features, and turning a professional NASA repair-training video into a timecoded procedure manual while explicitly marking what the frames could not confirm; audio *understanding* was exercised (a music player that visualises volume, drum hits and accents and responds live to level changes) but there is **no audio input and no non-text output**, which is what the 90–100 band requires. Output side is deliberately narrower than the input side, per the same testers.
- **Coding: 62/100.** Anchored on the one real independent measurement: **KingBench 3 66.25% (53/80)**, a partial-credit interactive-application suite where the model leads on visual/3D deliverables and loses points precisely where interactive state and runtime correctness matter (elevator 3/10, archery 4/10) and where it trails GPT-6 Sol, SWE 2 and Opus 5.5 head-to-head. The methodology's mid reference (~65–75) assumes a LiveCodeBench figure in the 80s, which this model does not have. **What caps it:** no SWE-bench Verified/Pro, LiveCodeBench, SciCode, Vibe Code Bench, DeepSWE or AA Coding Index row exists, so real-repository bug-fixing ability is entirely unmeasured — and hands-on reports split sharply, with one MiniMax Code tester recording multiple broken interactive deliverables and another finding front-end quality competitive with Claude Opus 5.5 on design tasks. A partial-credit suite score is not a task-completion rate.
- **Cost efficiency: 35/100.** Scored **deliberately low and deliberately uncertain**: the model has **no published per-token price on any MiniMax page**, is absent from the pay-as-you-go list, and is reachable only through a Token Plan / M Plan subscription. The methodology's inverse-pricing ladder cannot be applied to an unpriced model, and subscription-quota economics are not convertible into $/1M. This is **not** a $0 = 100 case — the $0.00 rows aggregators publish for this ID mean *unpriced*, not free, and treating them as free would be the single most misleading number in this report. **What caps it:** the sibling MiniMax-M3 sits at $0.30 / $1.20 per 1M and the gateway figures floating around for M3.1 are unverified SEO content, so neither the cheap end nor the expensive end can be substantiated. What would move this score: a published rate card, or a verified gateway price with a named provider and date.
- **Overall Score: 67/100.** Half-up mean of the five quality dims (42 + 55 + 95 + 82 + 62) / 5 = 67.2 → **67**. **Best fit:** a fast, cheap-to-try 1M-context multimodal workhorse for prototyping, front-end and multimodal-understanding tasks inside an existing MiniMax subscription — **not** a model to put in front of a benchmark-driven selection today, because four of the five quality dimensions above rest on one partial-credit suite plus qualitative observation rather than on standard harness rows. Best used as a candidate for private A/B testing against a priced, published model, not as a primary production route on current evidence.
