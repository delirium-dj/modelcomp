## Model card

- **Name:** MiMo-V2.6-Distill-Qwen-9B (SFT checkpoint — no "Free" tier exists; see IDs below)
- **Short description:** Xiaomi MiMo's 9B dense agentic model, built by supervised fine-tuning `Qwen/Qwen3.5-9B` on MiMo-generated data across coding, general agent tasks, visual coding and cybersecurity, released as a starting point for open agentic-RL research. Not an alias of MiMo-V2.6-Pro/Flash: a separate 9B checkpoint on the Qwen3.5-9B trunk.
- **Provider / access:** **Self-host only.** Weights on Hugging Face `XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B`, served through SGLang (vendor quickstart: `sglang serve --model-path XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B --reasoning-parser mimo`) or vLLM, exposed as an OpenAI-compatible Chat Completions endpoint (`/v1/chat/completions`), reasoning returned in `reasoning_content`. No Responses API. No hosted route found anywhere: the HF card states plainly **"This model isn't deployed by any Inference Provider"** (2026-10-11); absent from OpenCode Zen `zen/v1/models`, absent from OpenRouter. Community GGUF ports exist (ggml-org, `maternion/mimo-v2.6:9b` on Ollama) but are weights distributions, not hosted APIs.
- **Release / knowledge:** HF repo created 2026-09-21T18:18:40Z, card last modified 2026-09-22T03:52:45Z; BenchmarkList and aggregators date the release **2026-09-22** — released with the MiMo-V2.6 series (the MiMo-V2.6 collection holds 5 items). **Knowledge cutoff not published** (the trunk Qwen3.5-9B cutoff is not inherited evidence and is not claimed here; apxml also lists Knowledge Cutoff "–").
- **IDs:** `XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B` (Hugging Face; the only verified identifier). Community quant IDs: `ggml-org/MiMo-V2.6-Distill-Qwen-9B-GGUF` and `maternion/mimo-v2.6:9b` (Ollama). **No Zen Free ID — and in fact no Zen ID at all**: this folder's `meta.json` id `opencode/mimo-v2.6-distill-qwen-9b` is not present in `https://opencode.ai/zen/v1/models`. Flagged, left unedited because no verified replacement API ID exists (the model is not served by anyone).
- **Context window:** **262,144 tokens (256K) native** — verified directly in the shipped `config.json` (`text_config.max_position_embeddings: 262144`), re-confirmed independently in the GGUF metadata ("Maximum trained context length 262,144 tokens", Local Model Watch) and in apxml's spec sheet (262K). **This contradicts `meta.json`, which said "128K total" and has been corrected.** Max output **not disclosed**: `generation_config.json` ships no `max_length`/`max_new_tokens`, and the vendor quickstart example merely passes `max_tokens=2048`.
- **Modalities:** **Text + image + video in; text out** — verified in `config.json`: `vision_config` (`model_type: qwen3_5_vision`, depth 27, hidden 1152, patch 16, `temporal_patch_size` 2, `out_hidden_size` 4096) plus `image_token_id` 248056, `video_token_id` 248057, `vision_start/end_token_id` 248053/248054, and `preprocessor_config.json` + `video_preprocessor_config.json` in the file list; HF `pipeline_tag: image-text-to-text`, `AutoModelForMultimodalLM`. Corroborated independently by the GGUF vision projector (`maternion` ships a 456M `clip` projector; the ggml-org repo ships a Q8_0 `mmproj`) and by Local Model Watch's own image tests. **Conflict:** apxml.com labels the modality **"Text"** — a spec-sheet error (its own MiMo-V2 family blurb mixes in MiMo-V2-Flash); the primary card plus independent GGUF packaging both prove vision. **Note the independent aggregators corroborate text + image only** (no third party documents the video path), so video stays config-verified hardware rather than externally validated. **This also contradicts `meta.json`, which said "Text in/out" and has been corrected.** **No audio**: there is no `audio_config` and no audio preprocessor, even though the MiMo v2.6 chat template emits `<|mimo_audio_start|>…<|mimo_audio_end|>` markers — those tokens are inert here, so do not treat this as omni-modal. Reasoning yes (`enable_thinking` via `chat_template_kwargs`, parsed by `--reasoning-parser mimo`); tool calls yes (`tool-use` tag, `<tool_call><function=…>` template; the community GGUF carries a fixed chat template for JSON tool-call arguments); structured/JSON via `tojson` tool rendering.
- **Pricing (as of 2026-10-11):** **$0 per token — MIT-licensed open weights, self-hosted.** No per-token price exists on any host because no host serves it (HF: "isn't deployed by any Inference Provider"; BenchmarkList: "Price not published"). `meta.json` "Standard pricing" was a placeholder and has been corrected. Cost is hardware, not tokens: 9,409,813,744 BF16 params (~17.5 GB stored weights per YouRunAI), reduced by community GGUF/MLX quantisations (Q4_K_M ≈ 5.6 GB, Q6_K ≈ 7.4 GB, Q8_0 ≈ 9.5 GB; llmrun.dev quotes ≈ 6.2 GB VRAM for Q4_K_M). Data-usage caveat: none — self-hosted inference leaks nothing.
- **Architecture:** 9.4B **dense** (no `num_experts`/`num_experts_per_tok` in `config.json`), BF16, MIT. 32 layers, hidden 4096, 16 heads / 4 KV heads, head_dim 256, vocab 248,320, one MTP layer, FFN intermediate 12,288 (SwiGLU). **Hybrid attention**: only 8 of 32 layers are `full_attention` (`full_attention_interval: 4`), the other 24 are `linear_attention` (apxml: "Linear Attention Yes, ratio 75.0%") with `linear_conv_kernel_dim: 4` and `mamba_ssm_dtype: float32` — this is what makes a 256K window tractable on one GPU. Interleaved M-RoPE (`mrope_section [11,11,10]`, `rope_theta 1e7`). Trained on a 77.4B-token SFT mixture (27.2B loss-bearing): code 23.2B / general 22.0B / visual 21.2B / cyber 11.0B.

Second pass adds BenchmarkList's independent rank (TB2.1 48th pct) and llm-bench's Agent Workflow 41.4 — both consistent with "below mid", neither lifting the number. What caps it: no Tau3 or GDPval at this ID, and frontier TB2.1 is ~88%+. **Unchanged.**
- **Reasoning: 52/100.** Provisional and the softest number in this report: **zero** reasoning-suite evidence (GPQA, HLE, LCR, CritPt, AA Index, Omniscience all absent — and the second pass confirmed no independent composite exists: BenchLM 404, LLM-Stats no page). Scored from lineage and weak proxies — Qwen3.5-9B trunk, 22.0B general SFT tokens — placed at the floor of the 55–65 mid band and then trimmed, because the only measurable reasoning-adjacent signals are low absolutes (OfficeQA 19.5%, JobBench 18.3%) and an independent knowledge-recall failure. Not a claim of frontier reasoning in either direction. **Unchanged.**
- **Context window: 74/100.** 262,144 tokens falls in the 200K–500K tier (65–84, 200K = 70). It sits above the 200K anchor because the number is now confirmed a third time (shipped `config.json`, GGUF metadata, apxml spec sheet) and the hybrid 8-full/24-linear attention pattern is deliberate long-context engineering rather than a marketing figure. Capped by zero retrieval evidence at length, and by undisclosed max output — a caveat per methodology, not a separate score. **Unchanged.**
- **Multimodal: 76/100.** Text + image + **video** in maps to the "+video/PDF in = 75–90" band, and the vision tower is real checkpoint hardware (`qwen3_5_vision`, depth 27, `temporal_patch_size: 2`, dedicated video preprocessor, shipped mmproj), not a tokenizer illusion — independently substantiated this pass by Local Model Watch reading a chart and a table correctly. It sits at the band floor because no multimodal benchmark is published, the only visual number is internal MiMo Visual Coding (mini) 64.0% vs base 61.7% (+2.3, the weakest delta on the card), output is text-only, audio tokens are inert, and independent aggregators corroborate only text + image (video stays config-only). **Unchanged.**
- **Coding: 66/100.** SWE-bench Verified 61.1%, SWE Pro 44.6% and MiMo Code (mini) 51.6% is a solid upper-mid profile for a 9.4B dense model, with SWE Pro +12.6 and cyber +25.6 as the real gains. Capped because SWE Verified barely moved (+1.1) and ranks only 46/50 (8th pct) on BenchmarkList, TB2.1 stays 37.1% against an 85%+ frontier bar, and LiveCodeBench / SciCode / DeepSWE are entirely absent. Independent llm-bench Code 66.6 corroborates the level but adds no new suite. **Unchanged.**
- **Cost efficiency: 92/100.** Methodology scores $0 = 100, and per-token cost truly is $0 under MIT with no rate limit and no training-data consent clause. Docked 8 because the evaluated tier has **no hosted route whatsoever** (HF card: not deployed by any Inference Provider; absent from Zen and OpenRouter; BenchmarkList: "Price not published"), so "free" is contingent on ~17.5 GB of BF16 VRAM or accepting quantisation drift — a self-hosting tax rather than a price. **Unchanged.**
- **Overall Score: 64.6/100.** Mean of the five quality dims: (55 + 52 + 74 + 76 + 66) / 5 = 323 / 5 = **64.6**; Cost excluded per RULES v4. Best fit: a local, MIT-licensed agentic **base checkpoint for RL experimentation** — you get the weights, a verified 256K window and a real video-capable vision tower at zero marginal cost, and you pay for it in vendor-only evidence and a below-mid agent ceiling. Not a frontier coder; for hosted agentic coding this repo's MiMo V2.6 Flash / Pro entries remain the stronger picks.
