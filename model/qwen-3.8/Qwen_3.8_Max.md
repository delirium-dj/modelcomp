## Model card

- **Name:** Qwen 3.8 (Qwen3.8-27B)
- **Short description:** Alibaba's **dense 27B open-weight multimodal model** (Apache 2.0) and the *deployable* half of the Qwen3.8 generation — roughly a hundredth the size of the 2.4T-MoE Qwen3.8-Max, but the checkpoint most teams can actually run on a single high-end GPU. A **native vision-language model** (text + image + video in) built on the Qwen 3.5 hybrid-attention backbone, positioned for **local, long-horizon agent and coding work**. On Alibaba's own (disclosed-harness) table it beats Claude Opus 4.6 Max on SWE-bench Pro, OSWorld and MathVision, but its only independent signal — Artificial Analysis Intelligence Index **34** — is modest in absolute terms and its widest margins sit on modified or in-house benchmarks.
- **Provider / access:** Open weights on Hugging Face (`Qwen/Qwen3.8-27B`, `Qwen/Qwen3.8-27B-FP8`) and ModelScope under **Apache 2.0** (commercial use permitted, no revenue share — confirmed in the license file, unlike Qwen3.8-Max's bespoke license). No first-party Alibaba hosted price at launch (Qwen Cloud was "coming soon"/404 on 2026-08-17); served via OpenRouter, DeepInfra, Alibaba Cloud/Model Studio, CoreWeave, Parasail, Multiverse, Crusoe and others (8+ tracked providers). Self-host via vLLM (Ascend NPU), SGLang, HF Transformers ≥5.8.0, llama.cpp/GGUF, Ollama.
- **Release / knowledge:** Released **2026-08-14** (HF repo created Aug 13; weights for Max landed Aug 12). Knowledge cutoff not disclosed in the sources reviewed.
- **IDs:** `opencode/qwen-3.8`; weights `Qwen/Qwen3.8-27B` (+ `-FP8`).
- **Context window:** **262,144 tokens native** (~384 A4 pages), extendable to **1,000,000 via YaRN** — with Alibaba's own model-card caveat that common OSS frameworks apply YaRN *statically* and "can lose accuracy on shorter inputs," so the 1M is an extension, not a native, guarantee.
- **Modalities:** **text + image + video in → text out** (native VLM — full vision encoder, `language_model_only=false`; *not* the text-only Max checkpoint early coverage described). **No audio.** Reasoning model with flexible thinking control (effort levels **low / medium / xhigh**); function calling, structured output and prompt caching supported on host providers.
- **Pricing (as of 2026-10-23):** self-host **$0** (Apache 2.0). Hosted varies widely by provider: DeepInfra **$0.15 in / $1.875 out** (promo; list $0.20/$2.50, cache $0.038); OpenRouter **~$0.45 / $3.20** (route-dependent; a free tier exists); Alibaba Cloud/Model Studio **$0.42–$0.50 / $3.00**. Cost per AA Intelligence-Index task ≈ **$0.82**; ~$56 GB VRAM at BF16, ~28 GB FP8, ~14–16 GB 4-bit (24 GB+ GPU / RTX 4090 recommended).
- **Architecture:** **Dense** 27,781,427,952 params (27.78B incl. vision encoder; "27B" is the LM count) — *not* MoE, all params active. 64 layers, hidden dim 5,120, **hybrid attention: 48 Gated DeltaNet linear-attention layers + 16 full gated-attention layers** (3 linear : 1 full, `full_attention_interval: 4`); built-in **multi-token-prediction (MTP)** draft head for speculative decoding; shares the hybrid backbone of the Qwen3.8-2.4T-A95B flagship. FP8 variant uses fine-grained block-128 quantization ("nearly identical" per Alibaba).

### Raw benchmarks found

- **SWE-bench Pro: 61.7%** — beats Claude Opus 4.6 Max (53.4%), Qwen3.7-Plus (57.6%), Muse Glimmer-30B (51.2%)
- **LiveCodeBench v6: 90.3%** — leads Opus 4.6 Max (88.8%)
- **Terminal-Bench 2.1: 73.0%** — behind Opus 4.6 Max (78.2%), well ahead of Muse Glimmer-30B (51.7%); up from Qwen3.6-27B's 63.4%
- **DeepSWE 1.1: 42.2%** — the largest generational jump (vs Qwen3.6-27B's 13.3%), but modest in absolute frontier terms
- **IFBench (instruction following): 79.5%** — leads Opus 4.6 Max (62.5%) and Muse Glimmer-30B (77.0%)
- **SWE-MM: 38.6%** (up from 25.7%)
- QwenSWEBench **79.0%** (vs Opus 4.6 Max 63.8%) and CoWorkBench **70.7%** (vs 68.2%) — **in-house benchmarks**, one-line descriptions, no published task list/sample size → not independently checkable

Reasoning / knowledge:

- **GPQA Diamond: 89.2%** — below Opus 4.6 Max (91.3%), above Muse Glimmer-30B (83.5%)
- **HLE (Humanity's Last Exam): 30.8%** — clearly below Opus 4.6 Max (40.0%); a real weakness
- **Artificial Analysis Intelligence Index: 34** (xhigh) — the sole independent signal; modest in absolute terms (DeepSeek V4.1 Flash ≈ 39–40, MiMo-V2.6-Pro 46.32) but **strong for its open-weight size class** (median 8). Very verbose: ~200M output tokens in the Index eval (median 76M). **[2026-11-02: AA's current v5.0 read is 20 (class median 13, still #1/62 among open-weight small models); the "34 / median 8" figure is v4.x-vintage and not convertible to v5.0 — a basket rebase, not a regression. Speed re-measured 41.1 tok/s (#55/62, notably slow), cost $3.53/task, verbosity 130M tokens.]**

Multimodal (vision; Alibaba's table):

- **MathVision: 90.0%** — far above Opus 4.6 Max (65.5%)
- **OSWorld-Verified: 84.3%** — well above Opus 4.6 Max (72.7%); up from Qwen3.6-27B's 63.9%
- **AndroidWorld: 81.9%** — well above Opus 4.6 Max (62.0%)
- Native image + video input (no audio); no MMMU/MMMU-Pro figure published in the sources reviewed **[2026-11-02: AA now publishes MMMU-Pro 76.3 — mid-70s complex visual reasoning, below the 84 the draft inferred from vendor figures; doc/extract cells are stronger (ExtractBench 89.75, OmniDocBench 91.1, CharXiv 90.2).]**

> Provenance: The benchmark table is **Alibaba vendor-run**, but unusually transparent — the harness and sampling (Claude Code, temp 1.0, top_p 0.95, 256K) are disclosed, which is more than most vendor comparisons offer. Two material caveats: (1) Alibaba states it **"corrected problematic tasks" in SWE-bench Pro and re-evaluated all baselines on the amended set**, and **fixed ground-truth annotations in MathVision and CharXiv** — so those scores are **not directly comparable** to numbers on the unmodified benchmarks; (2) its widest margins (QwenSWEBench, CoWorkBench) are **in-house benchmarks with no published task list or sample size**. The only neutral signal is **Artificial Analysis Index 34 (xhigh)** — modest absolutely, strong for a 27B dense open-weight model. Speed is provider-dependent (DeepInfra ~29 t/s, Alibaba ~44 t/s, Multiverse/Crusoe ~191 t/s; median ~93 t/s) and verbosity (~200M eval tokens) inflates real cost. Per methodology, vendor figures are treated as an upper bound and discounted against neutral harnesses; no benchmark was invented. Specs were independently verified against DeepInfra/Artificial-Analysis and DataNorth coverage rather than inherited from the folder's scaffolded `meta.json`.

> **Independent (added 2026-11-02, closed-benchmark cross-check):** Artificial Analysis + BenchLM (**#80/1004, overall 54.26, 75/724 coverage** — partial, so BenchLM's composite is conservative) + Vals AI + LlamaIndex. **Intelligence:** AA v5.0 Index **20** (rebased from the draft's v4.x 34; still #1/62 in its open-weight size class, median 13), **AA-HLE 33.9**, **CritPt 5.4**, **AA-GPQA-D 90.5**, **GPQA-D (Vals) 88.9**, **MMLU-Pro (Vals) 84.3**; **AA-Omniscience Accuracy 17.3 / hallucination 28.6 / net index −6.4** (a fabrication-reliability flag). **Agentic/tool:** **Vals Terminal-Bench 2.1 58.4** (vendor 73.0 does not replicate; AA leaderboard 79.8), **AA Terminal-Bench 4.0 5.6** (long-horizon), **AA Agentic Index 46.5**, GDPval-AA 45.9, AA AutomationBench 48.2, **AA Cyber Index 12.7, CWE-Bench-AA 26.7, CyberGym-E2E-AA 0.0, DeepsecBench-AA 11.5** (security near-nil). **Coding:** **SWE-bench (Vals) 86.0**, **LiveCodeBench (Vals) 84.0**, AA Coding Index 68.1, **AA-SciCode 46.6**, NL2Repo 42.3, DeepSWE 42.2. **Multimodal:** **AA-MMMU-Pro 76.3** (mid-70s complex visual reasoning — the figure the draft lacked), ExtractBench (LlamaIndex) 89.75, ParseBench 69.72. **Long context:** **AA-LCR 82.0** (the recall score the draft flagged as unpublished). **Quarantined (not imported):** the vendor model-card set (SWE-bench Pro 61.7 *amended*, LiveCodeBench v6 90.3, OSWorld-Verified 84.3, AndroidWorld 81.9, MathVision 90.0 *annotation-corrected*, IFBench 79.5, in-house QwenSWEBench 79.0 / CoWorkBench 70.7) is Alibaba-run; the Perplexity **pplx-decider-v1-27b** decision-panel rows on BenchLM belong to a different model.

### Normalized scores (1–100)

- **Tool use: 80/100.** Genuinely strong vendor computer-use for a 27B dense model — OSWorld-Verified 84.3% and AndroidWorld 81.9% both above Claude Opus 4.6 Max — plus function calling, structured output, prompt caching and flexible thinking control. **Trimmed 83 → 80** on the independent pass: the vendor **Terminal-Bench 2.1 73.0 does not replicate (Vals 58.4; AA's own leaderboard 79.8 — the true band straddles)**, and the harder set is weak-to-near-zero — **AA Terminal-Bench 4.0 5.6**, **AA Cyber Index 12.7, CyberGym-E2E-AA 0.0, CWE-Bench-AA 26.7**, AA Agentic Index 46.5, GDPval-AA 45.9. Everything remains vendor-run; the OSWorld/AndroidWorld margins are on Alibaba's own harness and are not independently re-measured.
- **Reasoning: 78/100.** Mixed and now capped lower. **Trimmed 80 → 78** on independent evidence: **AA-GPQA-D 90.5 / Vals 88.9** and **MMLU-Pro (Vals) 84.3** are solid, and IFBench 79.5 leads Opus — but **CritPt 5.4** (research physics), **AA-HLE 33.9** (weak, matching the vendor 30.8) and a very low **AA-Omniscience 17.3% accuracy (net index −6.4)** put a firm ceiling on depth and reliability. The neutral anchor also rebased: the draft's AA Index 34 (v4.x) is now **v5.0 Index 20** — a basket rebase, not a regression, still #1/62 in class — but it does not support a lift.
- **Context window: 86/100.** A large **262,144-token native** window is a real strength for a self-hostable model. **Lifted 85 → 86:** the draft discounted long-context partly because **"no MRCR-style long-context recall benchmark is published"** — the independent **AA-LCR 82.0** now supplies exactly that recall score, closing the gap (a provenance lift, not a capability change). Still below native-1M leaders (88–93) because the headline **1M is a YaRN extension** Alibaba warns "can lose accuracy on shorter inputs" under static OSS runtimes, and **AA spec independently confirms the native window at 256K**.
- **Multimodal: 82/100.** **Trimmed 84 → 82 with the rationale corrected.** The draft reached 84 without any MMMU figure, leaning on vendor MathVision 90.0 / OSWorld 84.3; the independent **AA-MMMU-Pro 76.3** shows complex visual reasoning is only **mid-70s**, below the frontier. Held at 82 (not lower) by genuinely strong document/grounding/extract cells — **ExtractBench 89.75, OmniDocBench 91.1, CharXiv 90.2, RealWorldQA 85.9** — and real modality breadth: **native text + image + video (AA spec confirms; no audio)**.
- **Coding: 84/100.** **Trimmed 85 → 84.** The standout dimension for its class and the best-corroborated by independent data: **Vals SWE-bench 86.0 and LiveCodeBench 84.0** broadly validate Alibaba's vendor coding set (unlike Terminal-Bench, which did not replicate), and AA Coding Index 68.1 is respectable. Held below the high-80s because the headline **SWE-bench Pro 61.7 is on Alibaba's amended task set** (not comparable to the unmodified benchmark), and the long-horizon/repo deficits are independently confirmed — **AA-SciCode 46.6, NL2Repo 42.3, DeepSWE 42.2, Terminal-Bench 4.0 5.6** — while 61.7% still trails the true frontier (Opus 4.7 64.3%, Fable 5 80.0%).
- **Cost efficiency: 92/100.** **Holds.** Exceptional deployability value — **Apache 2.0 open weights ($0 self-host)** on a single 24 GB GPU, FP8 variant, hosted from ~$0.15/$1.875 (DeepInfra). Tempered below the MIT Flash models (96–97) because the first-party served price is **$0.50/$3.00 (AA: expensive vs size-class median $0.12/$0.30; ~$3.53 per Index task)** and the model is **very verbose (AA 130M Index tokens, #6/6) and slow (41.1 tok/s, #55/62)**, so real-world token spend exceeds the sticker input rate. Scored but **not** counted in the Overall per methodology.
- **Overall Score: 82/100.** Mean of Tool 80 + Reasoning 78 + Context 86 + Multimodal 82 + Coding 84 = 410 / 5 = 82.0 → **82**. Best fit: **the self-hoster's dense sweet spot** — a single-GPU, Apache-2.0, native-vision agent/coding engine for local long-horizon tool calling, visual/document extraction and repo work where data sovereignty and $0 weights matter and frontier-tier depth is not required; escalate the hardest reasoning/security/long-horizon tasks to Qwen3.8-Max/Plus or a closed frontier model. Independent read: my 82 sits **below the queue's curated 88.6** because I discount the vendor-only table (amended SWE-bench Pro/MathVision, in-house QwenSWEBench/CoWorkBench, non-replicating Terminal-Bench), weight the rebased independent AA Index (v5.0 = 20) and weak independent agentic/security cells, and treat the 1M window as a caveated YaRN extension — landing at/below the larger open-weight DeepSeek V4.1 Flash (83), consistent with its smaller size and lower independent index.
