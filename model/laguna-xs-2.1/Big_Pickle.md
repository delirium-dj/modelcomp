## Model card

- **Name:** Laguna XS 2.1 — Poolside's lightest and fastest agentic coding model, small enough to run on-device
- **Short description:** A **33B-total / 3B-active open-weights MoE** built by Poolside specifically for **agentic coding and long-horizon work on a local machine**, trained in-house on **15T tokens** and reinforced inside Poolside's own `pool` agent harness. It reaches **70.9% SWE-bench Verified** and **63.1% SWE-bench Multilingual** from only 3B active parameters, ships under the fully permissive **OpenMDW-1.1** license, runs on a Mac with 36 GB of RAM, and costs **$0.06 in / $0.12 out** hosted. It is a **coding specialist with essentially no published reasoning or long-context evaluation** — no GPQA, HLE, MMLU, AIME, SciCode, LiveCodeBench, Tau3, MCP-Atlas, Toolathlon, LCR, RULER or MRCR score exists for it anywhere.
- **Provider / access:** **OpenCode Zen `opencode/laguna-xs-2.1`** (per this folder's `meta.json`). Poolside first-party `https://inference.poolside.ai/v1` ID **`poolside/laguna-xs-2.1`** (OpenAI-compatible Chat Completions). OpenRouter **`poolside/laguna-xs-2.1`**. NVIDIA NIM (`build.nvidia.com/poolside/laguna-xs-2-1`). Local: vLLM ≥ 0.21.0, SGLang, TensorRT-LLM ≥ 1.3.0rc16, Transformers ≥ 5.7.0, llama.cpp (upstream PR #25165), Ollama (`ollama run laguna-xs-2.1`, default Q4_K_M imatrix), Atomic Chat, and `ollama` + MLX on Apple silicon. **Important ID caveat:** models.dev carries **no `opencode/laguna-xs-2.1` entry at all** — its `poolside` provider lists `poolside/laguna-xs-2.1` at **$0/$0**, and the `opencode` provider only has the **deprecated** `opencode/laguna-s-2.1-free` (256,000 ctx / 32,000 out) plus `opencode/laguna-xs.2` and `opencode/laguna-m.1` entries carrying implausible `32768` context caps and `tool_call: false`. This folder's `meta.json` is therefore stale on both the ID and the price.
- **Release / knowledge:** **2026-07-02** (Poolside blog "Introducing Laguna XS 2.1"; benchmarks dated 2 July 2026; BenchmarkList release date Jul 2 2026). An upgraded version of **Laguna XS.2** (2026-04-28, same architecture), which **Poolside sunset from its own API one week after this launch** and moved to Baseten's Model Library. **Knowledge cutoff not published** on the card, blog, NVIDIA card, or any tracker.
- **IDs:** `opencode/laguna-xs-2.1` (this folder's ID; not present in the models.dev catalog), `poolside/laguna-xs-2.1` (Poolside API, listed at $0/$0), `poolside/laguna-s-2.1` / `poolside/laguna-s-2.1-free` (OpenRouter free + paid), `poolside/Laguna-XS-2.1` (Hugging Face weights), `poolside/Laguna-XS-2.1-GGUF`, `-FP8`, `-NVFP4`, `-INT4`, `poolside/Laguna-XS-2.1-DFlash` (open-weight speculator), `laguna-xs-2.1` (Ollama), `laguna-xs.2` (superseded). **A free ID does exist** — Poolside offers free and paid endpoints, and OpenRouter lists a `:free` variant — but it is explicitly **"for a limited time"**.
- **Context window:** **262,144 tokens (256K)**, max output **32,768** — verified on the HF model card ("Context window: 262,144 tokens"), the NVIDIA NIM card, models.dev (`limit: {context: 262144, output: 32768}` on the `poolside` entry), OpenRouter and Known Good (262,144 / 32,768). Poolside states it serves the model at 256K on its API and through OpenRouter, and **all four official benchmarks were run at a 256K context length**, so the window is exercised rather than merely advertised. Max output of 32K is below the methodology's 64K comfort line — a noted caveat, not a separate deduction.
- **Modalities:** **text-to-text only.** Reasoning: **native and on by default**, with **interleaved thinking between tool calls** and *preserved thinking* — the card is explicit that reasoning "may not be generated in follow-up steps if prior thinking blocks are dropped … when messages are reconstructed over multiple steps", so a client that strips `reasoning_content` degrades the model. Thinking can be turned off per request via `enable_thinking: false`. Tool calls supported (`poolside_v1` tool parser and reasoning parser in vLLM; `laguna` in TRT-LLM). **No structured-output / JSON-schema mode** (models.dev `structured_output: false`). No image, audio, or video.
- **Pricing (as of 2026-09-25):** **the cheapest hosted model in this comparison**, and the number depends on which listing you read. OpenRouter's live rate: **$0.06 in / $0.12 out per 1M, $0.03 cache read** (a 50% discount), blending to **$0.07/M** — cheaper than 82% of the 191 open-weight models olud.ai tracks, and $0.08/M on AA's 3:1 convention. Poolside's launch blog quotes **$0.10 / $0.20 / $0.05** "matched to XS.2". models.dev lists the `poolside/laguna-xs-2.1` entry at **$0/$0**. A **free endpoint exists** on both Poolside and OpenRouter, explicitly **time-limited** — the usual rate-limit and data-usage caveats apply. Self-hosting the OpenMDW-1.1 weights is free outright: 4-bit GGUF is ~20.3 GB, NVFP4 ~22 GB.
- **Architecture:** **33B total / 3B activated per token**, Mixture-of-Experts, **second-generation Laguna architecture** (`laguna` / `laguna-xs-2.1` architecture tags, BF16, `trust_remote_code` for Transformers). **40 layers — 10 global attention + 30 sliding-window attention (3:1 SWA:global)**, using **sigmoid gating with per-layer rotary scales**; **256 routed experts + 1 shared expert**, ~3M params per expert, 8 experts firing per token; **sliding window 512 tokens**; **KV cache quantized to FP8**. **Muon optimizer.** Vocabulary 100,352. Trained in-house on **15T tokens** through pre-training, post-training and **reinforcement learning — with async off-policy agent RL inside `pool`, Poolside's own agent harness** ("These models learned to code inside `pool`"); method details in the Laguna M.1/XS.2 technical report (data automixing + async off-policy agent RL). An independent architectural breakdown puts active parameters at **~2.2B** (≈1.0B of firing experts + ~1.2B always-on dense attention/embedding/shared stack). **OpenMDW-1.1** — "fully permissive. Use it, modify it, and build commercial products on it. No permission required," the NVIDIA/Linux Foundation standard Poolside adopted specifically to cut licensing friction. **DFlash speculator** open-weighted alongside each checkpoint: a 5-layer Llama-style draft model proposing **up to 7 tokens per step at ~70% per-position acceptance** on coding tasks, which **doubles achieved tok/s**. 18,391 HF downloads last month.

### Raw benchmarks found

> All four official numbers are the **Laguna XS 2.1** row of Poolside's model card and blog, benchmarked **2026-07-02** against XS.2, Qwen3.6-35B-A3B, North Mini Code (Cohere), MAI-Code-1-Flash, gpt-oss-120B, Claude Haiku 4.5 and GPT-5.4 Nano. Poolside states it used **the highest publicly-referenced score** for every comparison model. Harness: **Laude Institute's Harbor Framework with Poolside's `pool` agent harness, max 500 steps, sandboxed**, temperature 1.0, top_k 20, top_p 1, **thinking enabled, 256K context**; 8 GB RAM / 2 CPUs per task except Terminal-Bench 2.0 at 48 GB / 32 CPUs. Some task images and verifiers were patched for infrastructure reliability, and Poolside ran a post-hoc reward-hack judge plus manual review that "did not find significant reward hacking."

Agent / tool use:

- Terminal-Bench 2.0: **37.5%** (official; mean pass@1 over **5 attempts**, 48 GB RAM / 32 CPUs) — vs Qwen3.6-35B-A3B **51.5%**, MAI-Code-1-Flash 54.8%, GPT-5.4 Nano 46.3%, North Mini Code 36.0%, XS.2 35.7%, Claude Haiku 4.5 29.8%, gpt-oss-120B 18.7%. **Beats its own predecessor but loses to every other coding model Poolside listed except Claude Haiku 4.5**
- Terminal-Bench **2.1**: **no verified public score found.** Poolside published only the 2.0 row — the version that fixes 28 of 89 tasks and on which most agent-model pairs gain 2–12 points
- Tau3-Banking / Tau2-Bench / GDPval-AA / AutomationBench / OSWorld / Agents' Last Exam / MCP-Atlas / Toolathlon / Claw-Eval / ClawProBench / SWE Atlas Codebase QnA: **no verified public score found**
- Independent harness data exists only for the **predecessor**: Vals AI's bash-only mini-swe-agent run lists **Laguna XS.2** at 79% / 61% / 17% / 0% across the four SWE-bench Verified difficulty bands (and **Laguna M.1** at 80/61/24/0). **XS 2.1 itself is absent from that leaderboard**

Reasoning / knowledge:

- GPQA Diamond / HLE / MMLU / MMLU-Pro / AIME / HMMT / IMO / Math / SimpleQA / CritPt / Omniscience / LCR / MLCR / IFBench / AA-Omniscience: **no verified public score found — Artificial Analysis has never benchmarked this model** (olud.ai: "Artificial Analysis measures 273 of the 383 models tracked here — this one is not yet covered"). The Known Good tracker likewise declines to score it: "does not yet carry a Known Good Index score — the index needs at least one science, one mathematics and one coding result." lm market cap records **Raw Quality 0/100** (no benchmarks indexed) with **Capabilities 50/100**
- This is the single largest evidence gap in the model: a model whose entire published evaluation surface is four coding benchmarks and zero knowledge, maths or science evals
- One third-party composite exists: **local.ai scores the Q4_K_M variation 59/100 (#87 of 232)** and the NVFP4+DFlash variation 55, on a "fastest hardware: NVIDIA RTX PRO 6000 Blackwell 96GB" setup. That composite is built from the same four coding benchmarks, so it is **not independent reasoning evidence**

Coding:

- SWE-bench Verified: **70.9%** (official; mean pass@1 over **4 attempts**) — vs Qwen3.6-35B-A3B 73.4%, Claude Haiku 4.5 73.3%, MAI-Code-1-Flash 71.6%, XS.2 69.9%, North Mini Code 67.6%. **Reproduced as an HF eval result at 70.9**
- SWE-bench Multilingual: **63.1%** (official; 4 attempts) — the release's headline improvement, **up 5.4 points from XS.2's 57.7%**; vs Qwen3.6-35B-A3B 67.2%, MAI-Code-1-Flash 65.5%
- SWE-bench Pro (Public Dataset): **47.6%** (official; 2 attempts) — vs Qwen3.6-35B-A3B 49.5%, MAI-Code-1-Flash 51.2%, GPT-5.4 Nano 52.4%, North Mini Code 40.2%, Claude Haiku 4.5 39.5%, gpt-oss-120B 16.2%. **Reproduced as an HF eval result at 47.6**
- Terminal-Bench 2.0: **37.5%** (official; 5 attempts). **Reproduced as an HF eval result at 37.5**
- DeepSWE / LiveCodeBench / SciCode / Vibe Code Bench / FrontierCode / FrontierSWE / SWE-Atlas: **no verified public score found**
- Efficiency framing from Poolside: this is a **33B-A3B** model beating or matching models 4–35× its size (MAI-Code-1-Flash at 137B-A5B, gpt-oss-120B at 120B-A5B) on the coding suite

Long context:

- **No long-context retrieval benchmark exists for this model** — no MRCR, RULER, GraphWalks, LongBench or needle test at any window length. The only long-context-adjacent facts are that the 256K window is the served limit and that all four official benchmarks **ran at a 256K context length**
- Architecture is genuinely long-context-friendly for a 33B: 30 of 40 layers are **512-token sliding-window** attention with **FP8-quantized KV cache**, which is why a full 262,144-token window costs the local community about **1 GiB of KV with zero decode-speed penalty** at 4-bit
- Verified local throughput: **DGX Spark (88 GB, 110 GB unified)** at 22 GB / 20% of usable memory; **NVFP4 + DFlash 133.6 tok/s single-stream** on code, 3.2× the no-draft baseline, with the full 256K window still fitting 1.5× over; **Q4_K_M GGUF 90.4 tok/s** with no draft → **122.7 tok/s** with the DFlash speculator. Hosted: **137.9 tok/s (#21 of 338)** with **0.3s TTFT** on OpenRouter's Poolside endpoint

### Normalized scores (1–100)

- **Tool use: 56/100.** At the floor of the methodology's mid band (50–70). The one agentic measure that exists, **Terminal-Bench 2.0 37.5%**, sits *below* the mid band's "TB2.1 ~45–60%" trigger — and it is on the older, easier-in-comparison benchmark version, so 2.1 would likely read lower still. Everything else is absent: **no Tau3, no GDPval-AA, no MCP-Atlas, no Toolathlon, no AutomationBench, no Claw-Eval**. Held at 56 rather than the bottom of the band because the model is *genuinely* built as an agent — RL inside `pool`, interleaved thinking between tool calls, preserved-thinking designed for multi-step loops, a purpose-built `poolside_v1` tool parser, and launch-day support in every major serving framework — and because the model card's own caveat that the benchmarks used **patched task images** is a small discount, not a disqualification.
- **Reasoning: 55/100.** The methodology's mid band (GPQA 60–80%, HLE <10%, LCR <40%, Index 20–35 → **55–65**) is the only defensible placement, and this model sits at its **exact floor with no data at all**: zero GPQA, HLE, MMLU, AIME, HMMT, IMO, CritPt, Omniscience, LCR or SciCode scores exist, Artificial Analysis has explicitly never run it, and the Known Good tracker refuses to composite it for want of any science, maths or knowledge result. Not scored lower, because a 33B model RL-trained for long-horizon agentic work with interleaved thinking is not obviously floor-tier on general reasoning — there is simply no measurement, and a missing measurement is not evidence of weakness. Not scored higher, because nothing supports the mid band's upper half either.
- **Context window: 72/100.** **262,144 tokens** lands in the methodology's **200K–500K band (65–84)**, above the 200K = 70 anchor, with a **32,768 max output** noted as the band's stated caveat. Placed modestly above the anchor rather than mid-band because the window is real and exercised — Poolside serves it and ran **all four benchmarks at 256K context** — and because the SWA-heavy architecture (30 of 40 layers at a 512-token window) plus FP8 KV cache keeps the full window practical: the community measures the complete 262,144-token window at ~1 GiB of KV and **zero decode-speed penalty** at 4-bit. Held well below the 500K–1M band because **no retrieval benchmark exists at any depth** — no RULER, no MRCR, no needle test — so nothing establishes that 256K of window is actually usable recall.
- **Multimodal: 15/100.** **Text-to-text** — the HF card's own modality line, and models.dev records `input: ["text"], output: ["text"]`. The methodology's flat text-only value. Nothing to negotiate: there is no vision tower, no audio path, and no sibling in the XS class to swap to.
- **Coding: 75/100.** The top of the methodology's mid band (65–75), and the one dimension this model genuinely earns. **SWE-bench Verified 70.9%** and **SWE-bench Multilingual 63.1%** are solid mid-tier repo-fixing numbers *from 3B active parameters*, both independently reproduced in the HF eval results, with **SWE-bench Pro 47.6%** clearing the 40% trigger. Capped at 75 because **Terminal-Bench 2.0 37.5%** is the one weak row, and because it **loses to Qwen3.6-35B-A3B on all four of Poolside's own benchmarks** (73.4 / 67.2 / 49.5 / 51.5) — a near-identical size-class MoE beating it across the board under an identical harness is the single most relevant comparison, and Poolside printed it. There is also **no DeepSWE, no LiveCodeBench, no SciCode and no Vibe Code Bench** number, so the dimension has no frontier-anchor evidence at all.
- **Cost efficiency: 99/100.** Effectively at the top of the scale. OpenRouter's live rate is **$0.06 in / $0.12 out with $0.03 cache read**, blending to **$0.07/M** — below the methodology's ~$0.10/$0.20 = 97–99 anchor and cheaper than 82% of tracked open-weight models — and models.dev lists Poolside's own endpoint at **$0/$0**, with a free OpenRouter variant too. Self-hosting is ~20–23 GB at 4-bit under a fully permissive license. Held at 99 rather than 100 on two honesty grounds: the free endpoints are explicitly **time-limited** with the usual data-usage caveats, and the scored ID is genuinely ambiguous — models.dev has **no `opencode/laguna-xs-2.1` entry**, Poolside's blog says $0.10/$0.20 while OpenRouter says $0.06/$0.12, and the only `opencode` Laguna entries in the catalog are a **deprecated** `laguna-s-2.1-free` and two stale 32K-context placeholders.
- **Overall Score: 55/100.** (56 + 55 + 72 + 15 + 75) / 5 = 54.6 → 55. Best fit: **on-device or self-hosted agentic coding where the code is the whole job** — 70.9% SWE-bench Verified from 3B active parameters, a Mac-with-36-GB deployment story, a fully permissive OpenMDW-1.1 license, DFlash speculative decoding that doubles local throughput, and the cheapest hosted tokens in this comparison. It is the small sibling of **Laguna S 2.1** (118B-A8B, 1M context, released 2026-07-21, also OpenMDW-1.1, 70.2% TB2.1 / 78.5% SWE-Multilingual / 59.4% SWE-Pro / 40.4% DeepSWE) — if you can host 118B, that is the strictly better buy. Two hard limits: **there is no published evidence for its reasoning or its long-context recall**, so it should not be trusted for knowledge work or for 256K-token retrieval, and its **32K max output** and Terminal-Bench 2.0 37.5% mean it is a fast local executor, not the planner.
