> **Verdict:** GPT-5.3-Codex-Spark is OpenAI's **first "real-time" coding model** — a **distinct, smaller, vision-stripped, pruned/distilled checkpoint of GPT-5.3-Codex**, released **12 February 2026** as a research preview and served on **Cerebras Wafer-Scale Engine 3 (WSE-3)** at **>1,000 tokens/s** (the first OpenAI×Cerebras collaboration). The entire product is a **latency play, not an intelligence play**: to fit the WSE-3's fast-but-small on-chip SRAM, OpenAI **removed vision (text-only)** and shrank the model, so it is **128K context / 32K max output**, aimed at keeping the developer "in the flow" for precise inline edits, boilerplate, regex, unit tests, syntax fixes and UI/styling iteration. Its own numbers are respectable for a fast variant — **Terminal-Bench 2.0 ~58.4%** and **SWE-Bench Pro 51.5%**, "more capable than GPT-5.1-Codex-mini… in a fraction of the time" — **but the caveats dominate:** (1) the **~77.3% Terminal-Bench in circulation is standard GPT-5.3-Codex's, NOT Spark's** (a ~19-pt accuracy drop; meta + remio both flag this); (2) the headline **"15× faster" is disputed** — an independent recalculation from OpenAI's *own* SWE-Bench-Pro chart points found **~1.37× at comparable accuracy** (the "15×" appears only in the page's `<meta>` tag / RSS, not the visible text); (3) **no reasoning benchmarks were published**, and independent hands-on reports describe a **"significant intelligence tax"** — "a highly advanced autocomplete rather than a pair programmer," weak on multi-file synthesis and complex logic; (4) **no public first-party price** (ChatGPT-Pro preview + design-partner API only; the third-party OpenCode-Zen route is a pricey **$1.75/$14.00**), and it was **retired 2026-09-14**. Scored Overall **59** (div **−6.2** vs curated 65.2) — a genuinely novel fast-inference artifact whose reduced reasoning, text-only modality, disputed speed claim, weak 128K depth, and retired/no-price status pull the quality-dimension mean well below the curated value.

## Model card

- **Name:** GPT-5.3 Codex Spark (GPT-5.3-Codex-Spark)
- **Short description:** OpenAI's first real-time coding model — a smaller, **vision-stripped, pruned/distilled** checkpoint of GPT-5.3-Codex served on **Cerebras WSE-3** at **>1,000 tok/s** for latency-sensitive, iterative "grunt work" (inline edits, boilerplate, regex, unit tests, styling). Trades reasoning depth for speed; text-only, 128K context, ChatGPT-Pro research preview, retired 2026-09-14. Best used as a fast *sub-agent* under a heavier planner model.
- **Provider / access:** **Research preview** rolling out to **ChatGPT Pro** users across the **Codex app, CLI (`-m gpt-5.3-codex-spark`), and VS Code extension**; **API access for select design partners only** (not the standard commercial API — you cannot build customer-facing apps on it). Runs on a **separate WSE-3 rate-limit bucket** that does not consume standard GPT quota. Third-party route via **OpenCode Zen** (`opencode/gpt-5.3-codex-spark`). No open weights (proprietary). Manual model selection in IDEs (no auto-fallback; a future "Hybrid Mode" router was floated but not shipped).
- **Release / knowledge:** Released **12 February 2026** (OpenAI + Cerebras blogs); **retired 2026-09-14** (meta). The "5.3" denotes the training-data generation; the "Spark" suffix denotes the distilled/pruned variant. Knowledge cutoff not separately published.
- **IDs:** id `opencode/gpt-5.3-codex-spark`; CLI flag `gpt-5.3-codex-spark`; official URL `openai.com/index/introducing-gpt-5-3-codex-spark/`. **No Artificial Analysis page** (`gpt-5-3-codex-spark` → 404; retired preview, no public API for AA to benchmark).
- **Context window:** **128,000 (128K) total; 32,000 max output** (meta). remio: the 128K window "suggests it can read a whole codebase, but the processing depth over that window differs from larger models" — it recalls well but **struggles synthesizing complex relationships across ~50 files** or applying constraints requiring multi-step deduction.
- **Modalities:** **Text input → text output only** — **vision was explicitly removed** to shrink the model onto a single Cerebras chip's SRAM (remio/Cerebras; the standard GPT-5.3-Codex retains vision). **Reasoning:** a Codex-generation model that reasons, but the pruning/distillation reduces reasoning depth; **no reasoning benchmarks published** and independent reports note a "sharp drop in reasoning accuracy."
- **Pricing:** **No public first-party per-token rate** (ChatGPT-Pro preview; API for design partners only — for Pro users it does not count against the standard cap). Third-party **OpenCode Zen route: $1.75 / 1M input, $14.00 / 1M output, $0.175 / 1M cached read** (expensive — output at flagship territory). Retired, so no live first-party pricing.
- **Architecture:** A **distinct, smaller checkpoint of GPT-5.3-Codex** — **pruned/distilled** so it fits the **Cerebras WSE-3** on-chip SRAM (the WSE-3's massive on-chip memory bandwidth removes the memory↔compute bottleneck, enabling >1,000 tok/s, but its SRAM capacity is limited vs GPU-VRAM clusters, forcing the size reduction; ~20 kW per device). Parameters undisclosed. This is a **hardware-driven** model variant: the speed comes from the wafer-scale chip, not from a token-count reduction.

### Raw benchmarks found

> **Provenance:** The only quantitative scores are **vendor-published** (OpenAI's SWE-Bench-Pro / Terminal-Bench-2.0 chart points, reproduced by Cerebras and meta): **Terminal-Bench 2.0 ~58.4%**, **SWE-Bench Pro 51.5%**, "more capable than GPT-5.1-Codex-mini in a fraction of the time." **No Artificial Analysis page exists** (404 — retired preview, no public API), so there is **no independent speed/cost/intelligence measurement**. Two independent sources add crucial context: the **Hacker News thread "15× vs. ~1.37×"** (nvanlandschoot recalculated from OpenAI's own SWE-Bench-Pro chart that at *comparable accuracy by reasoning effort* the effective speedup is **~1.37×, not 15×**; nearbuy confirmed the "15× faster, 128k context" wording lives only in the page's `<meta>` tag/RSS, not the visible text) and **remio.ai** (hands-on: "significant intelligence tax," "highly advanced autocomplete rather than a pair programmer," exceptional for grunt work but "a mistake" for architecture/complex logic). **Reattribution guards:** (1) the **~77.3% Terminal-Bench 2.0 is standard GPT-5.3-Codex's score, NOT Spark's** (meta tradeoff + remio both flag this — Spark is ~58.4%, a ~19-pt drop); (2) sibling numbers for **GPT-5.3-Codex / GPT-5.1-Codex / GPT-5.1-Codex-max / GPT-5.1-Codex-mini / GPT-5-Codex** are NOT credited; (3) **no reasoning benchmarks** (AIME/GPQA/etc.) were published for Spark.

- **Agent / tool use:** **SWE-Bench Pro 51.5%** and **Terminal-Bench 2.0 ~58.4%** — real agentic-coding results, and "more capable than GPT-5.1-Codex-mini." Terminal-Bench 2.0 58.4% edges out GLM-5's 56.2% and hy3-preview's 54.4%. **But** it is ~19 pts below standard GPT-5.3-Codex (77.3%), and remio reports it "introduces a new, subtler bug" where the big model "fixes a bug," failing multi-file/multi-step orchestration. Designed for tight-loop iterative edits, not autonomous long-horizon agents.
- **Reasoning / knowledge:** **No reasoning benchmarks published** (meta tradeoff). Independent hands-on (remio) describes a **"sharp drop in reasoning accuracy"** and a **"significant intelligence tax"** from the pruning/distillation: it "can see a definition 20,000 tokens back but often fails to apply strict type constraints or architectural patterns… if the logic requires multi-step deduction" — "a high-bandwidth, low-compute operation." The HN recalculation implies its accuracy at a given reasoning effort is well below the standard model.
- **Coding:** Its raison d'être. **SWE-Bench Pro 51.5%**, **Terminal-Bench 2.0 ~58.4%**, beats **GPT-5.1-Codex-mini**; excels at precise edits, boilerplate for known APIs, regex, unit tests from existing logic, syntax corrections, UI/styling iteration and "visualize new layouts" — preserving developer flow state. **But** it trades precision for speed ("suggests a solution in 2 minutes where the big model takes 17, but the probability of first-try correctness is significantly lower"), and complex logic/architecture is explicitly "a mistake." The optimal pattern per remio/community is Spark as a **fast sub-agent** under a heavier planner (GPT-5.3-Codex standard / Opus 4.6).
- **Long context:** **128K** window (32K max output). remio: **"128k context does not equal intelligence"** — recall is effective but synthesis across ~50 distinct files / multi-step deduction "is where the architecture begins to struggle compared to the standard version." No RULER/MRCR long-context retrieval number published.
- **Speed / cost:** The headline — **>1,000 output tok/s on Cerebras WSE-3**, marketed as **"~15× faster than standard GPT-5.3-Codex."** **Disputed:** the independent HN recalculation from OpenAI's own chart points puts the effective speedup at **~1.37× at comparable accuracy** (the 15× compares different accuracy/reasoning-effort settings); community consensus: "efficiency per token has tanked but it's still faster," "first-gen Cerebras hardware." **No AA speed/cost measurement** (no page). **No public first-party price**; Zen route $1.75/$14.00 ($0.175 cached); separate Pro rate-limit bucket.

### Normalized scores (1–100)

- **Tool use: 63/100.** Real agentic-coding results — **SWE-Bench Pro 51.5%**, **Terminal-Bench 2.0 ~58.4%** (beats GPT-5.1-Codex-mini, GLM-5's 56.2%, hy3-preview's 54.4%) — and it is purpose-built for tight-loop iterative edits, plan revision and contextual codebase Q&A. Held to mid-range because it is **~19 pts below standard GPT-5.3-Codex on Terminal-Bench 2.0**, independently reported to "introduce a new, subtler bug," weak on multi-file/long-horizon orchestration, and designed as a fast *sub-agent* rather than an autonomous agent.
- **Reasoning: 55/100.** The weakest quality dimension by design — **no reasoning benchmarks were published**, and the pruning/distillation imposes a documented **"intelligence tax"** ("sharp drop in reasoning accuracy"; "high-bandwidth, low-compute"; fails multi-step deduction / applying constraints seen 20K tokens back). It remains a Codex-generation reasoner that beats Codex-mini, so it is not non-reasoning, but the reduced depth and the independent "~1.37× at comparable accuracy" finding cap it here.
- **Context window: 60/100.** **128K total / 32K max output** — modest for a 2026 coding model (many peers are 200K–1M) and, critically, **the depth over the window is weak**: remio's "128k context does not equal intelligence" (recalls well, but "synthesizing complex relationships across 50 distinct files is where the architecture begins to struggle"). No RULER/MRCR retrieval number published.
- **Multimodal: 50/100.** **Text-only** — **vision was explicitly removed** to fit the Cerebras WSE-3 SRAM (the standard GPT-5.3-Codex retains vision). Scored at the corpus convention for a text-only model (no image/audio/video in or out).
- **Coding: 66/100.** Its core purpose and best-corroborated strength — **SWE-Bench Pro 51.5%**, **Terminal-Bench 2.0 ~58.4%**, "more capable than GPT-5.1-Codex-mini," genuinely excellent for boilerplate/regex/unit-tests/syntax/UI-styling "grunt work" that preserves flow state. Capped well below the frontier because it **trades precision for speed** (first-try correctness "significantly lower," ~19 pts under standard Codex on TB 2.0), is "a mistake" for architecture/complex logic, and behaves like "a highly advanced autocomplete rather than a pair programmer."
- **Cost efficiency: 56/100.** **No public first-party per-token price** (ChatGPT-Pro preview + design-partner API only); the accessible third-party **OpenCode-Zen route is expensive at $1.75/$14.00** (output at flagship territory, $0.175 cached). The one value lever is the **separate WSE-3 rate-limit bucket** that doesn't consume standard Pro quota — but the model is **retired**, and remio notes the real "cost" is the lower accuracy requiring more user verification. (Scored but NOT counted toward Overall.)
- **Overall Score: 59/100.** Half-up mean of the five quality dims (63+55+60+50+66)/5 = 294/5 = 58.8 → 59. Divergence **−6.2** vs the curated queue value 65.2 — a sizable **negative** gap (only the second negative-div model this run after claude-haiku-3.5): the curated view appears to credit the **novel >1,000 tok/s real-time capability**, the respectable **SWE-Pro 51.5 / TB-2.0 58.4** numbers, and its niche utility, whereas the quality-dimension mean is dragged down by the **text-only modality (Multimodal 50)**, the documented **reasoning "intelligence tax" (55)**, the **weak 128K depth (60)**, the **disputed "15×" speed claim** (~1.37× at comparable accuracy), and the fact that it is a **retired, no-public-price research preview** whose accessible route costs $14/M output. Speed is a real differentiator but is not one of the five scored quality dimensions, so it cannot lift the mean. Cost efficiency excluded from the mean per methodology.
