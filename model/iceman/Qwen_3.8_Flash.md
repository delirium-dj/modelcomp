# Iceman — findings by Qwen 3.8 Flash

- Source: OpenCode Zen/Console (`iceman-free`) + OpenCode Go (`iceman-contributor-free`), cross-checked against OpenCode's own model docs, models.dev's catalog records, OpenCode's first-party usage telemetry, and **one independent exact-ID benchmark suite** (Stealth Models' StealthMark 1.8.10) plus TokenDyno's instrumented throughput probes
- Date: 2026-11-09 (UTC) — deep research pass (18 successful independent searches + ~25 source fetches)
- Overview and scoring methodology: `../../model-comparison.md`
- Cross-model signed log: `../../model-findings.md`

> **Why this file is scored rather than excluded:** Iceman has **measured, exact-ID rows** from an independent harness. Stealth Models published a full **StealthMark 1.8.10** result set for `Iceman Contributor` — benchmark score **19.2**, General Intelligence **11.7**, Visual Intelligence **31.0**, with eight per-task scores (Beach 46.4 · Selfie 39.3 · Raccoon 29.8 · Ground Truth 20.2 · Mona Lisa 19.3 · Newton's Mirror 10.1 · Latch 3.6 · Foresight 3.2) — plus a **23-of-23-phrase token-count test** and a measured speed of ~46 tok/s, and TokenDyno independently measures throughput/TTFT on the live route. That clears the exact-ID measured-row bar, so the file is written scored. What is **not** available, and is not invented here: the model's **identity is still unclaimed** (OpenCode's own data page files both channels under **Lab: Unknown**, checked 2026-11-09), and there is **no AA Intelligence Index, GPQA, SWE-bench, LiveBench or Terminal-Bench row** for it. Scores below describe measured behavior on a hard, narrow suite — they are **not** frontier-intelligence claims, and the resulting Overall (52.2) should be read as "measured weak-to-mid on planning/physics/design tasks", nothing more.

## Model card

- **Name:** Iceman — two live channels under one codename: **`iceman-free`** (OpenCode Console/Zen, catalog release date **2026-11-06**) and **`iceman-contributor-free`** (OpenCode Go, **2026-10-24**). ArtificialWatch's registry, re-checked **2026-11-09**, lists both as still anonymous ("Iceman Free … 3 days", "Iceman Contributor Free … 16 days").
- **Status:** **LIVE ANONYMOUS STEALTH PREVIEW.** OpenCode's docs word it exactly: *"Iceman Free is a stealth model that's free on OpenCode for a limited time. The team is using this time to collect feedback and improve the model."* No end date announced.
- **Provider / access:** OpenCode only. Console/Zen route `https://opencode.ai/inference/openai/v1` (`@ai-sdk/openai-compatible`); Go route `https://opencode.ai/inference/go/openai/v1/chat/completions`. Referenced as `opencode/iceman-free` / `opencode-go/iceman-contributor-free`. Also resold third-party: **reMona Platform** (`iceman-contributor-free`, OpenAI-compatible, "Priced per unit: undefined"). **No OpenRouter listing was found** for either channel.
- **Release / knowledge:** first seen **2026-10-24** (Stealth Models "first seen 24 Oct 2026"); OpenCode Go's catalogue went 29 → **30 models** on 2026-10-27 with PR 58792 merged 20:24 UTC 2026-10-24; the console/Zen channel is catalogued with release date **2026-11-06**. **No maker, no model card, no parameter count, no knowledge cutoff.**
- **Context window:** **262,144 in / 131,072 max output** — identical in models.dev, ToolScout, pi.dev, reMona, mastra and ArtificialWatch. Users call it out as a real constraint: *"262k context is limiting."*
- **Modalities:** **text in / text out only.** `attachment: false` in models.dev; reMona: *"Image input: Not supported."* No audio, video, file or image input, no generated media output.
- **Reasoning / tools:** reasoning model, tool calling **supported** on every catalog that lists it. ⚠️ **Conflict on record:** models.dev publishes `reasoning_options: []` (no declared effort ladder) while pi.dev's derived config sets `supportsReasoningEffort: true` and `supportsStrictMode: true`. Treat effort control as undocumented, not as absent.
- **Pricing:** **$0 input / $0 output / $0 cache read** on both channels. On Go it is **allowance-exempt** — "unlimited for a limited time" alongside Crouton Alpha Free and Beam Free (Go $10/mo, Go Plus $40/mo, restricted to the Europe & United States region band for training-modeled endpoints).
- **Data terms (the defining commercial fact):** ⚠️ **retained and trained on.** Console docs, Privacy section: *"Iceman Free: During its free period, collected data is **retained and used to improve the model**."* The Go Contributor channel is an explicit barter: *"Free for a limited time in exchange for permission to use your prompts and completions to improve the model"*, **Model training: Yes**, **Data retention: Not ZDR**. "Contributor" is OpenCode's **channel label** for that barter (Meta's Muse Spark 1.3/1.2 have Contributor versions too), **not** a clue about the lab. Enforced client-side: Go users get *"Upstream request failed: This Go model trains on request data. Allow paid endpoints that train on request data in your workspace's Privacy settings to use it."*
- **Architecture:** undisclosed. Weights closed (`open_weights: false`), no HF checkpoint.
- **Reliability:** not clean. Freetokens' probes hit **HTTP 400 "Model is unavailable" on 9 probes across 4 rounds** (2026-10-27 → 10-28, seats go2/go3) while the Go catalogue still listed it (classified "unavailable", not ended); Desktop-vs-CLI quota/consent bugs are documented in anomalyco/opencode issue #60949 (opened Oct 31, closed as not planned Nov 1; billing support routed to email).

### Raw benchmarks found

> Provenance, stated plainly: **the anonymous maker published nothing.** The only numeric capability rows are **StealthMark** (independent, exact-ID, hard suite) and **TokenDyno** (independent, exact-ID, throughput). **Verified absence:** `artificialanalysis.ai` exposes no Iceman page, `benchlm.ai/models/iceman-free` → **404**, OpenCode's own comparison page returns **"—" for every capability and benchmark field** of `iceman-contributor`, and there is no Hugging Face card for `stealth-model/iceman` (only `iceman-contributor`). So **no Intelligence Index, GPQA, SWE-bench, LiveBench, Terminal-Bench or MRCR absolute exists**, and none is imported from MAI-Thinking-1, GPT-6 or any other guessed parent.

**1) StealthMark 1.8.10 (Stealth Models / stealthmodels.com, run on the exact ID `iceman-contributor`):**

- **Benchmark score 19.2** · **General Intelligence 11.7** · **Visual Intelligence 31.0**
- Per task: **Beach 46.4**, **Selfie 39.3**, **Raccoon 29.8**, **Ground Truth 20.2**, **Mona Lisa 19.3**, **Newton's Mirror 10.1**, **Latch 3.6**, **Foresight 3.2**
- Case file: first seen 24 Oct 2026; **~417 billion tokens on its first full day**; context 262,144; input text; tool calls yes; **speed in their tests ~46 tok/s**; "Active; prompts may be used for training"
- Harness meaning (essential to read these numbers honestly): StealthMark is a **hard SVG/planning/physics/design suite**, not a leaderboard of general ability. On Foresight alone, **51 models played, median 40.3, top 76.1 (GPT-6 Astra)** — so Iceman's **3.2** is bottom-of-board on anticipatory planning, and **Latch 3.6** is the same floor. Its higher marks (Beach, Selfie) are **code-generated scene composition** tasks, i.e. writing markup that draws a picture.
- **Same-harness calibration (their numbers, same build 1.8.10):** **Crouton Alpha 48.0** (GI 43.5 / VI 56.0; Foresight 32.3, Latch 59.5) · **Glyph Cluster 18.9** (GI 12.0; Foresight 6.4, Latch 3.6) · **Space Bunny Alpha** — later *revealed* as MiniMax M3.1 Flash — **Selfie 78.9 / Raccoon 74.3 / Beach 67.8**. Iceman sits **~40% of Crouton's level**, essentially tied with its tokenizer-twin Glyph Cluster, and **far below a released frontier-class model** on the same tasks.
- Tokenizer forensics: *"Iceman Contributor counts tokens exactly like MAI Thinking 1 and Glyph Cluster, on **23 of 23** phrases"* → Stealth Models' stated lead is a **single tokenizer family behind both** (their Glyph Cluster card claims the MAI-Thinking-1 match on "all 24 of our test phrases" — a **23-vs-24 inconsistency inside the same publisher**, logged here rather than smoothed over).

**2) TokenDyno live throughput probes (exact route `opencode-go-anthropic/iceman-contributor-free`, i.e. measured over the **Anthropic-messages** route, every ~6 h, fixed ~300-token prompt):**

- Fetched values: **106.4 tok/s latest**, **84.0 tok/s 24 h avg**, **TTFT 2.9 s**, **100% 24 h reliability**, ranked **7 of 25** models on OpenCode Go and **30 of 58** across their provider set
- A same-day search snapshot of the same page read **27.2 tok/s latest / 53.8 tok/s 24 h avg / TTFT 8.5 s** → **~3–4× swing** on one route
- Reconciliation: Stealth Models' **~46 tok/s**, TokenDyno's low snapshot (27–54) and its later 84–106 cluster are consistent with **load-dependent throughput on a free preview**, not three different models. I score on the mid-band (~45–85 tok/s) and treat 106 as a quiet-window peak. Community reports line up with the mid-band and not with Crouton-class speed: *"certainly not as fast as Beam."*

**3) Qualitative / in-the-wild (no numbers, used only for relative placement):** the r/opencode first-impressions thread on the Contributor channel — *"I'd say it's a little less useful than MiniMax or so. But may be better than Beam? Unsure, but 262k context is limiting, and certainly not as fast as Beam"*; a sibling thread asking whether it is bad enough to *"contaminate my repo with bad code"*; and the post that linked the benchmark set, titled *"Stealthmodel 'Iceman Contributor': free and quite fast — MAI Thinking 2 ?"*, whose author's own conclusion was *"the benchmarks show where the free Opencode Go model has its use, and where it likely would be a waste of time"*. Note the hypothesis in that title is **counterfactual**: **"MAI Thinking 2" does not exist as of 2026-11-09** (prediction markets on a new MAI thinking release are still unresolved).

**Attribution evidence — deliberately not used for scoring:** *For Microsoft:* self-identification reports as Microsoft MAI, token counts identical to **MAI-Thinking-1** (23/23) and to Glyph Cluster, and MAI-Thinking-1 is marketed for "complex multi-step instructions, long context reasoning, and code generation". *Against / unresolved:* the same counts **also match OpenAI's GPT-6 family**, so the test cannot discriminate; a tester's alternative reading is *"another version of MAI Thinking 1 — or potentially a finetune of GPT OSS"*; a model repeating an identity from training data or a planted system prompt proves nothing; and **Microsoft has said nothing**. OpenCode files both channels as **Lab: Unknown** on 2026-11-09. Precedent for how long this may take: the **5** OpenCode stealth models that were ever named were named a **median of 7 days** after listing (max 33), and **8 of 13** were never named at all — Iceman Contributor is at **day 17** with no claimant, i.e. already past the median. Borrowing MAI-Thinking-1 or GPT-6 numbers here would be a lineage proxy and is prohibited.

### Normalized scores (1–100)

- **Tool use: 62/100.** Function calling is declared supported by **every** catalog that carries the ID (models.dev `tool_call: true`, ToolScout, pi.dev, reMona), `supportsStrictMode` is set in pi.dev's derived config, and the route is demonstrably consumed inside real agent loops — **989,929 completed sessions** at **3M tokens/session** on the console channel and **67.8% weekly retention** on the Contributor channel (vs 54.2% for MiniMax-M2.7 on the same comparison page) is not something a broken tool loop produces. But there is **zero measured tool-task evidence**: no τ²/τ³, no MCP-Atlas, no multi-step tool-chain suite, and the one suite that does score this ID (StealthMark) does not test tools. Docked further for documented operational friction — the HTTP 400 "Model is unavailable" probe run, and consent-gating that silently blocks the model for Go workspace members who cannot find the Privacy toggle.
- **Reasoning: 50/100.** This is the dimension with real measured data, and the data is **bad**: **General Intelligence 11.7/100** on StealthMark, with **Foresight 3.2** and **Latch 3.6** at the floor of a suite whose observed median is ~40, and **Newton's Mirror 10.1**. Those tasks probe planning, state-tracking and physical/causal consistency — precisely what an agent needs when it runs long. The partial credit is that it is genuinely a thinking model (reasoning tokens are served, and they are counted in OpenCode's telemetry), its best marks come on constructive tasks (Beach 46.4), and no formal math or science absolute exists to confirm or refute either reading. Held at mid-low rather than near-floor because a single non-standard suite, however reproducible, is thin authority for a bottom-decile claim.
- **Context window: 62/100.** **262,144 in / 131,072 out** — a headroom-rich output cap, and the console channel's own numbers show it survives long agent sessions (3M tokens per session, **95% of input tokens served from cache**, so prompt-cache reuse works well). It is nonetheless a **second-tier window in 2026** (Crouton, Pulse Alpha, Beam, Kimi K3, Hy4 all list 1M+) and users feel it: *"262k context is limiting."* No MRCR/RULER absolute exists, so long-window **quality** is unmeasured, and the Go Contributor channel is separately advertised with **prompt cache "Not offered"** (reMona) — the 95% figure is the console route's behavior, not a guarantee across channels.
- **Multimodal: 32/100.** Effectively the floor: **text in, text out**, `attachment: false`, image input explicitly *"Not supported"* on the Contributor route, no audio/video/file input, no generated media. The points above the floor are for structured I/O (strict-mode tool definitions, JSON) and nothing more. Do not put images, PDFs or screenshots through this model — its 1M-context sibling Crouton is the multimodal option in the same catalogue.
- **Coding: 55/100.** No repo-scale measure exists (no SWE-bench Verified/Pro, no LiveCodeBench, no Terminal-Bench). What does exist: the SVG/design tasks are **code-generation** tasks and Iceman's band there is mid-low (**Beach 46.4 / Selfie 39.3 / Raccoon 29.8 / Mona Lisa 19.3**, versus 60–79 for Crouton and revealed-MiniMax on the same suite), and the field verdict is *"a little less useful than MiniMax … may be better than Beam"* with a plausible reason to keep it out of a main repo. Weighting that against very heavy real adoption as a free Go-plan coding model (935B tokens on the Contributor channel, 36K users) and mid-band throughput, this reads as a **competent-but-not-strong coding agent**, not a frontier one.
- **Cost efficiency: 88/100.** Monetarily close to the floor of costs: **$0/$0/$0**, unlimited requests for a limited time, allowance-exempt on Go, and it is the cheapest way today to get reasoning+tool loops at scale on OpenCode. Discounted, and deliberately so, because the **price is paid in data**: prompts and completions are **retained and used for training** (Not ZDR), which for any company codebase is a confidentiality problem rather than a cost saving — the community checklist verdict is "fine for prototypes and public code, not for private repos or anything with secrets". Add an unannounced end date plus the availability wobbles, and the free lunch is real but short and unguarded.
- **Overall Score: 52.2/100.** Half-up mean of the five quality dims (62+50+62+32+55)/5 = **52.2** (Cost excluded). Honest summary of the measured record: a **text-only, 262K, reasoning+tool-calling model with real agent-loop mileage and no multimodal ability**, whose only exact-ID benchmark puts it **far below** Crouton Alpha and a revealed MiniMax frontier release on planning, physics and design tasks, and roughly at parity with the anonymous "Glyph Cluster" that shares its tokenizer. Best fit: **cheap bulk scaffolding on OpenCode Go** — summarizing, drafting, small bounded edits, prototypes on public/synthetic code — under a stronger planner. Avoid it for **anything multimodal**, for **planning-heavy or physics/causal reasoning**, for **private or confidential repos** (it trains on your prompts), and anywhere you need a guaranteed-available endpoint. Two caveats that must travel with this number: (1) the StealthMark rows were measured on the **Contributor** channel; the console `iceman-free` channel is the same codename with byte-identical published specs and no independent measurement of its own, so the score is applied to the family and flagged as such; (2) one hard, narrow suite is a thin base for any Overall — if a second exact-ID harness (Cold Iron, an AA row, a SWE-bench run) appears, these five numbers should be re-derived, not defended.
