## Model card

- **Name:** Kimi K2.5
- **Short description:** Moonshot AI's **native multimodal agentic** open-weight model, released **2026-01-27** via continual pretraining on ~15T mixed visual+text tokens on top of Kimi-K2-Base. Its defining feature is the **Agent Swarm** paradigm — a self-directed architecture that coordinates up to **100 parallel sub-agents** (1,500+ tool calls, up to 4.5× faster execution) without predefined roles. Architecturally it uses **MoonViT-3D**, a native-resolution vision encoder with NaViT packing, enabling variable-resolution image inputs, with visual features compressed by spatial-temporal pooling before projection into the LLM. It has since been **superseded by Kimi K2.6, Kimi K2.7 Code and Kimi K3**.
- **Provider / access — LIFECYCLE, the material change this pass:** the **Moonshot first-party endpoint is DISCONTINUED**. Moonshot confirmed that `kimi-k2.5` and the entire `moonshot-v1` series (8k/32k/128k/auto) were **fully discontinued on 2026-08-31**; both strings had already been closed to newly registered Kimi API users since the K3 launch on 2026-07-16. The first pass described this sunset as "approaching" — it has happened. Remaining access:
  - **Amazon Bedrock** — model ID `moonshotai.kimi-k2.5`, lifecycle **Active**, launch 2026-01-27, **EOL no sooner than 2027-01-27**, legacy period ≥6 months; in-region only (Geo and Global inference profiles **not supported**), 10 regions.
  - **Microsoft Foundry** — available in 25 regions at $0.60 / $3.00 with $0.11 cached input; **deprecation 2027-01-26** (Radar deprecation calendar, first observed 2026-08-26; corroborated by modelavailability.com's "Deprecation: 1/26/2027").
  - **Self-hosted weights** — the only route with no clock on it. `Kimi-K2.5-Base` and `Kimi-K2.5-Instruct` are public under a Modified MIT License.
  - NVIDIA NIM (`moonshotai/kimi-k2.5`, NIM and NIM-Turbo containers); OpenRouter (`moonshotai/kimi-k2.5`); Requesty.
  - Cloudflare's `@cf/moonshotai/kimi-k2.5` **was retired 2026-05-30**, replaced provider-named by `@cf/moonshotai/kimi-k2.6`.
- **Release / knowledge:** Released **2026-01-27** (Moonshot/Bedrock); NVIDIA NIM and Vals both record 2026-01-26. **Knowledge cutoff: October 2025** (ApX) — uncorroborated by Moonshot.
- **IDs:** `moonshotai.kimi-k2.5` (Bedrock), `moonshotai/kimi-k2.5` (NIM / OpenRouter), `kimi-k2.5` (Moonshot, now dead)
- **Context window:** **256K (262,144 tokens)** — now confirmed by **three** routes: Moonshot's own API table (pre-sunset), Vals, and the AWS Bedrock model card. Requesty and OpenRouter also list 262K. ApX's 512K claim remains **unresolved and uncorroborated**.
- **Max output — wide conflict, recorded not resolved:** **Bedrock 16K** (official AWS model card) vs **Vals 128K** (its stated harness setting) vs **OpenRouter 64,000 tokens** vs Requesty 262K. Bedrock's 16K is the only figure from a provider contract, and it is 8× below Vals and 16× below the 256K window. Practical consequence: on Bedrock, a 256K-context model can emit at most 16K tokens.
- **Modalities — CONFLICT, and it cuts against the leads:** Vals' capability probe records **Text supported, Image supported, Video input NOT supported, File input NOT supported**. The **AWS Bedrock model card** independently records Input Modalities with **Video ✗**, Image ✓, Text ✓, Audio ✗, Speech ✗, max image payload 3 MB. But **Moonshot's own technical report and GitHub README report measured video results** — VideoMMMU 86.6, MotionBench 70.4, VideoMME 87.4, LongVideoBench 79.8, **LVBench 75.9** — and the **NVIDIA NIM card states "Supports image, video, PDF, and text inputs. Video input is experimental."** The correct reading is that **video is a capability of the weights but is not exposed by the Bedrock or Vals serving surfaces**; it is not a missing capability. **PDF: the first pass's claim is sourced and is RETAINED** — NVIDIA's NIM documentation states it explicitly. The lead asserting that no vendor source supports PDF input is wrong and is not applied.
- **Architecture:** **1T total / 32B active sparse MoE**, 61 layers (1 dense + 60 MoE), MoE hidden dim 2,048 per expert, attention hidden dimension 7,168, 64 attention heads, 384 routed experts with 8 selected per token plus 1 shared expert, MLA attention, SwiGLU, ~160K vocabulary, MoonViT-3D vision encoder (~400M). **Modified MIT License** — commercial use, fine-tuning and redistribution permitted. Native INT4 weight-only quantization supported. Self-hosting footprint at 512K context is roughly 2.96 TB of VRAM (FP16 estimate).
- **Pricing (as of 2026-10-17):** **$0.60 in / $3.00 out** per 1M tokens on Bedrock and Microsoft Foundry (cached input $0.11 on Foundry). OpenRouter lists **$0.45 / $2.25**. Artificial Analysis records $0.60 / $2.75. ApX lists $2.75 output. The Moonshot first-party rate card is no longer purchasable.

### Normalized scores (1–100)

- **Tool use: 70/100.** Held. τ²-Bench 95.9% (AA) and Claw-Eval 52.3% (independent) are the strongest items; BrowseComp 60.6%, WideSearch 72.7% and DeepSearchQA 77.1% are **vendor** numbers, and the Agent Swarm variants (BrowseComp 78.4, WideSearch 79.0) show how much of the headline agentic performance is a multi-agent scaffold rather than the base checkpoint. **New this pass and unhelpful: Terminal-Bench 4.0 at 13% on Artificial Analysis.** Nothing raised the score and nothing lowered it; the picture is unchanged.
- **Reasoning: 74/100.** Held. GPQA Diamond 84.09% (Vals) / 87.6% (vendor), MMLU-Pro 85.91% (Vals), AIME 2025 96.1% and HMMT 95.4% are solid. Capped hard by **AA Intelligence Index 23**, **CritPt 3%**, **AA-Omniscience −7**, and HLE text-only at 30–31% across both vendor and independent readings. The HLE-with-tools figure of 50.2% is a genuine positive and is credited here. No CritPt/Omniscience absence to complain about any more — they exist now, and they are low.
- **Context window: 84/100.** **Raised from 82.** 256K (262,144) is now verified on three routes rather than one (Moonshot's table, Vals, and the AWS Bedrock card). The reason for the bump is new independent evidence: **AA-LCR v1.1 78%** is a far better long-context retrieval measurement than the LongBench v2 61% the first pass had, and it is the kind of test that actually discriminates. Still capped by a mid-tier 256K window, the uncorroborated ApX 512K claim, and the practical fact that **Bedrock caps output at 16K** on a 256K-context model.
- **Multimodal: 84/100.** **Held — and a lead that would have cut this is rejected.** Vals and the AWS Bedrock card both record video input as not supported, and the lead took that as proof the model is image-only. It is not: **Moonshot's own technical report publishes measured video results** (VideoMMMU 86.6, VideoMME 87.4, LongVideoBench 79.8, LVBench 75.9), and NVIDIA's NIM card states the model "Supports image, video, PDF, and text inputs." The Bedrock/Vals "not supported" flags describe **serving surfaces**, not the weights. Same correction for PDF: the first pass's PDF claim is sourced to NVIDIA's NIM documentation and is **retained**, not withdrawn. Independently corroborated vision: MMMU-Pro 84.33% (Vals). Capped only by text-only output, no audio path, and the deployment caveat that the two surviving hosted routes do not expose video.
- **Coding: 76/100.** Held, on corrected provenance. Every strong coding number on this model is a **Moonshot model-card number**, which the newly visible source column makes explicit — SWE-bench Verified 76.8%, LiveCodeBench v6 85.0%, SWE-bench Pro 50.7%, SWE-bench Multilingual 73.0%, SciCode 48.7%. The first pass counted SWE-bench Verified as triple-sourced; it is one vendor figure repeated. Independent evidence reads lower across the board (Vals SWE-bench 70.00%, Vals LiveCodeBench 83.87%, **Vibe Code Bench v1.1 17.54%**) with SWE-Rebench 58.5% and React Native Evals 77.2% the exceptions. The score does not move because the first pass already had the Vals numbers in view — but the reason not to *raise* it is now firmer, and the honest read is "a good open-weight coder whose headline sheet is a vendor sheet."
- **Cost efficiency: 88/100.** Held. $0.60 / $3.00 on Bedrock and Foundry, $0.45 / $2.25 on OpenRouter, and the **Modified MIT weights permit full commercial self-hosting** — the strongest cost argument in the open-weight tier, and the one argument the August 31 sunset cannot take away. Not higher because the first-party endpoint is gone, there is no free tier, Bedrock caps output at 16K which limits practical long-generation economics, and Foundry itself is deprecated on 2027-01-26.
- **Overall Score: 77.6/100.** (70 + 74 + 84 + 84 + 76) / 5 = **77.6**, cost excluded — up from 77.2 on the first pass's arithmetic. Best fit: self-hosted native-multimodal agent and visual-coding workloads that need Agent Swarm parallelism. The Moonshot-hosted endpoint is gone; plan for Bedrock, Foundry or your own GPUs, and prefer K2.6 or K3 for hard agentic coding.
