## Model card

- **Name:** Ring-2.6-1T (Hugging Face `inclusionAI/Ring-2.6-1T`, ModelScope `inclusionAI/Ring-2.6-1T`; AA id `ring-2-6-1t`; curated id `opencode/ring-2.6.1t`)
- **Short description:** InclusionAI's (Ant Group's) **"trillion-parameter flagship reasoning model designed for real-world complex task scenarios"** — the *thinking* half of the 2.6-1T pair, released alongside the instruction-tuned **Ling-2.6-1T**. The stated goal is explicitly not parameter scale: "not simply to pursue larger parameter scale, but to address the real production environments that large models are entering: **agent workflows, engineering development, scientific research**". Its signature feature is an **adjustable Reasoning Effort mechanism** with two levels — `high` (default for high-frequency agent workflows: multi-turn interaction, tool collaboration, task decomposition) and `xhigh` (extra reasoning budget for mathematics, science, complex logical analysis, multi-path exploration).
- **Provider / access:** **Open weights**, downloadable from Hugging Face and ModelScope. **License: MIT** (the card's front-matter declares `license: mit` and the repo points at `inclusionAI/Ring-V2.5/LICENSE`) — the most permissive licence class in this registry, so commercial deployment is unrestricted on paper. Serving guidance in the card is **SGLang**-oriented ("we will later submit our model to SGLang official release", with a multi-node `--master-addr` launch example); the family's async-RL training stack is NeMo-aligned. Training-content disclosure is published as a transparency PDF (`inclusionAI/AI-Transparency/Ring-2.6_TDS-Summary.pdf`), an EU-AI-Act-style summary rather than a full technical report.
- **Release / knowledge:** Artificial Analysis lists **Released May 2026**; third-party marketplace listings for the sibling Ling-2.6-1T are dated **2026-04-23/27**, so the 2.6-1T pair landed in the **April–May 2026** window. **No knowledge-cutoff date is published** in the card, and no standalone technical report with training detail is available — the card is prose + one benchmark claim + deployment notes.
- **IDs:** `inclusionAI/Ring-2.6-1T` (HF/ModelScope), `ring-2-6-1t` (AA), `opencode/ring-2.6.1t` (curated). **Aggregator coverage flag:** BenchLM returns **404** for both `ring-2-6-1t` and `ling-2-6-1t` (it *does* have pages for other members of this family, e.g. `ling-2-6-flash`), llm-stats' `models/ring-2.6-1t` and `models/ring-2-6-1t` render **no content**, and OpenRouter has **no `inclusionai/ring-2.6-1t` product page**. The independent evidence base for this ID is therefore **Artificial Analysis plus the vendor card only**.
- **Context window:** **128K native, extendable to 256K with YaRN** — the card's own download table reads "128K -> 256K (YaRN)", and Artificial Analysis reports the served window as **262k tokens**. The curated `meta.json` says "128K total", which matches the *native* figure but omits the documented YaRN extension that AA measures. **Max output tokens are not published** anywhere found — an unresolved gap given the methodology's sub-64 K output caveat.
- **Modalities:** **text in / text out.** AA: "supports text input, outputs text". The card's entire framing is text reasoning, tool calls and agent loops; there is no vision encoder, no audio, no generation of non-text output. The curated "Text in/out" is **correct** here.
- **Pricing (as of 2026-10-08):** Artificial Analysis measures **$0.30 / $2.50 per 1M input/output** with **$0.29 per Intelligence-Index task** (#22 of 117) — input exactly at its class median, output called "somewhat expensive" (class median $1.15). Self-hosting is licence-free (MIT) but the practical cost is hardware: a 1T-parameter MoE in BF16 is a multi-node job (the card's own example spans multiple GPU nodes). **Scaffold flag:** the curated `pricingNote` is the placeholder string "Standard pricing" with no numbers.
- **Architecture:** **1T total parameters / 63B active per token** (AA spec block: "Total parameters 1T", "Active parameters 63B"), sparse MoE, **reasoning** model. Post-training is the headline engineering story: an **asynchronous RL architecture** that decouples policy sampling from parameter updates, with the **IcePop** algorithm carried over from `Ring-1T` to stabilise async training — introduced to fix "insufficient training throughput: prolonged training cycles with limited iteration speed". The Reasoning Effort knob (`high` / `xhigh`) is a *deployment* feature: dynamic allocation of thinking budget per task difficulty.
- **Identity flags:** (1) **Ring vs Ling split:** `Ring-2.6-1T` = thinking/reasoning line, `Ling-2.6-1T` = instruct line; they share scale and release window but are **different models** and must not inherit each other's scores. The registry already has `model/ling-2.6.1t/` and `model/ling-2.6-flash/` as separate folders. (2) Predecessors `Ring-1T` / `Ring-2.5-1T` are distinct (the card cites Ring-1T's IcePop and links the Ring-V2.5 repo for licensing). (3) **Scaffolded entry:** `meta.json` carries `"scaffolded": true` with the boilerplate `short` "Ring 2.6.1t model evaluation entry." — the official name is **Ring-2.6-1T** (InclusionAI style), and pricing/cutoff need curation. (4) **Slug check:** `ring-2.6.1t` uses the registry's dotted-version convention correctly and has no hyphen twin (rule-7 clean).

### Normalized scores (1–100)

- **Tool use: 52/100.** The design intent is unambiguously agentic — two-level reasoning effort with `high` tuned for "high-frequency agent workflows … multi-turn interactions, tool collaboration, task decomposition", and the vendor's only quantitative claim is an execution harness (**PinchBench 87.60**, `high`, said to beat GPT-5.4 xHigh and Gemini-3.1-Pro). Against that: the number is single-sourced from the vendor on a harness with no independent run, and **τ²/τ³/Toolathlon/Claw-Eval/OSWorld/Terminal-Bench/GDPval have no verified row for this ID at all**. AA's composite (Index 17, built substantially from agentic evaluations) gives no indirect support for a high placement. Judged at the lower edge of the mid tier with the absence stated rather than papered over.
- **Reasoning: 48/100.** The decisive independent signal is AA's **Intelligence Index 17** against a **class median of 18** — i.e. a trillion-parameter flagship measured **below the average of comparable open-weights models**, and well under the methodology's mid-band reference of 20–35 and the frontier anchor of 60. `xhigh` effort plus 63B active parameters buys "more extensive reasoning space" in principle, and the family markets AIME/math strength, but **no GPQA, HLE, AIME, MMLU-Pro, CritPt or AA-LCR row is retrievable for this ID**, so there is nothing to lift the composite reading. The MIT licence and 1T/63B scale are architectural facts, not measured reasoning ability.
- **Context window: 68/100.** **256 K with YaRN** (documented "128K -> 256K (YaRN)", measured **262k** by AA) places it in the 200 K–500 K tier (65–84) at its low end, because the extension is opt-in RoPE rescaling rather than native length extrapolation — native training/deployment length is **128 K**, which alone would score in the 50–64 band. There is **no MRCR/AI-Needle retrieval measurement** for the ID, and **max output is unpublished**, so the sub-64 K output caveat can be neither applied nor dismissed; that unresolved gap is what keeps this at 68 rather than the tier midpoint.
- **Multimodal: 15/100.** **Text-only** on both sources — AA: supports text input, outputs text; the card contains no vision/audio encoder, no document or image evaluation, and no non-text output. That is the methodology's 10–20 band with nothing to lift it, and the curated "Text in/out" is accurate for once.
- **Coding: 40/100.** "Engineering development" and "code generation" are named as target workloads and the model is an RL-trained reasoning model — the right shape for coding agents — but the registry has **no coding measurement for this ID**: no SWE-bench Verified, LiveCodeBench, DeepSWE, SciCode, Terminal-Bench or Coding-Index row from any independent source (BenchLM 404, llm-stats unrendered, AA components not broken out), and the only adjacent SWE-bench-style fragment proved **unattributable** and was excluded. Scored near the bottom of the low band with the evidence gap printed in full.
- **Cost efficiency: 92/100.** **$0.30 / $2.50** per 1M with **$0.29 per Intelligence-Index task** (#22 of 117), input priced exactly at the class median, **"fairly concise"** (120M vs 140M median — it does not waste tokens while thinking) and **notably fast at 110.7 tok/s** (#14/117), on top of **MIT open weights** that make self-hosting licence-free. Deductions: output is "somewhat expensive" for the class (median $1.15 — over 2× — which matters because reasoning models emit many more output than input tokens), and the 1T-parameter footprint makes the practical self-host cost multi-node even when the licence is free.
- **Overall Score: 45/100.** Mean of the five quality dimensions (52 + 48 + 68 + 15 + 40) / 5 = 223 / 5 = 44.6 → 45; Cost excluded per `RULES.md`. Best fit: **organisations that must own their weights** — MIT-licensed trillion-parameter reasoning with a task-adaptive `high`/`xhigh` budget knob, deployed on a multi-node SGLang stack for agent workflows, enterprise process automation and engineering assistance, where per-token price and token economy ($0.29/task, concise, fast) matter more than leaderboard position. It is **not** the pick on measured capability: AA scores it **below its own size-class median** on intelligence, and after four aggregator sources came back empty there is **no independent benchmark row of any kind** — no τ-bench, no SWE-bench, no GPQA/HLE — to argue otherwise. Expect this Overall to move up once harnesses publish; re-verify before relying on it.
