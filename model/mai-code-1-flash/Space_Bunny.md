## Model card

- **Name:** MAI-Code-1-Flash
- **Short description:** Microsoft AI's **small, fast coding specialist**, introduced at Build 2026 (**2026-06-02**) and generally available across GitHub Copilot from 2026-06-26. Explicitly **"built for developers, not benchmarks"** — trained directly with the **GitHub Copilot production harnesses**. Its pitch is **token efficiency**: adaptive solution-length control keeps responses concise and solves harder problems with **up to 60% fewer tokens**. Microsoft launched it on the claim that it beats Claude Haiku 4.5 on *every* coding benchmark tested while using fewer tokens. Now retired.
- **Provider / access:** **Retired.** It was **GitHub Copilot only** — a single route, model ID `mai-code-1-flash-picker` (Models.dev family key) / `github_copilot/mai-code-1-flash`. Individual users selected it in the VS Code model picker or let Copilot auto-route to it; Copilot Enterprise and Copilot Business administrators had to enable the MAI-Code-1-Flash policy in Copilot settings. As of **2026-09-10** it is removed from Copilot Chat, inline edits, ask and agent modes, and code completions. There was never a standalone pay-per-token API and there is no OpenCode Zen ID.
- **Release / knowledge:** Released **2026-06-02** (Microsoft Build 2026); GA for Copilot Business/Enterprise **2026-06-26**; GitHub Models listing last updated 2026-06-08. **Knowledge cutoff: 2025-12** (Models.dev via ModelBench). Official model card gives **training dates March 2026 – May 2026**.
- **IDs:** `mai-code-1-flash-picker` (GitHub Copilot model-picker ID), `github_copilot/mai-code-1-flash`, `microsoft/mai-code-1-flash`
- **Context window:** **256K tokens — now settled.** The **official Microsoft model card PDF** states plainly *"Context length 256K tokens"*, and OpenCode's model data (models.dev-derived) independently lists **256K context / 128K max output**. This resolves the first pass's open conflict: the 128K-context / 64K-max-output figure carried by CloudPrice was the outlier, and it is not supported by any vendor or provider source. Max output **128K**.
- **Modalities:** **Text-to-text only**, now confirmed at the source: the official model card declares `Inputs Text` / `Outputs Text`. Reasoning: **adaptive solution-length control** — stays concise on simple requests, spends more reasoning budget on complex repository changes, refactors, debugging and tool-using agent tasks. Tool calls / function calling: yes. Structured output: yes. Temperature control: yes.
- **Pricing (as of 2026-10-09, now historical):** **$0.75 in / $4.50 out per 1M**, **cache read $0.075** (GitHub Copilot / GitHub Models), billed at provider list pricing under Copilot's usage-based billing. Paid only; no Free tier. This tariff is **unbuyable** — the only channel that sold it closed on 2026-09-10 — and it had already been undercut fourfold by the 2026-08-11 successor at $0.20 / $1.20 / $0.02.
- **Architecture:** proprietary closed weights — **weights not released**. Now confirmed at the source by the official model card: *"The model uses a transformer architecture with self-attention using sparse Mixture-of-Experts layers. Parameters 137B total, 5B active."* This **settles the first pass's ambiguity** between Microsoft's public "5B parameters" and third-party readings of a 137B MoE — 137B total, 5B active, no reconciliation needed. Licensed under GitHub / VS Code product terms, not an open licence.

### Raw benchmarks found

> **Provenance correction, and the single most important finding of this pass.** The first pass reported seven benchmark numbers sourced to BenchmarkList and said nothing about GPQA Diamond, HLE or τ²-Bench. All of that was an artefact of not having read Microsoft's **official MAI-Code-1-Flash model card PDF** (`microsoft.ai/pdf/MAI-Code-1-Flash-Model-Card.PDF`, 2026-06-03). That card publishes **eleven** scored rows across coding, reasoning and instruction-following/tool-use, and it discloses **average token usage** per task — a column no aggregator surfaced. **Every number below is Microsoft-reported**, measured in "our internal benchmark system with production harness"; the Claude Haiku 4.5 comparison figures are Microsoft-measured too, not Anthropic-measured.

Coding (all Microsoft-reported, production VS Code harness, end-to-end with repository context, tool calls and verification):

- **SWE-bench Verified: 71.6%**, average **10.8K tokens** per task — vs Claude Haiku 4.5 **66.6%** at **27.3K tokens**. The token column is the story: a **2.5× reduction** in solution tokens for a +5.0 point pass-rate gain. First pass listed an independent rank of 35/46 (24th percentile) — that rank still stands but was the only non-Microsoft number attached to the model.
- **SWE-bench Pro: 51.2%**, **28.0K tokens** — vs Claude Haiku 4.5 **35.2%** at **29.8K tokens**. A +16.0 point lead at slightly *fewer* tokens than the competitor. Independent rank 43 of 49 (13th percentile); BenchmarkList notes this is **−87.5 points behind Claude Fable 5.1 (81.2)**.
- **SWE-bench Multilingual: 65.5%**, **15.3K tokens** — vs Claude Haiku 4.5 **62.7%** at 17.2K. Independent rank 40 of 46 (13th percentile); **−84.4 points behind Opus 5 (89.5)**.
- **Terminal-Bench 2.0: 54.8%**, **21.6K tokens** — vs Claude Haiku 4.5 **41.6%** at 25.0K. Independent rank 20 of 68 (72nd percentile — its best relative coding rank).
- **ArtifactsBench: 36.4%**, **12.0K tokens** — an automated multimodal evaluation of visual and interactive artifact generation from code, MLLM-judged over 1,825 tasks. Note the honest comparison: Claude Haiku 4.5 scores **36.6%** here, i.e. Haiku is marginally *ahead*. The first pass called this "the only benchmark where this model tops its field" — true only inside BenchmarkList's one-model field, not against the competitor Microsoft itself benchmarks against.
- **Frontier Math Tier 1–3: 6.3%** (31.2K tokens) vs Haiku 4.5 2.8% (38.7K) — both models are near-floor on frontier math; do not read this as a differentiator.
- **AMO Bench (olympiad math): 40%** (56K tokens) vs Haiku 4.5 16% (46.2K).
- Terminal-Bench 2.1 / 3.0 / 4.0, LiveCodeBench, SciCode, DeepSWE, Vibe Code Bench: no verified public score found for this checkpoint. (The 2.1 figure of 62.9% belongs to the 1.1 successor.)
- Coding composite (llm-stats): **19.8** (#96 of 5 evals) — low; GLM-5 at 26.1 (#62) beats it on both shared benchmarks.

Reasoning / knowledge (all Microsoft-reported — **all newly found this pass**):

- **GPQA Diamond: 84.6%**, **9.6K tokens** — vs Claude Haiku 4.5 **73.2%** at 14.6K. The first pass recorded "no verified public score found" for this benchmark; the figure exists, it is simply vendor-measured.
- **HLE (text): 18.0%**, 26.3K tokens — vs Haiku 4.5 **9.5%** at 22.2K. Also absent from the first pass. 18% is well above the <10% floor that `model-comparison.md` uses for the 55–65 band but far below the 40%+ frontier anchor.
- **Frontier Science: 58.2%**, 20.5K tokens — vs Haiku 4.5 42.3% at 24.1K.
- **AIME 2026: 92.5%**, **23.6K tokens** — vs Claude Haiku 4.5 **83.3%** at 30.3K. (First pass had this at 92.5%; correct, but the +9.2 point lead and the token advantage were not noted.) Independent rank 25 of 36 (31st percentile), −7.4 points vs Claude Fable 5 at 99.9.
- MMLU / MMLU-Pro, CritPt, Omniscience, Artificial Analysis Intelligence Index: still **no verified public score found** for this checkpoint.
- LongFact / GraphWalks / AIR-Bench: **not published for this model.** llm-stats attributes LongFact 98.0, GraphWalks 90.0 and AIR-Bench 88.0 to **MAI-Thinking-1**, a different model; those numbers remain explicitly excluded. (They are genuine — BenchLM now lists Graphwalks BFS 128K 90% against the *MAI-Thinking-1* technical report — which is precisely why they must not leak into this file.)

Agent / tool use (the **τ²-Bench row is the second major new finding this pass**):

- **τ²-Bench (agentic tool use), telecom domain: 71.7%** — published for the first time, on the official model card, in the section titled *"Instruction following and agentic tool use."* The card's table also shows a second adjacent value of **54.7%**; the excerpted rendering does not make clear whether that is the cross-domain average, a second domain, or a harness-level figure, so **both are recorded and neither is merged into a single score**. The first pass asserted "Tau3-Banking / Tau2-Bench: no verified public score found" — that is now falsified for the telecom domain specifically. τ²-Bench is the tool-use benchmark `model-comparison.md` treats as a primary tool-use input, and a 71.7% telecom-domain result would sit in the frontier band *if* it were representative; one domain out of a multi-domain suite is not.
- **Robust IF Bench (internal, diverse hard instruction following): 61.2%**, 45K tokens — a Microsoft-internal eval, no external comparator. Unverifiable by construction; recorded, not scored.
- **Advanced IF (rubric-based instruction following): 71.4%**, 56.9K tokens — the first pass described a "+14.5 points over Haiku 4.5" claim; the card gives **no Haiku column for the IF block at all**, only the model's own 75.0 / 71.4 / 61.2. The "+14.5 vs Haiku 4.5" figure appears to come from the launch blog rather than the card and could not be re-verified against a competitor number this pass.
- **IFBench: 75.0%**, 46.1K tokens — confirmed on the card. First pass called this "field leader (1 of 1, 100th percentile)"; that percentile is an aggregator artefact of a one-model field and is not a claim about the model.
- Tool calling is a first-class design target ("agentic tool use" is an enumerated primary use case on the card).
- Terminal-Bench 2.0 54.8% remains the only other agentic-terminal figure.
- Tau3-Banking, GDPval-AA, OSWorld, AutomationBench, Claw-Eval / ClawProBench, Toolathon, MCP-Atlas, SWE Atlas Codebase QnA: **no verified public score found.**
- Agents composite (llm-stats): **10.9** (#101 of 2 evals); GLM-5 at 19.2 (#57) leads it.
- Independent user reports in the GitHub community thread (June–July 2026) are mixed-to-negative in a way no benchmark captures: reports of slow peak-hour responses, difficulty with Plan mode, and outright failure on mature multi-part codebases. Anecdotal, but consistent with a small, fast, deliberately concise model.

Long context:

- **256K context / 128K max output**, now confirmed by the vendor's own model card and by OpenCode's model data. **Still no long-context retrieval benchmark** — no MRCR, RULER, LongBench or AA-LCR exists for this model. The 60%-fewer-tokens behaviour is tuned for concision, which is orthogonal to (and arguably in tension with) long-context depth.

Instruction following and safety:

- Microsoft's own documentation states that accuracy on core adversarial categories, **"such as the Einstellung trap," remains below 50%** — an explicitly acknowledged weakness, relevant to any autonomous deployment.
- **ECI (BenchmarkList composite): 138.56, #42 of 398** overall, and **#10 of 158 among open-weight-comparable models** — a respectable mid-field composite in a very crowded ranking.

### Normalized scores (1–100)

- **Tool use: 78/100** *(up from 70).* The load-bearing new evidence is the **τ²-Bench telecom result of 71.7%** published on Microsoft's own model card — the single benchmark family `model-comparison.md` weights most heavily for tool use after Terminal-Bench, and the one the first pass recorded as absent. It is joined by **Terminal-Bench 2.0 at 54.8%**, **IFBench 75.0%** and **Advanced IF 71.4%**, plus tool calling trained on the live Copilot harness. Still held well short of the 90–100 band because *all* of it is Microsoft-measured in an internal harness, only one τ²-Bench domain is published, the second τ² figure (54.7%) is of unclear meaning, and there is still no GDPval-AA, OSWorld, AutomationBench, Claw-Eval, MCP-Atlas or Toolathon number from anyone.
- **Reasoning: 78/100** *(up from 65 — the biggest move in this report).* The first pass scored a 5B-active model on AIME alone and explicitly recorded "no verified public score found" for GPQA Diamond and HLE. Both exist: **GPQA Diamond 84.6%** (vs Haiku 4.5's 73.2%) and **HLE 18.0%** (vs 9.5%), alongside **Frontier Science 58.2%** and **AMO Bench 40%**, all on the vendor's model card. GPQA in the mid-80s with a +11.4 point lead over a frontier-class small model is a real measured capability, not a claim. Capped below 85 because every one of these numbers is vendor-run in an unspecified internal harness, because **MMLU-Pro, CritPt and Omniscience remain entirely unpublished**, and because Frontier Math Tier 1–3 at 6.3% shows the ceiling is real.
- **Context window: 80/100** *(up from 78).* **256K** is no longer a source-disputed figure: the official model card states "Context length 256K tokens" and OpenCode's model data gives 256K / 128K max output. The first pass's CloudPrice-based 128K caveat is retired as an outlier. Held at 80 rather than higher because **no retrieval benchmark of any kind exists** — no MRCR, RULER, LongBench or AA-LCR — so effective long-context quality is entirely unmeasured, and because 256K is upper-mid, not top tier.
- **Multimodal: 15/100** *(unchanged).* **Text-only**, now confirmed by the model card itself (`Inputs Text` / `Outputs Text`) rather than by two third-party aggregators. Floor score by methodology. ArtifactsBench is an *output-side* multimodal evaluation of code-generated artifacts — it is not image input, and the new token-usage column does not change that. One correction carried forward: against Claude Haiku 4.5 the model is 36.4% vs 36.6%, i.e. marginally behind, not ahead.
- **Coding: 76/100** *(up from 74).* The pass-rate figures are unchanged — SWE-bench Verified 71.6%, SWE-bench Pro 51.2%, SWE-bench Multilingual 65.5%, Terminal-Bench 2.0 54.8% — but the newly surfaced **token-usage column** is genuine new evidence about coding *productivity*: 10.8K tokens per SWE-bench Verified solve versus Haiku 4.5's 27.3K, and 28.0K vs 29.8K on the much harder Pro set. A model that solves a comparable fraction of tasks for a quarter of the tokens is materially better as a daily driver, which is the axis the first pass had only as an unquantified marketing claim. Still far below frontier: **13th-percentile ranks on both SWE-bench Pro and SWE-bench Multilingual**, −87.5 and −84.4 point gaps to Fable 5.1 and Opus 5, 24th-percentile SWE-bench Verified rank, and a coding composite of 19.8 (#96).
- **Cost efficiency: 87/100** *(unchanged — deliberately).* **$0.75 in / $4.50 out with $0.075 cache reads** sits near the ~$1.25/$4.25 reference point (~88). The token-usage column this pass surfaced is real money: at 10.8K tokens per SWE-bench Verified task against Haiku 4.5's 27.3K, effective per-task cost is roughly a quarter of the headline tariff suggests. **The score is deliberately not changed by the 2026-09-10 deprecation.** The methodology scores the inverse price of the evaluated tier, and the list price of that tier has not moved — what changed is that the tier closed. Deprecation is an access fact, and it is recorded as one, in the Model card and the Retired-model note above. Anyone weighting availability separately from price should treat this model as unavailable at any price.
- **Overall Score: 65/100** *(was 60).* Arithmetic: **(78 Tool + 78 Reasoning + 80 Context + 15 Multimodal + 76 Coding) / 5 = 327 / 5 = 65.4 → 65.** Cost efficiency (87) is excluded by the v4 rule. Best fit, stated plainly: **there is no live fit — the model was deprecated on 2026-09-10.** Read this report as a historical record of a model that was genuinely better than Claude Haiku 4.5 per token and worse than it per hard-task, with an 84.6% GPQA Diamond that no aggregator had surfaced. If you are choosing a Copilot coding model today, choose **MAI-Code-1.1-Flash** — quarter the price, image input, higher on both published benchmarks — and check Microsoft's own acknowledged Einstellung-trap weakness if you plan to deploy any of them autonomously.
