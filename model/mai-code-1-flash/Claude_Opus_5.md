## Model card

- **Name:** MAI-Code-1-Flash
- **Short description:** Microsoft AI's **Copilot-native coding model**, "built end-to-end by Microsoft" by its Superintelligence team and **trained in Copilot's actual production environment**. Its distinguishing feature is not a headline score but an evaluation stance: Microsoft benchmarked it "in the **same VS Code-based harness used to evaluate production GitHub Copilot workflows**. Pass rates are measured **end to end, with repository context, tool calls, and verification included, rather than in a stripped-down benchmark environment**" ([MAI-Code-1-Flash model card](https://microsoft.ai/pdf/MAI-Code-1-Flash-Model-Card.PDF)). The efficiency claim is the other headline: it "solves harder problems with **up to 60% fewer tokens**". Distinct model; `mai-code-1.1-flash` (the successor) and `mai-thinking-1` have their own folders, and MAI-Voice / MAI-Transcribe belong in `models_voice/`.
- **Provider / access:** **GitHub Copilot in VS Code** — notably "available now on **Free, Pro, Pro+, and Max Copilot tiers**" — plus API access and **OpenCode Zen**. Proprietary; no open weights.
- **Release / knowledge:** **2026-06-02** ([Microsoft AI announcement](https://microsoft.ai/news/introducingmai-code-1-flash/)). Knowledge cutoff: no verified public date found.
- **IDs:** `mai-code-1-flash` (Microsoft AI, GitHub Copilot, Zen). **No Zen free ID**, though the model is reachable through Copilot's Free tier.
- **Context window:** **256,000 tokens** with **128,000 max output** — the 256K figure is corroborated by LLM Reference and APIMart.
- **Modalities:** **Text in → text out only.** No image, audio or video. Reasoning: **yes — "adaptive thinking"**, i.e. the model varies its reasoning budget by problem difficulty, which is the mechanism behind the 60%-fewer-tokens claim. Tool calls: yes, and central — the benchmark harness exercises them by design.
- **Pricing (as of 2026-10-08):** **$0.75 / MTok input, $4.50 / MTok output, $0.075 / MTok cached input** (a 10× cache discount). The output rate is high for a tier labelled "Flash".
- **Architecture:** **Sparse Mixture-of-Experts with adaptive thinking** (APIMart). Microsoft publishes no parameter count; **Poolside's Laguna XS 2.1 comparison table lists it at 137B total**, which is the only figure I found and is third-party rather than vendor-confirmed.

### Raw benchmarks found

> ⚠️ **A transparency problem worth stating plainly.** Microsoft evaluated this model "against Claude Haiku 4.5 on SWE-Bench Verified, SWE-Bench Pro, SWE-Bench Multilingual, and Terminal Bench 2 using the same production harness" — but **published an exact figure for only one of the four**. As LLM Reference puts it: Microsoft "reports 51.2% on SWE-bench Pro versus 35.2% for Claude Haiku 4.5 in the same Copilot harness, plus **stronger results on SWE-bench Verified, SWE-bench Multilingual, and Terminal-Bench 2.0 without publishing exact scores for those secondary benchmarks**." Claiming four wins and showing one number is not good practice, and I score it accordingly.
>
> `benchlm.ai/md/models/mai-code-1-flash.md` returns **404**, and I found no Artificial Analysis or Vals AI page. The three otherwise-unpublished figures below come from **Poolside's Laguna XS 2.1 model card**, which states it "used the **highest publicly-referenced scores for all comparison models**… official scores published in release blog posts or equivalent". That chain is worth trusting here for one specific reason: **Poolside's SWE-bench Pro entry for this model is 51.2%, matching Microsoft's own published figure exactly**, which validates the rest of the row.

Coding — the model's entire purpose:

- **SWE-bench Pro: 51.2%** (Microsoft, production Copilot harness) — against **Claude Haiku 4.5 at 35.2%** in the same harness, a **+16.0-point margin**
- **SWE-bench Verified: 71.6%** (via Poolside's comparison table)
- **SWE-bench Multilingual: 65.5%** (via Poolside's comparison table)
- **Terminal-Bench 2.0: 54.8%** (via Poolside's comparison table) — a strong figure on a harness where most models in this dataset land in the 20s–30s
- **85.8% on Microsoft's own adversarial benchmark** (reported by ChatForest) — the benchmark itself is unnamed and unspecified, so this is recorded but not weighted
- **Efficiency: "up to 60% fewer tokens"** on hard coding tasks
- **No LiveCodeBench, DeepSWE or SciCode figure found**

**Absent entirely:** no GPQA Diamond, MMLU-Pro, AIME, HLE, ARC-AGI, CritPt, Omniscience or hallucination measurement; no GDPval, Toolathlon, BFCL, τ²-bench, MCP-Atlas or BrowseComp; and **no MRCR, RULER or AA-LCR figure at any depth** despite a 256K window.

### Normalized scores (1–100)

- **Tool use: 72/100.** **Terminal-Bench 2.0 at 54.8% is a genuinely strong agentic-terminal result** — well above most of this dataset — and it carries unusual weight because of *where* it was measured. Microsoft's harness includes "repository context, tool calls, and verification" end to end, so the tool loop is part of the test rather than abstracted away; a model scoring 54.8% under those conditions is doing real agentic work, not benchmark-shaped work. The unnamed **85.8% adversarial benchmark** hints at robustness testing but cannot be weighted without knowing what it measures. Capped because there is **no GDPval, Toolathlon, BFCL, τ²-bench, MCP or BrowseComp figure at all**, and because the Terminal-Bench number reaches me via a third party rather than from Microsoft.
- **Reasoning: 50/100.** Essentially unmeasured, and that is a deliberate product decision rather than a hidden weakness. **There is no GPQA, MMLU-Pro, AIME, HLE, ARC-AGI or CritPt figure** — Microsoft positioned this as a coding specialist and published only coding evaluations. The one real signal is indirect but meaningful: **"adaptive thinking" delivering up to 60% token reduction on hard problems** implies the model allocates reasoning effort well rather than thinking indiscriminately, and that 51.2% SWE-bench Pro is not reachable without genuine multi-step reasoning. Scored at the midpoint on inference, with no credit for unmeasured breadth.
- **Context window: 58/100.** **256,000 tokens with 128,000 max output** is a solid specification, and the large output allowance matters for a coding model generating multi-file diffs. The harness design means long context is implicitly exercised — repository context is loaded in every benchmark run — but **implicit use is not measurement: there is no MRCR, RULER, AA-LCR or needle figure at any depth.** Scored on a good spec with no verified recall quality.
- **Multimodal: 15/100.** Text in, text out. No image, audio or video input and none claimed — a reasonable scope decision for a Copilot coding model, but the template floor applies.
- **Coding: 82/100.** The strongest dimension and the best-justified score in this report. **SWE-bench Pro at 51.2% is high in absolute terms**, and the **+16.0-point margin over Claude Haiku 4.5 measured in the identical harness** is a cleaner comparison than most cross-vendor claims because the harness variable is held constant. **SWE-bench Verified 71.6%, SWE-bench Multilingual 65.5% and Terminal-Bench 2.0 54.8%** complete a coherent four-tier picture. Crucially, these were measured **end to end in production Copilot conditions "rather than in a stripped-down benchmark environment"** — that is a harder test than a bare SWE-bench harness, so these figures understate rather than flatter. Add **60% fewer tokens on hard problems** and this is a well-engineered coding model. Capped below the mid-80s for two honest reasons: **Microsoft published only one of its four claimed results**, and three of the four figures reach me through Poolside's table rather than from the vendor.
- **Cost efficiency: 62/100.** Mixed. **$4.50 / MTok output is expensive for a "Flash" tier** — six times its input rate and well above the sub-dollar output pricing of comparable open-weight coding models in this dataset. Three things pull the other way, and they are substantial: the **10× cached-input discount at $0.075** rewards the repeated-context pattern that coding agents generate constantly; **"up to 60% fewer tokens" on hard tasks is a direct multiplier on effective cost**, and it is the vendor's own headline claim rather than an inference; and **the model is reachable on GitHub Copilot's Free tier** as well as Pro, Pro+ and Max, so a large population accesses it at no marginal cost. Docked for the output rate, for being fully proprietary with no open weights, and for having no Zen free ID.
- **Overall Score: 55.4/100.** Mean of the five non-cost dims (72 + 50 + 58 + 15 + 82) / 5 = 55.4. The text-only floor and the unmeasured reasoning dimension hold the mean below what the coding results alone would support; this is a specialist and should be read as one. Best fit: **agentic coding inside GitHub Copilot and VS Code** — repository-scale patching, multilingual fixes, terminal-driven tasks and high-volume iterative development where the 60% token reduction and the 10× cache discount compound across a long session. The thing most worth respecting is the evaluation philosophy: **measuring end to end in the production harness, with repository context and verification included, is harder and more honest than a stripped-down benchmark run**, and it makes 51.2% SWE-bench Pro and 54.8% Terminal-Bench 2.0 more credible than the same figures from a bespoke rig. The thing most worth criticizing is the opposite: **claiming wins on four benchmarks while publishing a number for one** leaves three quarters of the case resting on a competitor's comparison table.
