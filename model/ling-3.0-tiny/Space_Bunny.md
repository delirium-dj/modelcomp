## Model card

- **Name:** Ling-3.0-tiny
- **Short description:** InclusionAI's (Ant Group) **lightweight edge model** — **7.9B total / ~1.3B active** sparse MoE, released **2026-08-06** under MIT. Its purpose is to bring reasoning and agentic capability to **local and resource-constrained deployment**: validated on **NVIDIA DGX Spark, Apple Silicon MacBook and Mac mini**, needing only **~8.34 GiB peak memory at 8K context** (or **4.2 GB** as a 4-bit MLX build, or 4.82 GB as Q4_K_M GGUF). It inherits the Ling 3.0 hybrid linear attention stack while being specifically re-optimized for footprint. Top use case: on-device and edge agents, routing and classification layers, lightweight tool-using assistants, and local OpenClaw / Claude Code style workflows.
- **Provider / access:** Hugging Face `inclusionAI/Ling-3.0-tiny` (**MIT**; BF16, plus official `-fp8` (serialized block FP8) and `-int4` (compressed-tensors INT4) checkpoints — the vLLM recipes confirm all three are served and all share `BailingMoeV3ForCausalLM`); official **GGUF** (`inclusionAI/Ling-3.0-tiny-GGUF`, Q4_K_M 4.82 GB / Q5_K_M 5.64 GB / Q6_K 6.5 GB / Q8_0 8.41 GB / BF16 15.8 GB, `bailingmoe3`) and a community **MLX 4-bit** conversion (`rapid-mlx/Ling-3.0-tiny-MLX-4bit`, 4.2 GB, reference parity 1.5e-6); the highest-volume community GGUF is now **`bloomer010/Ling-3.0-tiny-GGUF` at 260,531 downloads last month**, up from the 37,304 the first pass recorded for the official repo; ModelScope; **OpenRouter** `inclusionai/ling-3.0-tiny`; Novita AI; Vercel AI Gateway. Self-host via SGLang, vLLM, **llama.cpp, MLX** and — **new this pass** — **Ollama**: the official cookbook now publishes an **"Ollama On-Device Deployment Guide"** for Ling-3.0-tiny on Apple Silicon (INT4 / FP8 / BF16), built from `ollama/ollama#17643`, with the honest caveat that "support is currently provided by ollama/ollama#17643 and is limited to running via MLX on Apple Silicon… **not yet included in the official Ollama release**." No OpenCode Zen ID found.
- **Release / knowledge:** Released **2026-08-06** (OpenRouter, Requesty, aimlapi); HF card last revised 2026-09-24; Novita's listing and an independent test log both date it 2026-08-10, and bartowski's GGUF conversion landed 2026-08-18. Knowledge cutoff: not disclosed.
- **IDs:** `inclusionAI/Ling-3.0-tiny` (HF), `inclusionai/ling-3.0-tiny` (OpenRouter/Novita)
- **Context window:** **The first pass's 131,072-native credit is now confirmed and the 256–262K hosted figure is explained.** The **vLLM recipes** state that all three served checkpoints (BF16/FP8/INT4) "use the same `BailingMoeV3ForCausalLM` architecture and a **native 131,072-token context window**," and the bloomer010 GGUF card independently confirms "**131,072-token context in the released configuration.**" The 256–262K figure comes from the **official HF card's YaRN recipe** (`SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1`, `rope_type: yarn, factor 2.0, original_max_position_embeddings: 131072`, `--context-length 262144`) — i.e. **131,072 native / 256K via YaRN**, the same structure as `ling-2.6-flash`. Max output **32,768** (33K on aggregators).
- **Modalities:** **Text in → text out only.** Every distribution channel — HF, GGUF, MLX, llama.cpp, Ollama, OpenRouter, Novita — lists text→text. Reasoning: **yes, native chain-of-thought with thinking mode configurable per request** via `enable_thinking` / a `detailed thinking on/off` system-prompt switch, giving switchable "thinking" and "instant" modes. Tool calls: **native function calling** (parsed natively by rapid-mlx). Prompt caching: yes. Recommended sampling: temperature 1.0, top_p 0.95, top_k 20.
  - **Aggregator error flagged:** Requesty lists this model as "Proprietary… served through InclusionAI's own API and licensed cloud," with "Not supported: Reasoning, Tool use, Structured output" on ModelCap. Both are catalogue-generation errors. The weights are **MIT on Hugging Face**, and the official card, the vLLM recipes, the MLX conversion and the HF card's own Terminal-Bench protocol note all describe reasoning and tool calling as native. **Do not let those two aggregators override the vendor repo.**
- **Pricing (as of 2026-10-17):** **$0 in / $0 out / $0 cache** on Novita per Requesty (updated 2026-10-17) and **$0.00 blended** on AA's InclusionAI provider page — where it ranks **#1 lowest price of all five InclusionAI models**. **But** see the free-tier warning above: Novita delisted the model on 2026-08-14, LLMTR shows it retired 2026-08-15, and Kilo removed it from its free list on 2026-10-13. **MIT open weights make local deployment the durable zero-cost path**, in 4.2 GB (MLX 4-bit) or 4.30–4.82 GB (GGUF).
- **Architecture:** **7.9B total / ~1.3B active** sparse MoE. Ling 3.0's hybrid linear attention as a **3:1 KDA–MLA stack** (24 layers = 18 Kimi Delta Attention + 6 Multi-Head Latent Attention). Sparse MoE FFN with **128 routed experts, 8 routed + 1 shared activated per token**. First layer dense (`first_k_dense_replace: 1`); hidden 1,536; 16 Q / 16 KV heads (**MHA, no GQA**); **Q-LoRA rank 256 and KV-LoRA rank 512** (this is the detail that breaks most llama.cpp builds — see below); QK-norm enabled; expert FFN intermediate 512; vocabulary 157,184. GGUF architecture `bailingmoe3` (`BailingMoeV3ForCausalLM`). **`num_nextn_predict_layers: 0`** — this model ships **no MTP head**, so there is no speculative-decoding draft model in any format (the first pass said only "no speculative drafter exists").
- **Active-parameter discrepancy, still flagged and still unresolved:** the official model card says **1.3B active per token**; the SGLang cookbook said ~1.2B; an independent llama.cpp derivation said ~0.8B. **1.3B (official) is used throughout.**
- **NEW llama.cpp caveat, load-bearing for anyone planning a local setup.** `bailingmoe3` merged upstream on **2026-08-17**, and the two PRs that make *agentic* use reliable — the dedicated Ling parser **#28682 (merged 2026-09-19)** and invalid-UTF-8 handling in the PEG parser **#29161 (merged 2026-09-20)** — both landed in September. bloomer010's card states that before both, "tool calls inside an unclosed think block are dropped and some turns fail with a 500." Separately, a ROCmFP4 GGUF repo reports that **stock llama.cpp still will not load this model**, because `bailingmoe3` support lives in an unmerged PR (#26608) and this checkpoint additionally needs the **Q-LoRA attention path** (`q_lora_rank: 256`) that builds written for Ling-3.0-flash lack — the failure mode is `missing tensor 'blk.0.ssm_f.weight'`. **Practical rule: use a build with both `bailingmoe3` and the Q-LoRA path, and note that the ROCmFP4 quant types require a fork regardless.** Also recorded by bloomer010: **"The model does occasionally terminate its response, mid-think, without any sort of closing. This is inherent in the weights, even at full precision."** That is an independent, reproducible observation about the checkpoint itself and it is a genuine reliability concern for agentic loops.

### Raw benchmarks found

> **The first pass's central conflict is resolved: Artificial Analysis has now measured this model directly.** The card claimed **AA Intelligence Index v4.1.1 = 25** and **AA Agentic Index = 16**; AA's provider page showed **Index 11**. This pass finds the measured current values: **AA Intelligence Index 11.06** (Vector Wire, 2026-10-16; ModelCap 11.1 #119 of 134) and **AA Agentic Index 7.06** (2026-09-09) / **4.4** (OpenRouter's AA block, 2026-10-15). The 25 was a **v4.1.1-era figure on a composite that has since been reweighted twice (now v4.3.2)**; the 16 was likewise a superseded Agentic Index. **The first pass preferred the card's 25 over AA's 11 — that preference was wrong and is reversed here.** aimlapi's 11.9 (2026-09-12) and AIToolsReview's 25 (which also quotes 154.1 t/s and ~210M tokens as "very verbose") are both launch-week or stale snapshots.

Reasoning / knowledge — **all independent (Artificial Analysis), all new this pass**:

- **GPQA Diamond: 73.43%** — genuinely respectable for a 7.9B/1.3B-active model, and the strongest row it has.
- **Humanity's Last Exam: 9.31%** — very low, consistent with the family.
- **CritPt: 0.00%** — a clean zero on research-level physics.
- **SciCode: 24.19%** (#36% of the field leader).
- **AA Intelligence Index: 11.06** — vs Claude Opus 5.5 at 57.6, GLM-5.3 at 44.8, and Ling 3.0 Flash at 20.1 on the same provider page.
- **AA-Omniscience: −19.35**, with **Accuracy 8.52% (13% of the leader)** and **Non-Hallucination Rate 69.54% (79% of the leader)**. The hallucination-avoidance behaviour is actually its best factuality number; knowing the right answers is not.
- MMLU-Pro / AIME / MATH / CritPt-independent / long-context retrieval beyond AA-LCR: **no verified public score found**.

Agent / tool use:

- **AA Agentic Index: 7.06** (2026-09-09) / **4.4** (2026-10-15). **Conflict recorded; both are very low.** Compare the same AA page's Ling 3.0 Flash at 19.3–21.0 and Ling 3.1 Flash at 41.
- **τ-Bench V3 Banking: 20.82** (41% of the field leader) — the only agentic *task* row.
- **GDPval (win rate): 3.07** (3% of the leader) — near-total failure on professional knowledge work.
- **Terminal-Bench 4.0: 0.00%** — a clean zero, tied with Ling 3.0 Flash at #56 of 92 in the AA terminal-agentic ranking.
- **Terminal-Bench 2.1: 27.72%** (30% of the field leader); ModelCap ranks it **#80 of 128**. Note the **official card already publishes a Terminal-Bench 2.1 protocol** (AA protocol, Terminus 2, 2-hour timeout, preserve-thinking JSON parser, 3 runs/task, temperature 1.0, max_new_tokens 32K, 256K context) without publishing the resulting number — a name-only claim of the kind this report flags everywhere else.
- **Independent community free-tier sweep — a striking and important positive.** Ben Ebsworth's harness ran 13 OpenRouter free-tier models across 7 tasks × 5 iterations (84 runs, $0.00 total). **Ling 3.0 Tiny averaged 99.4, tied first, beating Kimi K3's 90.5**, with per-task scores of 100 / 95.5 / 100 / 100 / 100 / 100. **But every single task carries a `partial` flag** — at least one of the five iterations returned empty or truncated content — and the write-up states the free tier "is rate-limited per provider, not per request, and the limits are tight. Several models returned empty responses or 429s on two of every five iterations." **So: the model is capable on short, well-scoped tasks; the free route is unreliable.** Both halves belong in the score.
- **Local community quality sweep (llm-bench.io, `inclusionAI/Ling-3.0-tiny-GGUF:Q4_K_M`): overall quality 54.5/100**, with **Agent Workflow 69.4** (P5 63.7 / P95 75.0), Research & Analysis 61.4, Role Play & Narrative 68.6 — and **Code Generation 18.8** (P5 1.9 / P95 35.6). The agentic number is the best tool-use evidence this model has.
- BFCL / τ²-bench / GDPval-AA / AutomationBench / MCP-Atlas / Claw-Eval / Toolathon: **no verified public score found**.

- **SciCode: 24.19%** *(AA)*. **AA Coding Index: 26.54** *(AA, frozen 2026-09-09)*. **Terminal-Bench 2.1: 27.72%** *(AA)*. **Terminal-Bench 4.0: 0.00%** *(AA)*.
- SWE-bench Verified / Pro / Multilingual, LiveCodeBench, DeepSWE, HumanEval: no verified public score found. Tool calling is supported, which is necessary but not sufficient.

Multimodal:

- **Text-only**, confirmed by every distribution channel including the new Ollama path. No image, audio, video or PDF input; no non-text output. No multimodal benchmark exists.

Long context:

- **131,072 tokens natively (128K)** per the vLLM recipes and the bloomer010 GGUF card; **256K via the official YaRN recipe**; 256–262K as listed by API providers.
- **NEW: AA-LCR v1.1 = 60.33** (Vector Wire, 2026-10-16, 68% of the field leader) — **the first retrieval benchmark ever measured for this model.** It is mediocre: Ling 3.0 Flash scores 73.0 on the same benchmark.
- **Still standing from the first pass, and not contradicted:** an independent llama.cpp SYCL benchmark (2026-08-21, b10566, isolated card, 20 runs) measured prefill throughput that **peaks at 2K tokens (2,293 tok/s) and then falls ~47% to 1,218 tok/s at 12K** — while *every* model in the same sweep on the same build and card **rose** monotonically (LFM2.5-8B-A1B 2,667→3,665; Qwen3.8-9B-Distill 1,914→2,020; Ornith 1.5-9B 1,910→1,987; Nemotron 30B-A3B 1,536→1,772). The test author calls this "the disqualifier."
- **Also relevant and new:** llm-bench.io's runs topped out at a **65,536-token** context, and the ROCmFP4 build verified 32,768 was granted but explicitly recorded that "**nothing exercised rope/KV behaviour at depth, and nothing was run near the model's 131,072 ceiling.**" **No one has meaningfully tested this model's long-context behaviour, and the one careful test found it degrading.**

Speed / deployment (measured, and this model's real strength):

- FP8: **~100–105 tokens/s on NVIDIA DGX Spark**, **86–90 tok/s on an M4 Pro MacBook** (InclusionAI's own figures). FP8 peak memory **~8.34 GiB at 8K context**. The HF card's recommended low-latency recipe adds **built-in MTP / NEXTN speculative decoding on 1× 141GB-class GPU** — note the `num_nextn_predict_layers: 0` finding above means there is no draft head to exercise on this checkpoint.
- GGUF Q4_K_M (llama.cpp, SYCL): **91.86 tok/s median decode**, **5.72 GiB peak VRAM** (first pass, not contradicted).
- New community ROCmFP4 GGUF on AMD gfx1151 (Ryzen AI MAX+ 395 / Strix Halo): **104.04 tok/s median at 4.30 GiB** (4-bit COHERENT) and **88.8–89.5 tok/s at 7.6–7.7 GiB** for the 8-bit builds, verified on two independent machines — **the fastest measured decode for this model anywhere.**
- llm-bench.io (RTX 2060, Q4_K_M): **55.7 tok/s peak, 44.3 tok/s average**, 472.9 tok/s prompt, TTFT 1.28 s, 3.4 GB.
- MLX 4-bit on Apple Silicon: **4.2 GB at 4.507 bits/weight**, fits and runs on an 8 GB MacBook.
- **Hosted speed is a different story and the first pass did not record it:** AA's provider page lists a **median 15 tok/s with 30.24 s to first chunk and a 193.40 s total response** for Ling 3.0 Tiny — an order of magnitude slower than the local numbers and slower than every other InclusionAI model. **This is a case where running it locally is dramatically better than renting it.**

### Normalized scores (1–100)

- **Tool use: 45/100** *(was 58).* The first pass scored 58 on native function calling plus "AA Agentic Index 16" — and that 16 is now superseded. **AA's measured Agentic Index is 7.06 (2026-09-09) or 4.4 (2026-10-15); both are near the floor.** The independent task rows agree: **Tau3-Bench V3 Banking 20.82**, **GDPval win rate 3.07**, **Terminal-Bench 2.1 27.72**, **Terminal-Bench 4.0 0.00%**. There is still no BFCL, τ²-bench, GDPval-AA, AutomationBench, MCP-Atlas or Claw-Eval row. Held at 45 rather than lower for two genuine positives: the **independent community local-agentic score of 69.4/100**, and the **Ben Ebsworth free-tier sweep at 99.4 average (best in cohort, above Kimi K3's 90.5)** — though that second result carries a `partial` flag on all seven tasks, i.e. the model delivered empty or truncated content on at least one of five iterations every single time. **Native function calling plus a 69.4 local agentic score is real; it is just not an agentic model at scale.**
- **Reasoning: 52/100** *(was 66 — the largest single correction in this report).* The first pass anchored on the model card's "AA Intelligence Index v4.1.1 = 25" and called it "genuinely impressive for a model activating ~1.3B parameters per token — on par with InclusionAI's own 124B/5.1B Ling-3.0-flash," while flagging but not penalising AA's contrary 11. **Reversing that preference was the right call: AA's measured current Index is 11.06**, on a composite (v4.3.2) that has been reweighted twice since the card was written. Under `model-comparison.md`'s bands — "Mid: GPQA 60–80% … Index 20–35 → 55–65" — the GPQA Diamond **73.43%** genuinely lands in the mid band while the Index sits *below* it. **CritPt 0.00%**, **HLE 9.31%**, **Omniscience Accuracy 8.52%** and **SciCode 24.19%** are all weak, and the one bright knowledge-adjacent factuality row is the 69.54% non-hallucination rate, which is a different capability from knowing answers. 52 reflects "solid exam-style science reasoning for 1.3B active parameters, poor frontier knowledge reliability."
- **Context window: 66/100** *(was 68 — a small downgrade).* **131,072 native is now confirmed twice** (vLLM recipes and the bloomer010 GGUF card), and the 256K figure is explained as the official YaRN recipe rather than a native window — so the first pass's conflict resolution was right. The downgrade is because the **first actual retrieval measurement for this model now exists and is mediocre: AA-LCR 60.33 (68% of the field leader)**, against Ling 3.0 Flash's 73.0. It cannot go higher than 66 because (a) no retrieval benchmark reached 100K+ in any run anyone has published — llm-bench.io topped out at 65,536 and the ROCmFP4 test explicitly recorded that nothing was run near the 131,072 ceiling — and (b) **the one careful long-context test found prefill throughput collapsing ~47% between 2K and 12K while every peer in the same sweep improved**, which makes the advertised window materially less useful than the number suggests.
- **Multimodal: 15/100.** Unchanged — **text-only**, confirmed by HF, GGUF, MLX, llama.cpp, the new Ollama path, OpenRouter and Novita alike. Floor score by methodology. InclusionAI's vision-capable members are `Ling-3.0-flash-VL` (itself retired 2026-09-22 by one gateway) and `Ming-Flash-Omni`, both different models.
- **Coding: 42/100** *(was 52).* Downgraded, because the dimension the first pass flagged as "rests on almost nothing" now rests on measurement, and the measurement is bad. **Code Generation 18.8/100** in an independent local sweep (P5 **1.9**, P95 35.6 — a spread so wide that single runs are nearly meaningless), **SciCode 24.19%**, **Terminal-Bench 2.1 27.72%**, **Terminal-Bench 4.0 0.00%**, **AA Coding Index 26.54**. The 4-bit quantization makes it worse still. **This was the one dimension where the first pass explicitly warned you not to select the model on the strength of the report, and it turns out that warning was correct.** Nobody should pick this model for coding.
- **Cost efficiency: 97/100** *(was 99).* **MIT weights in 4.2 GB (MLX 4-bit) or 4.30–4.82 GB (GGUF), running at 104 tok/s on an AMD APU, 92 tok/s on a SYCL card, 86–90 tok/s on an M4 Pro, or 45–56 tok/s on a six-year-old RTX 2060**, plus a $0.00 blended hosted price on AA's provider page — this is still the cheapest route to a reasoning-capable, tool-calling model into any pipeline, and **260,531 monthly GGUF downloads** attest that people actually use it that way. The point lost is durability of the *hosted* free tier: **Novita delisted the free listing on 2026-08-14 after three days**, LLMTR shows it retired 2026-08-15, and Kilo dropped it on 2026-10-13 — while Requesty still advertises it at $0. Also worth weighing: **AA measures the hosted route at a median 15 tok/s with a 193 s total response**, which is far slower than running the same weights locally. **The local path is the cost-efficiency story; the hosted free tier is a fragile bonus.**
- **Overall Score: 44/100.** `(Tool 45 + Reasoning 52 + Context 66 + Multimodal 15 + Coding 42) / 5 = 220 / 5 = 44.0 → 44`. Best fit: **on-device and edge agents** — local tool-calling assistants, routing and classification layers, lightweight document work, and privacy-sensitive workloads where a 4–8 GB footprint and 100+ tok/s on consumer hardware matter more than benchmark leadership, and where the community local agentic score of 69.4/100 and the free-tier sweep's 99.4 average both point the same way. **$0 hosted with MIT weights** is still the cheapest way to get a reasoning-capable tool-calling model into a pipeline. Not the pick for coding (18.8/100 local, Terminal-Bench 4.0 = 0%), for hard agentic loops (Agentic Index 4.4–7.06, GDPval 3.07%), or for long-document work (AA-LCR 60.33, and the measured prefill collapse between 2K and 12K). **Treat the hosted free tier as unreliable and possibly gone; the local path is the durable answer.**
