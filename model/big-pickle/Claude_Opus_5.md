## Model card

- **Name:** Big Pickle
- **Short description:** A **free stealth reasoning model on OpenCode Zen** with a 200K context window and no named vendor. ⚠️ **This repo's metadata records the name as "Big Pickle (GLM 4.6)" on the basis of "community consensus", and I am not able to corroborate that.** My searches surfaced no vendor statement, no OpenCode attribution and no fingerprinting study tying `big-pickle` to GLM-4.6 or to anything else. Applying the same standard I used for `omen-alpha` and `exo-free` earlier in this queue — behavioural impressions, response style and a model's own answer about its identity are not sufficient attribution — **I treat the vendor as unknown throughout** and do not import any GLM-4.6 data. Distinct from `omen-alpha` and `exo-free`, which are separate anonymous routes with their own folders.
- **Provider / access:** **OpenCode Zen.** [Pi](https://pi.dev/models/opencode/big-pickle) records: Model `big-pickle`, Provider `opencode`, API `openai-completions`, Base URL `https://opencode.ai/zen/v1`.
- **Release / knowledge:** Not announced. The earliest dated evidence I found is a community benchmark run on **2026-08-11**, so the route was live by then. Knowledge cutoff: not disclosed.
- **IDs:** `big-pickle` / `opencode/big-pickle` (OpenCode Zen). **Free during the promotional period**; current status not confirmed.
- **Context window:** **200,000 tokens** with a **32,000-token maximum output** (Pi).
- **Modalities:** **Text in → text out only** — Pi records "Input: text" with no image or attachment support. Reasoning: **yes** (Pi: "Reasoning: Yes"). Tool calls: not separately documented, but demonstrably functional — its one benchmark was run inside an agent scaffold.
- **Pricing (as of 2026-10-08):** **$0 on OpenCode Zen's free stealth tier.** No rate card exists, no end date is published, and — unlike `exo-free` — **I found no statement either way about data retention or training on user prompts**, which is itself worth knowing before sending anything sensitive.
- **Architecture:** **Entirely undisclosed** — no vendor, no parameter count, no training details.

### Normalized scores (1–100)

- **Tool use: 50/100.** Inferred from the one benchmark rather than measured directly, but the inference is sound: **SWE Atlas Codebase QnA was run through the mini-swe-agent scaffold**, which drives a tool loop over a repository, so a 50.8% resolve rate means tool calling, file navigation and multi-step execution all function at a usable level. Pi also confirms reasoning is enabled, which agent loops depend on. Scored at the midpoint because that is the entirety of the evidence — **no BFCL, τ²-bench, Terminal-Bench, GDPval, Toolathlon or MCP figure exists**, so nothing is known about breadth, long-horizon stability or schema adherence.
- **Reasoning: 40/100.** Pi confirms the model is a reasoning model, and resolving 63 of 124 codebase-comprehension questions is not achievable without genuine multi-step reasoning over unfamiliar code. But **there is no GPQA, MMLU-Pro, AIME, HLE, ARC-AGI or CritPt figure of any kind**, and no calibration or hallucination data at all. Scored below the midpoint on absence of evidence rather than demonstrated weakness — and deliberately **not** inflated by assuming GLM-4.6's published reasoning scores, since that attribution is unverified.
- **Context window: 52/100.** **200,000 tokens with a 32,000-token maximum output** is a solid, independently recorded specification, and the one benchmark exercises long context meaningfully — SWE Atlas Codebase QnA requires reading across a repository rather than a single file, so a 50.8% result is partial evidence that the window is usable in practice. Capped because **no retrieval measurement exists at any depth** (no MRCR, RULER, needle test or AA-LCR), and because a 32K output cap constrains long-form generation.
- **Multimodal: 15/100.** Text in, text out — Pi records text-only input with no attachment support. Template floor.
- **Coding: 56/100.** The only measured dimension, and the measurement is good. **50.8% on Scale AI's SWE Atlas Codebase QnA, run on the official harness with the official judge model via mini-swe-agent, dated and publicly reproducible**, is more trustworthy than a vendor-reported figure on the same benchmark would be — the evaluator had no incentive to flatter an anonymous route and published the code. For context, this is a repository-comprehension benchmark rather than a patch-generation one, so it measures understanding more than it measures fixing. Capped in the mid-50s because **a single benchmark cannot establish a coding profile** — there is no SWE-bench, LiveCodeBench, Terminal-Bench, DeepSWE or SciCode figure to show whether it can actually write and verify changes.
- **Cost efficiency: 82/100.** Strong on the headline and weak on everything that makes a free route dependable. **$0 for a reasoning model with a 200K window and 32K output** is excellent, and the one measured result suggests the capability behind it is real rather than token. Four deductions, all about risk rather than price: **the vendor is unknown**, so there is no accountability; **no end date is published**, so the route can vanish; **there is no rate card**, so there is no priced fallback if it does; and **no data-retention statement was found either way** — for `exo-free` the retention terms were at least disclosed, whereas here I could find nothing, which is worse. Free is only cheap if you can plan around it.
- **Overall Score: 42.6/100.** Mean of the five non-cost dims (50 + 40 + 52 + 15 + 56) / 5 = 42.6. **This score reflects a near-total absence of published evaluation, not a judgement that the model is weak** — the one real measurement available is respectable, and it was produced under conditions I would trust more than most vendor tables in this dataset. Best fit: **free, low-risk codebase question-answering and exploratory coding** on non-sensitive repositories, where a 200K window and a reasoning mode at zero cost are worth the uncertainty. Three things to hold in mind: **do not assume this is GLM-4.6** — that attribution is community guesswork and nothing in my research supports it; **do not send anything confidential**, because unlike comparable stealth routes no retention policy could be found; and **do not build on it**, because an anonymous free endpoint with no published end date is not infrastructure. If OpenCode or an upstream lab publishes an attributable model card, this folder should be re-researched from scratch.
