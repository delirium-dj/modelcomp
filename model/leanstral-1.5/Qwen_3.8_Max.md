> **Verdict:** Leanstral 1.5 is **Mistral AI's specialized open-weight formal-verification model** — a **119B-total / 6.5B-active Apache-2.0 MoE (128 experts, 4 active)** for **Lean 4 theorem proving and code verification**, released **2 July 2026** (successor to the March-2026 Leanstral) and trained via mid-training → SFT → RL-with-CISPO in two environments (a multiturn Lean-compiler proof loop and a filesystem/bash/Lean-LSP **code-agent** that compacts its own context). Within its domain the results are extraordinary — **miniF2F saturated, PutnamBench 587/672, FATE-H 87% / FATE-X 34% (SOTA within its class), FLTEval pass@8 43.2 (vs Claude Opus 4.6's 39.6) at ~1/7 the cost**, the strongest test-time scaling Mistral has seen (an AVL-tree O(log n) proof ran **2.7M tokens / 22 compactions / 8+ hours**), and a bug-hunting pipeline that surfaced **5 previously-unreported bugs across 57 repos** — all at **6B active parameters**, ~1/50th the active size of the general models it beats. **But nearly every headline needs its conditions attached, and independent scrutiny is sharp:** the numbers are **all Mistral-reported and not independently reproduced** (FSR is a Tier-C document-first briefing); **miniF2F "100%"** is pass@4/2M-tokens (the first test run was 242/244 — the last two fell only on retries, one after 37 attempts); **PutnamBench 587** is pass@8/4M and is beaten by the closed **Aleph Prover (668)** and guided **Goedel-Architect (597)**; the **FLTEval win is pass@8 vs Opus's pass@1 in a different harness** (Vibe vs Claude Code — not like-for-like); on cutting-edge research math (**ArXivLean**) it manages only **17.1%** (Aleph 34.2%); the **cost is disputed even within Mistral's own materials** (blog "~$4/problem" vs technical-report table "$1.68"); and the **bug-finding pitch drew HN fire** — the flagship varinteger overflow was filed a week *before* the announcement and is trivially reproduced by proptest/fuzzing, and **Mistral's own report footnote admits Claude found the same bug** on the same repo. Crucially it is **text-only**, has **no general reasoning/coding benchmarks** (no AIME/GPQA/SWE-bench), the Rust pipeline is **narrow** (Aeneas translates only a subset of safe Rust — no unsafe/concurrency), a checked proof **confirms the formal statement, not that the spec matches reality**, and the **free hosted endpoint is an experimental Labs service (`labs-leanstral-1-5`) listed for retirement 2026-09-30 that trains on your data**. Scored Overall **63** (div **−1.7** vs curated 64.7) — a genuinely frontier *specialist* whose narrow domain, vendor-only/unverified numbers, text-only modality, and absence of any general-assistant capability keep the quality-dimension mean just below the curated value.

## Model card

- **Name:** Leanstral 1.5
- **Short description:** Mistral AI's free Apache-2.0 **Lean 4 formal-verification / theorem-proving code agent** — a 119B-total / 6.5B-active sparse MoE that saturates miniF2F, solves 587/672 PutnamBench, and sets FATE-H/X SOTA at ~1/50th the active parameters of the general models it beats. Extraordinary *within* formal proof engineering; not a general coding/reasoning assistant, text-only, and every number is Mistral-reported (not independently reproduced).
- **Provider / access:** **Open weights on Hugging Face** (Apache 2.0, free commercial self-host, $0) and a **free hosted Labs API endpoint** (`labs-leanstral-1-5`; hosted list ~$0.15/$0.45 elsewhere). Recommended inside **Mistral Vibe** (`vibe --agent lean`, `/leanstall`, optional Lean-LSP MCP); also supported by the open-source **OpenATP** prover package. Part of the OpenCode catalog as `opencode/leanstral-1.5`. Supports chat completions, function calling, structured outputs, prefix completion, and fill-in-the-middle. **Caveats:** the Labs endpoint is **experimental, not recommended for production, removable on two weeks' notice, listed for retirement 2026-09-30**, and **enabling Labs allows Mistral to train on your data** (Zero-Data-Retention only on the Scale plan / stateless calls).
- **Release / knowledge:** Released **2 July 2026** (Mistral blog + technical report carrying an arXiv submission stamp dated 2 Jul 2026). Successor to the original **Leanstral (March 2026)**, which Mistral said beat Claude Sonnet by 8 points at pass@16 for ~15× less. Knowledge cutoff not separately published.
- **IDs:** id `opencode/leanstral-1.5`; hosted `labs-leanstral-1-5` / `leanstral-1-5`; HF weights; report `github.com/mistralai/LeanstralSafeVerify`. **No Artificial Analysis page** (`leanstral-1-5` → 404 — specialized model, no AA speed/cost/intelligence measurement); no LMArena.
- **Context window:** **262,144 (256K) advertised; 200K recommended** (Mistral's example vLLM config uses 4-way tensor parallelism and caps model length at 200,000). Long tasks rely on **agentic context compaction** — the model summarizes earlier work and continues across many compaction rounds (the AVL proof spanned 2.7M tokens / 22 compactions), so its *effective* working horizon far exceeds the raw window.
- **Modalities:** **Text input → text output only.** Not multimodal. **Reasoning:** yes — extended, machine-checked formal proof search with test-time scaling (pass@k, multi-million-token trajectories); but this is *formal* reasoning (Lean 4 / mathematics), and **no general reasoning benchmarks** (AIME/GPQA/HLE) are published.
- **Pricing:** **Free** — Apache-2.0 open weights ($0/$0 self-host) and a **$0 experimental Labs endpoint** (hosted list ~$0.15/$0.45 on other routes). Per-problem cost is **vendor-disputed**: blog "~$4 per PutnamBench problem," technical-report table "$1.68" (vs ~$68 Aleph Prover, ~$240 est. Seed-Prover). FSR's core warning: **the model is free, the verification system is not** — proof-search compute (8h+ trajectories), Lean formalization labor, and governance are the real cost.
- **Architecture:** **119B-total / 6.5B-active sparse Mixture-of-Experts (128 experts, 4 active per token)** — runnable on modest hardware while reaching frontier formal-proof performance. Trained in three stages (**mid-training on proof data → SFT → RL with CISPO**) across two RL environments: a **multiturn theorem-proving loop** (statement → proof → Lean-compiler feedback → refine) and a **code-agent environment** (raw filesystem, bash, Lean language server, self-compaction), verified by Mistral's fork of **SafeVerify** (replays every declaration through the Lean kernel via `Environment.replay`, allows only the 3 standard axioms, rejects `partial`/`unsafe`).
