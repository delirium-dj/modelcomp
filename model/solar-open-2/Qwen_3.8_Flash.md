## Model card

- **Name:** Solar Open 2 / **Solar-Open2-250B** (Hugging Face `upstage/Solar-Open2-250B`; AA id `solar-open2-250b`; served model name `solar-open2-250b`; curated id `opencode/solar-open-2`)
- **Short description:** Upstage's **"250B-A15B open-weight large language model, built for agentic use cases such as office productivity, document-intensive work, and coding"**, positioned publicly as **"Korea's sovereign foundation model, built for agentic use."** The engineering thesis is capability-per-dollar-of-inference: a Hybrid-Attention Mixture-of-Experts that activates only 15B of 250B parameters per token and interleaves **one softmax (GQA) layer among every three linear-attention layers** (75 % of its 48 layers linear), so "large-model capacity at small-model inference cost" with a **1M-token window** and long-context memory at "roughly a quarter of an all-softmax model of the same shape."
- **Provider / access:** **Open weights, commercially usable**, on Hugging Face (with ModelScope-style mirrors and third-party quants). **Licence: "Upstage Solar License"** — a custom permissive-but-branded licence, *not* MIT/Apache: derivative models (create / train / fine-tune / distill / improve on it) must **prefix the name with "Solar"**, prominently display **"Built with Solar"** in public materials, and **ship a copy of the licence**. Serving stack: **vLLM v0.22.0 via Upstage's own fork** (`UpstageAI/vllm@v0.22.0-solar-open2`, `--reasoning-parser solar_open2 --tool-call-parser solar_open2 --enable-auto-tool-choice`, TP8 + expert parallelism, `--moe-backend triton`, plus a required `SolarOpen2TemplateLogitsProcessor`) or a patched Upstage **Transformers** branch (`v5.14.1-solar-open2`) with `fla-core[cuda]` KDA kernels. Official **Nota AI** quants exist (`Solar-Open2-250B-Nota-INT4-GlobalPruned`, `-Nota-NVFP4`, `-Nota-INT4`). Agent integrations documented in the card: **Claude Code** (through vLLM's Anthropic-compatible `/v1/messages`, no proxy) and **Nous Hermes Agent** (OpenAI-compatible `/v1`), both natively MCP-capable. **Hosted-API status:** this researcher could find **no first-party or third-party hosted endpoint** for this ID — OpenRouter has no `upstage/solar-open-2-250b` product page (404; the provider page lists only the Solar Pro line and Solar Decide), and an independent write-up states plainly that Solar Open 2 is "**open weights nobody hosts yet**". That absence is why Artificial Analysis reports **no speed, cost or verbosity measurement** for it.
- **Release / knowledge:** HF/blog/arXiv all date the release to **2026-07-22**; Artificial Analysis lists **Released August 2026** (its index-arrival date, ~2–3 weeks after weights). **Knowledge cutoff: February 1, 2026** (AA spec block — the first explicit cutoff this researcher has found for an Upstage model). Technical report: **arXiv 2607.20062**, "Solar Open 2 Technical Report", v1 2026-07-22, v2 2026-07-24, **CC BY 4.0**, ~54 authors including Kyunghyun Cho, Yejin Choi and Alice Oh.
- **IDs:** `upstage/Solar-Open2-250B` (HF), `solar-open2-250b` (AA), `opencode/solar-open-2` (curated). **Aggregator coverage:** **BenchLM has a page** (`benchlm.ai/models/solar-open-2`) but assigns **no Overall Score — "Unranked"**, with **15 of 625** benchmark rows, **every row sourced from the Upstage model card** (i.e. self-reported, not independently re-run). **Artificial Analysis has a page** (`solar-open2-250b`) but its Index is marked **"Estimate (independent evaluation forthcoming)"** and its per-evaluation panels read **"Not publicly available"**. Net: **there is currently no independently executed benchmark row for this model** — only vendor tables plus an AA estimate.
- **Context window:** **1,000,000 tokens** — corroborated by four sources (AA spec block "1M", BenchLM "Context Window 1M", HF card "Context Length 1M", Upstage blog "supports a context window of up to 1M tokens"), and architecturally substantiated: **NoPE** (no rotary positional encoding at all, which "lifts the RoPE extrapolation limit") + linear-attention recurrent state + a gated delta rule extended to negative eigenvalues, with only 12 of 48 layers keeping a KV cache. **Output budget:** reasoning blocks are capped at **131,072 tokens** in the recommended config, with `max_tokens` recommended **up to 256K** (up to 128K in non-reasoning mode) — comfortably above the methodology's 64 K sub-band caveat, so no output penalty applies. **The curated `meta.json` says "65,536 total (16,384 out)" — wrong by more than 15×, and the single most consequential curation error in this folder.**
- **Modalities:** **text in / text out.** AA: "supports text input, outputs text"; card `pipeline_tag: text-generation` with no vision/audio encoder, and no image/PDF/video benchmark row anywhere in the vendor tables. The "document-intensive work" framing means documents are ingested **as text** (OCR/parsing upstream), not natively. Curated "Text in/out" is **correct**. Languages: **English, Korean, Japanese**, on a 196,608-token vocabulary tuned so Korean text costs **50–80 %** of the tokens global models need (24 % ahead of the best global tokenizer on Korean office text across 12 compared).
- **Pricing (as of 2026-10-08):** **No published per-token API price exists for this ID.** What exists instead is a hardware bill of materials: **minimum 4× H200** (BF16), **2× H200 with quantization** (Nota INT4/NVFP4; independent coverage reports the INT4 path fitting **2× H100**), recommended 8× H200 for production TP8. Training cost is disclosed (**2M GPU hours on NVIDIA B200**, ~12 T pre-training tokens, a 20 T pool curated down to a 10 T mixture). Upstage's *closed* line is the priced alternative — Solar Pro 4 at **$0.30 / $1.20 per 1M** (a conflicting third-party table shows $0.03/$0.12; neither is confirmable from a first-party sheet here) — and Upstage explicitly splits the product lines: **Solar Pro for API-delivered commercial agents, Solar Open 2 for general-purpose/self-hosted.** AA's Cost and Verbosity units are "**Unknown**", so no cost-per-task figure is available. `noFreeId: true` in the curated file is **unverifiable in both directions**: weights are free to download and commercially usable, yet no free hosted endpoint was found.
- **Architecture:** **250,287,794,944 total / 15 B active per token**; 48 layers, hidden 4096, attention pattern `[Softmax, Linear×3] × 12`, **NoPE**, GQA 64 query / 8 KV heads (softmax path) and 64 query heads (linear path), **321 experts (320 routed + 1 shared), top-8 routed + 1 shared**, vocab 196,608. Two training innovations are load-bearing: **Selective Weight Transfer** initialization from Solar Open 1 (102B) — carrying over only the surviving **5.69 B-parameter shared skeleton (~2.3 % of weights)** and re-learning the rest, which hit target loss in ~12 B tokens vs ~22 B random (58 %, in a matched 200B-A15B proxy) and reached Solar-Open-100B's MMLU level at 210 B tokens instead of 671 B; and **twelve domain-specialist agent models consolidated by Multi-teacher On-Policy Distillation (MOPD)**. Reasoning Effort is a two-level knob (`none` | `high`).
- **Identity flags:** (1) **`meta.json` is not `"scaffolded": true` but is materially wrong** — context understated 15×, price field is a placeholder alternative ("Open-weights / free self-host or standard API pricing"). Do not inherit scores between Solar Open 2 and Solar Pro N; they are different models with different windows. (4) **Preview-era claim conflict:** June-2026 press coverage quotes Upstage claiming a **Solar Open 2 preview scored 44.4 on the AA Intelligence Index**; the live AA page for the shipped model shows **25 (estimated)**. The 44.4 is preview marketing and is **not** used for scoring. (5) **Slug check:** `solar-open-2` follows the registry's convention and has no hyphen/dotted twin (rule-7 clean).

### Normalized scores (1–100)

- **Tool use: 60/100.** This is the model's stated purpose and the training story behind it is the most credible in the folder: tool-calling data was generated by **executing changes in a real environment and reading the changed state back** ("separate generating a plausible answer from actually completing the task"), across search / MCP / coding / office-work scenarios consolidated by MOPD; the serving stack ships a **first-class `solar_open2` tool-call parser with `--enable-auto-tool-choice`** on the standard OpenAI function-calling interface; **MCP-Atlas 58.2** ties for the top of the vendor's comparison group; and it is documented to drive **Claude Code and Hermes Agent directly**. Held to the mid band, not the frontier band, because the absolute numbers are modest (**APEX-Agents 16.6**, **τ³-bench banking 19.6** against τ² frontier results near 98 %, **GDPval-AA Elo 1128** against a ~1750 frontier anchor), **BFCL / Toolathlon / AutomationBench / OSWorld have no row at all**, and every figure is self-reported with **no independent harness run** and no measurable cost-per-task.
- **Reasoning: 65/100.** AA's independent composite — **Index 25, #29/117, class median 18, "well above average"** — sits squarely in the methodology's 20–35 mid band (top edge), far from the Index-60 frontier anchor, and it is explicitly an **estimate**, not a measured run. The vendor rows that support the band are strong but unverified: **GPQA-Diamond 86.3** (below the 90+ frontier line), **MMLU-Pro 86.2**, competition-level math (**AIME2026 95.7, HMMT Feb 2026 93.9**), and the weak signal is **HLE w/o tools 28.8** — under the 40+ mid reference — plus **AA-LCR 62.3**. There is no CritPt/SciCode row and **no AA-Omniscience faithfulness measurement**, so knowledge-reliability risk is unquantified rather than reassuring.
- **Context window: 90/100.** **1M tokens, confirmed by four independent-of-each-other sources** (AA, BenchLM, HF card, blog) and — unusually — *mechanistically* explained rather than merely advertised: NoPE removes the RoPE extrapolation ceiling, three of four layers hold a fixed-size recurrent state, only 12 of 48 layers carry a KV cache (~¼ of all-softmax memory), and **output is not the bottleneck** (131,072-token reasoning cap, `max_tokens` up to 256K). That places it in the ≥1M band, but **not at 100**: the band's top requires demonstrated retrieval (**≥98 % at 512K+**), and the only long-context measurement in existence is **vendor-reported AA-LCR 62.3 / Multi-Challenge 61.0**, with no MRCR/AI-Needle run and no independent verification at any length. Curation flag recorded: the sheet's **65,536** is wrong and would have scored this dimension ~35.
- **Multimodal: 15/100.** **Text-only**, confirmed twice: AA's modality block (text in, text out) and the card (`pipeline_tag: text-generation`, no encoder, no MMMU/MMMU-Pro/video/audio row). "Document-intensive work" is text pipeline, not native document understanding — nothing in the trail mentions image, PDF-rendering, audio or any non-text output. 10–20 band, no lift. Vision/language breadth in Upstage's lineup lives in *other* products, not this checkpoint.
- **Coding: 78/100.** **LiveCodeBench v6 92.4** is a genuinely frontier-adjacent competitive-programming number (the vendor's "highest among comparable models", ahead of Mistral Medium 3.5's 84.9 and MiMo-V2.5's 89.1, essentially tied with DeepSeek-V4-Flash's 92.3), **SWE-bench Verified 70.4** is a solid real-repository result but ~25 points below the current frontier (~95), and **Terminal-Bench Hard 28.3** is the weak link — agentic terminal coding (Mistral Medium 3.5 33.3, DeepSeek-V4-Flash 34.1, MiMo-V2.5 41.7) plus **ArtifactsBench 55.9** and no DeepSWE/SciCode/SWE-Pro row. Well above the mid band on breadth and math-adjacent code strength; clearly short of a frontier coding-agent placement, and again entirely self-reported.
- **Cost efficiency: 93/100.** The strongest cost story of any folder researched in this pass: **weights are free and commercially usable**, the 15B-active MoE means "**large-model capacity at small-model inference cost**", the deployment floor is **2× H200 quantized / 4× H200 BF16** — an order of magnitude friendlier than the trillion-parameter 8-way-TP jobs in the neighbouring `ling-2.6.1t`/`ring-2.6.1t` folders — official INT4/NVFP4 quants exist, linear attention caps long-context memory at ~¼ (context tokens are the dominant agent cost), and the Korean tokenizer alone cuts Korean input to **50–80 %** of the usual token count. Deductions: **no per-token price and no AA cost-per-task figure exist**, so hosted economics are simply unknown; **self-hosting is the only route**, which shifts cost to GPUs and ops; and the **Upstage Solar License** imposes branding obligations ("Solar" prefix, "Built with Solar" attribution, licence copy) on derivatives — free but not frictionless, unlike MIT.
- **Overall Score: 62/100.** Mean of the five quality dimensions (60 + 65 + 90 + 15 + 78) / 5 = 308 / 5 = 61.6 → 62; Cost excluded per `RULES.md`. Best fit: **enterprises that must run long-horizon agents on their own infrastructure** — especially Korean-language office/document work, where it is measured (by its own lab) as the strongest model in its class and beats fast-tier closed APIs outright — with Claude Code or Hermes Agent pointed at a local vLLM endpoint on 2–4 H200s. It is **not** the pick for multimodal work (text-only), not for teams needing a hosted API with a price sheet and SLA (none exists for this ID), and not a verified leaderboard story: **BenchLM is Unranked and every one of its 15 rows traces back to the vendor's model card, and AA's Index 25 is an estimate with no measured speed, cost or verbosity.** The score is credible but provisional — it should be re-verified the moment Artificial Analysis runs the endpoint or an independent harness publishes. **Two concrete curation fixes before the next sync:** correct `contextWindow` to **1M (131K reasoning / 256K recommended output budget)** and replace the placeholder pricing note with "open weights, self-host only; no hosted API price published".
