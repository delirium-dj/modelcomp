## Model card

- **Name:** Kimi K2.7 Code HighSpeed
- **Short description:** Moonshot AI's **high-speed serving mode** for Kimi K2.7 Code, released 2026-06-15 — three days after K2.7 Code itself (2026-06-12) — and rolled out first to the Kimi Code Beta channel. HokAI's characterisation is the accurate one: "a serving-side optimization, **not a retrained model**." It reaches roughly **180 tokens/s on median-length coding completions and up to 260 tokens/s on short-context bursts, about 6× the throughput** of the standard K2.7 Code deployment. Vercel AI Gateway positions it precisely: "the underlying model is identical, so coding quality, multimodal input, and always-on thinking all carry over — you're paying for faster serving." Not an alias: it has its own API model ID and its own rate card at exactly double the base on every billed line.
- **Provider / access:** **Moonshot's native Kimi API** (`platform.kimi.ai`, model ID `kimi-k2.7-code-highspeed`) — the authoritative rate card. Also on **Vercel AI Gateway** (`moonshotai/kimi-k2.7-code-highspeed`, providers Moonshot and Fireworks), **Cloudflare Workers AI**, and **OpenRouter** at a lower rate. Available through the **Kimi Code** product (Beta channel first). Open weights under a **Modified MIT licence**, so self-hosting is possible — at roughly **1 TB of GPU memory for the FP8 build**.
- **Release / knowledge:** HighSpeed mode released **2026-06-15**; parent Kimi K2.7 Code released **2026-06-12** as a fine-tune of the Kimi K2.6 base. Knowledge cutoff not published for either.
- **IDs:** `kimi-k2.7-code-highspeed` (Moonshot API); `moonshotai/kimi-k2.7-code-highspeed` (Vercel AI Gateway). Parent model: `kimi-k2.7-code`. Kimi Code membership IDs: `kimi-for-coding-highspeed`.
- **Context window:** **262,144 tokens (256K)** — carried over unchanged from K2.6 and K2.7 Code (Moonshot pricing page; Artificial Analysis records 256k for the parent). **Note the 4× step-down from K2.8 Preview**, Moonshot's newer mainstream coding checkpoint, which carries 1,048,576 tokens. Max output is inconsistently reported: **Vercel AI Gateway lists 32,768 tokens**, HokAI lists **49,152**; no first-party Moonshot figure was found in the pricing documentation.
- **Modalities:** **text, image and video in; text out** (Artificial Analysis on the parent: "Supports: text, image, and video"). Architecture note from HokAI: a **MoonViT vision encoder** gives native image and video input alongside text. Reasoning: **thinking mode is always on and cannot be disabled** — so **reasoning tokens are billed as output tokens**, which materially raises the effective output rate in real use. ToolCalls, JSON Mode, partial mode and automatic context caching all supported.
- **Architecture:** **open weights, Modified MIT licence.** Moonshot's own pricing docs give no architecture; HokAI's detailed spec (recorded as third-party): **Mixture-of-Experts transformer, ~1 trillion total parameters, 32 billion active per token, 61 layers, 384 experts with 8 routed plus 1 shared per token, Multi-head Latent Attention for KV-cache compression, SwiGLU activations, 160K vocabulary.** Artificial Analysis independently confirms **1T total / 32B active** and the Modified MIT licence with Hugging Face weights.
- **Pricing (as of 2026-10-01):** **$1.90 / MTok input (cache miss), $0.38 / MTok cached input, $8.00 / MTok output** (Moonshot's own pricing page — `platform.kimi.ai/docs/pricing/chat-k27-code`, corroborated by Vercel AI Gateway at identical rates and by Kimi's own pricing resource page). **Every line is exactly double the base `kimi-k2.7-code` model's $0.95 / $0.19 / $4.00.** benchr's reading is the right one: "Moonshot prices the speed tier as a flat 2× rather than a separate rate card." **Correction to a widely repeated third-party figure:** HokAI lists HighSpeed at $0.95 / $0.19 / $4.00 — those are the *base* model's rates, not HighSpeed's. OpenRouter carries it cheaper at **$0.74 input / $3.50 output**. In an agent loop most input is cache-read, so Command Code's effective blended input rate is about **$0.84/MTok**. No subscription tier; self-hosting the MIT weights avoids per-token billing entirely at ~1 TB of GPU memory.

### Raw benchmarks found

**All benchmarks below are for `kimi-k2.7-code` — the identical weights. Moonshot has published no separate HighSpeed benchmark, and HighSpeed has no Artificial Analysis record of its own (Command Code lists its intelligence, coding and speed scores as "not yet scored").**

Agent / tool use:

- **MCP Mark Verified: 81.1%** — Moonshot-reported (2026-06-12). This is the strongest tool-invocation result in the K2.7 Code record and it is a **third-party-run** benchmark covering Notion, GitHub, Postgres, Filesystem and Playwright environments. HokAI notes it **beats Claude Opus 4.8's 76.4 on that specific test**, while Opus 4.8 leads on broader coding suites.
- **MCP Atlas: 76.0%** (Moonshot-reported)
- **LiveBench: 71.9%** (Moonshot-reported)
- Terminal-Bench 2.1 / 2.0 / Tau3-Banking / Tau2-Bench / GDPval-AA / Toolathlon / Claw-Eval / SWE Atlas Codebase QnA / AutomationBench: **no verified public score found** for K2.7 Code or HighSpeed at any mode.

Reasoning / knowledge:

- Artificial Analysis Intelligence Index: **41.9** for Kimi K2.7 Code, ranking **#32** on AA's leaderboard (Command Code's transcription of AA's figures; AA's own page headline reads "#32 /" with the index value truncated in the retrieved copy). AA's qualitative summary: "amongst the leading models in intelligence, but **particularly expensive** when comparing to other open weight models of similar size. It's also slower than average, however fairly concise."
- Artificial Analysis Coding Index: **60.8**; Speed sub-score 39.2 (Command Code).
- **AA cost per Intelligence Index task: $0.54** — against a peer median of $0.30 input and $1.18 output for comparable open-weight models, where K2.7 Code costs $0.95 / $4.00.
- GPQA Diamond / HLE / CritPt / AIME 2025 / FrontierMath / ARC-AGI / AA-LCR / AA-Omniscience: **no verified public score found.**

Coding:

- **Kimi Code Bench v2: 62.0%** (Moonshot-reported) — against Kimi K2.6's 50.9, a **+21.8% relative gain**. Moonshot's own benchmark, so vendor-reported.
- **Program Bench: 53.6%** (Moonshot-reported) — K2.6 48.3, +11.0%
- **MLS Bench Lite: 35.1%** (Moonshot-reported) — K2.6 26.7, **+31.5%**, the largest relative gain in the launch set
- Moonshot reports a roughly **30% reduction in reasoning-token usage** versus K2.6 — a token-efficiency claim, not a benchmark.
- **SWE-bench Verified / SWE-bench Pro / DeepSWE / LiveCodeBench / SciCode / Vibe Code Bench / SWE-rebench / SWE-Lancer: no verified public score found.** HokAI's framing of the resulting gap is the fair one: "its closest open-weight rival, GLM-5.2, holds a stronger position on audited benchmarks at 62.1% on SWE-bench Pro, so K2.7 Code's real edge is **token efficiency and tool-call reliability rather than raw solve rate**."

Long context:

- **No long-context retrieval measurement exists** — no MRCR, RULER or GraphWalks figure for K2.7 Code or HighSpeed. Moonshot's own description of the model is "completes programming tasks with higher success rates in long contexts" and "context length 256k, supports long thinking and deep reasoning" — a capability claim with no number behind it.
- Architectural note: **Multi-head Latent Attention** compresses the KV cache, which HokAI credits with keeping "enough KV cache headroom for long agentic sessions" in self-hosted deployments. That is an engineering property, not a measured retrieval result.

Vision / multimodal:

- **Text, image and video in** (Artificial Analysis; MoonViT vision encoder per HokAI) — image and video are documented, and the platform documentation explicitly lists video input support.
- **No MMMU, MMMUPro, DocVQA, OmniDocBench or CharXiv figure was found** for K2.7 Code or HighSpeed.

Speed (the one dimension HighSpeed genuinely changes):

- **~180 tokens/s** on median-length coding completions, **up to ~260 tokens/s** on short-context bursts — Moonshot's published figures, roughly **6× the standard K2.7 Code deployment**.
- Baseline for comparison: Artificial Analysis measures standard `kimi-k2.7-code` at **64.1 tokens/s** on Moonshot's own API, which AA calls "slower than average (median 72)".
- **Provider variance is enormous and undercuts the headline.** AA's provider matrix for standard K2.7 Code shows **CoreWeave at 272.5 t/s**, Nebius (FP4) 247.5 t/s, Baseten 153.8 t/s, Novita 77 t/s, DeepInfra 53 t/s, Kimi's own API 75 t/s — a **665% spread between fastest and slowest**. Third-party provider Crusoe reports **over 430 output tokens/sec** on its own optimised stack. HokAI's conclusion is the correct reading: **"the ceiling is provider-dependent rather than fixed by the model."** HighSpeed's 180 t/s is roughly what CoreWeave already delivers for the base weights at a lower price.

### Normalized scores (1–100)

- **Tool use: 70/100.** The strongest dimension, and the one with the best-sourced evidence in the K2.7 record. **MCP Mark Verified 81.1%** on a third-party-run suite spanning Notion, GitHub, Postgres, Filesystem and Playwright is a real tool-invocation result that **beats Claude Opus 4.8's 76.4 on that specific test**, and **MCP Atlas 76.0%** corroborates it. **LiveBench 71.9%** shows general-agent breadth. Capped at 70 — mid-band, not frontier — because **not one of the agentic harnesses this dimension is normally anchored on has a figure**: no Terminal-Bench 2.0 or 2.1, no Tau3-Banking, no Tau2-Bench, no Toolathlon, no GDPval-AA, no AutomationBench. The score rests on MCP-based tool use, which is the one agentic axis Moonshot chose to publish, plus its own LiveBench.
- **Reasoning: 45/100.** Below the dataset's mid-scale band, and driven by an honest reading of a thin record. **Artificial Analysis Intelligence Index 41.9 (#32)** is a respectable-but-not-leading placement, and AA's own summary calls the model "amongst the leading models in intelligence" in absolute terms while ranking it expensive. Thinking is **always on and cannot be disabled**, which means reasoning tokens are always billed as output. Capped at 45 by the complete absence of **GPQA Diamond, HLE, CritPt, AIME 2025, FrontierMath, ARC-AGI, AA-LCR and AA-Omniscience** — none of which exist for this model — plus the fact that AA's Speed sub-score of 39.2 and its "slower than average" verdict describe a model whose reasoning is not being applied quickly. HighSpeed changes nothing here; it is the same weights.
- **Context window: 72/100.** **262,144 tokens (256K)** places it in the methodology's 200K–500K band, above its floor and below its midpoint. Scored above the 70 tier point for the 256K window plus **Multi-head Latent Attention** KV-cache compression, which is a real architectural answer to long agentic sessions and matters for self-hosting. Not scored higher because **no retrieval measurement exists at all** — no MRCR, no RULER, no GraphWalks — so the "higher success rates in long contexts" claim is Moonshot's own and carries no number. Also worth stating plainly in 2026: this is a **4× step-down from Kimi K2.8 Preview's 1,048,576 tokens**, Moonshot's own newer mainstream coding checkpoint on the same Kimi Code surface.
- **Multimodal: 78/100.** **Text, image and video in; text out** — the methodology's "+video/PDF in = 75–90" band, scored near its floor. Moonshot's pricing documentation explicitly lists **text, image and video input**, and HokAI attributes it to a **MoonViT vision encoder**, so the capability is documented rather than inferred. Held near the band's bottom because **no vision benchmark of any kind was published** — no MMMU, no MMMUPro, no DocVQA, no OmniDocBench, no CharXiv — and because video *input* with text *output* earns this band rather than the 90–100 one that requires audio input or non-text output. HighSpeed's modality set is identical; the extra 3× throughput is real and simply unmeasured on vision tasks.
- **Coding: 66/100.** Solid mid-tier, honestly bounded by what Moonshot chose to publish. **Kimi Code Bench v2 62.0%**, **Program Bench 53.6%** and **MLS Bench Lite 35.1%** are meaningful, and the generational deltas are large (+21.8%, +11.0%, +31.5% over K2.6) — but all three are **Moonshot's own benchmarks**, and the headline **Kimi Code Bench v2 62.0%** lands exactly where HokAI points: below **GLM-5.2's audited 62.1% on SWE-bench Pro**, on a benchmark K2.7 Code has not been run on at all. With **no SWE-bench Verified, no SWE-bench Pro, no DeepSWE, no LiveCodeBench and no SciCode figure anywhere in the record**, the coding score cannot be placed against the anchors the methodology uses, and 66 reflects Moonshot's self-reported mid-60s rather than an audited result.
- **Cost efficiency: 62/100.** **$1.90 / $8.00 per MTok with cached input at $0.38** — every line **exactly double** the base model's $0.95 / $0.19 / $4.00, which Moonshot implements as a flat 2× multiplier rather than a separate rate card. Scored between the methodology's ~$1.25/$4.25 ≈ 88 anchor and its $3/$15 ≈ 60 anchor, and close to the latter: **$1.90 input against a $0.47 peer median and $8.00 output against a $1.69 peer median** for comparable open-weight models, which is what AA means by "particularly expensive." Real offsets, all credited: **cached input at $0.38** means the effective rate inside an agent loop is about **$0.84/MTok**, since most agent-loop input is cache reads; **OpenRouter carries it at $0.74 / $3.50**; and **self-hosting the Modified MIT weights costs no per-token fee at all**, at roughly 1 TB of GPU memory for FP8. The reason this does not score higher despite those offsets is the variant's own premise: **for any workload that is not latency-bound, paying 2× for byte-identical output is strictly worse value**, and HokAI's point about the speed ceiling being provider-dependent — CoreWeave already delivers 272.5 t/s for the base weights — means the premium may buy less speed than the headline suggests.
- **Overall Score: 66/100.** (70 + 45 + 72 + 78 + 66) / 5 = 66.2 → **66**. Best fit, stated as a two-model decision: **use `kimi-k2.7-code-highspeed` only where latency is the binding constraint** — interactive coding in the Codex/VS Code-class loop, live pair programming, an agent a human is watching and steering — where ~180–260 t/s against the base model's 64 t/s changes whether the loop feels usable, and where the tool-calling reliability (**MCP Mark Verified 81.1%, beating Claude Opus 4.8**) is what you are paying for. **For batch, overnight or unattended work, use the base `kimi-k2.7-code` and pay half.** For either: Moonshot's own newer **K2.8 Preview** offers a **4× larger context window** (1,048,576 vs 262,144) at near-K3 positioning, and **GLM-5.2** holds the stronger audited SWE-bench Pro position at 62.1%. And whichever route you pick, **self-hosting the Modified MIT weights is the cheapest path by a wide margin** if you can afford ~1 TB of GPU memory.
