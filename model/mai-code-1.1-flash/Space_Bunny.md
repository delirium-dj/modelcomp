## Model card

- **Name:** MAI-Code-1.1-Flash
- **Short description:** Microsoft AI's in-house **coding specialist**, released **2026-08-11** as an update to MAI-Code-1-Flash (June 2026, deprecated 2026-09-10). Explicitly "built for developers, not benchmarks" — trained directly with the **GitHub Copilot production harnesses** using hundreds of thousands of RL environments. Top use case: high-volume, low-latency agentic coding inside GitHub Copilot, VS Code and other Copilot surfaces. New in 1.1: **image input**, quarter the cost of its predecessor, 25% fewer tokens per task, 25% faster token streaming. As of **2026-10-07** it can also run **on-device** inside GitHub Copilot with no per-inference charge. It is a coding specialist, **not** a general frontier model.
- **Provider / access:** **GitHub Copilot** (model picker in the Copilot app, Copilot CLI, Copilot cloud agent, VS Code, Visual Studio, GitHub Mobile, JetBrains, Eclipse, Xcode; Copilot Free and Student get it via auto model selection, Pro/Pro+/Max/Business/Enterprise can select it manually; **Enterprise and Business administrators must enable the MAI-Code-1.1-Flash policy, which is off by default**) and **Microsoft Foundry / Azure AI** (`ai.azure.com/catalog/models/MAI-Code-1.1-Flash`, version 2026-09-15, "Direct from Azure"). OpenAI-compatible endpoints on Foundry. **Not available as a standalone pay-per-token API elsewhere** — no OpenRouter, DeepInfra or OpenCode Zen listing. **New this pass: local download.** Microsoft states the model "is available to download and run locally," shipping as a **3-bit quantization** that "retains a full 256K context window and comparable coding performance to its full-precision counterpart on SWE-Bench Verified and Terminal-Bench 2.1"; devices with **more than 120GB of RAM** are recommended. Experimental on-device access in GitHub Copilot was promised "by end of the month" (i.e. by 2026-10-31).
- **Release / knowledge:** Released **2026-08-11** (also the EU release date per the model card). Foundry version dated 2026-09-15. Official model card gives **training dates March 2026 – August 2026**. **Knowledge cutoff: not disclosed.**
- **IDs:** `MAI-Code-1.1-Flash` (Foundry / Copilot policy name), `microsoft/mai-code-1.1-flash` (OpenCode model data), `github-copilot` (llm-stats provider route)
- **Context window:** **256,000 tokens input, 128,000 max output.** The first pass could not find a max-output figure; it is now documented on two independent routes — OpenCode's model data and the HokAI model record both give 256,000 / 128,000, and Microsoft separately confirms "a full 256K context window" for the 3-bit on-device build. Verified on llm-stats and benchlm as well.
- **Modalities:** **Text-to-text and image-to-text** coding model, stated in the official model card's own summary line ("a text-to-text and image-to-text coding model"). New in 1.1-Flash: it "takes image inputs and reasons over image contents" — screenshots, diagrams and UI mock-ups to prototype. Reasoning: **adaptive solution-length control**. Tool calls / function calling: yes (trained with the Copilot harness). Instruction following: stated strength across single-turn and multi-turn.
- **Pricing (as of 2026-10-17):** **$0.20 in / $1.20 out per 1M**, input with cache **$0.02** — via the `github-copilot` route. That is **a quarter of MAI-Code-1-Flash's cost**, and GitHub's changelog puts it at a **73% lower list price** than the predecessor. Two access channels materially improve the effective rate and were **not in the first pass**: (a) **annual GitHub Copilot subscribers are charged at a 0.25× premium request multiplier**; (b) **on-device inference carries zero inference charges**. Paid only; no Free tier of the API.
- **Architecture:** proprietary closed weights — **not open-weight** (OpenCode's model data still carries `Open weights: No`). **~137–138B total, ~5B active**, sparse MoE. The first pass declined to state a total/active split because Microsoft had not disclosed it; that is now resolved, indirectly but authoritatively: the official model card's **Model dependencies** field lists **MAI-Thinking-1** and **MAI-Code-1-Flash** as ancestors and states that development "starts from **MAI-Thinking-1's compressed 5B-active-parameter mid-training checkpoint**." That is Microsoft's own confirmation that the 5B figure is *active* parameters, matching third-party totals of 137–138B. Licensed under GitHub/Microsoft product terms and the Microsoft Enterprise AI Code of Conduct — not an open licence.

### Raw benchmarks found

> **Provenance correction — the main finding of this pass.** The first pass presented SWE-bench Verified 72.6% and Terminal-Bench 2.1 62.9% as the "widest-published" figures sourced to llm-stats. They are not independently measured. **Every aggregator carrying them — llm-stats, BenchLM, HokAI and AITier — is relabelling the same two numbers from Microsoft's own model card.** HokAI states it outright ("vendor-reported"), BenchLM attributes both rows to "Microsoft AI: MAI-Code-1.1-Flash model card," and AITier reproduces them under "LLM Stats." **No independent organisation has run this checkpoint on any benchmark.** The count of genuinely independent benchmark numbers for MAI-Code-1.1-Flash remains **zero**. Only two scores exist, both vendor-run, both in Microsoft's own production harness — a status this report now states rather than implies.

Coding (both Microsoft-reported, from the model card and the launch blog):

- SWE-bench Verified: **72.6%**, averaging **8.6K tokens per solved task** (HokAI, restating the model card) — vs MAI-Code-1-Flash 71.6% (10.8K tokens), Claude Haiku 4.5 69.8%, GPT-5.4 mini 69.2%. **A reporting conflict to record:** a secondary explainx.ai write-up refers to "the **70.8** and **72.6** percent SWE-Bench Verified figures" for this model. 72.6% is corroborated by four separate sources and matches the model card; **70.8% could not be traced to any Microsoft document** and may be a third-party or quantized-build re-measurement. The 72.6% value is preferred here. HokAI's independent framing of the same number: **rank 21 of 31** models publishing SWE-bench Verified, against a peer median of 77.2% — i.e. bottom third of its price-class peers, which the first pass did not surface.
- Terminal-Bench 2.1: **62.9%** (Microsoft), **measured inside GitHub Copilot CLI**, averaging **17.0K tokens**. vs MAI-Code-1-Flash 51.7%, GPT-5.4 mini 60.7%, Claude Haiku 4.5 49.4%; beaten decisively by DeepSeek-V4-Flash-0731 at 82.7%, SWE-1.7 at 81.5%, SWE-2 at 92.8% and Qwen3.8 Max at 86.6%. Note that **TB 2.0 (54.8%) and TB 2.1 (62.9%) are different benchmark versions** and the first pass's implicit "22% improvement" reading should not be taken as a like-for-like jump between them.
- Terminal-Bench 2.1 inside GitHub Copilot CLI: **+22% relative improvement** over MAI-Code-1-Flash (Microsoft's claim; harness-specific and not convertible to an absolute score)
- .NET tasks in Copilot: **+15% relative improvement** over the predecessor (Microsoft claim, no absolute number)
- Code survival through commit: **+4%**; return visits **+9%** (Microsoft production telemetry, no absolute scores)
- Token efficiency: **25% fewer tokens** and **25% faster streaming** vs the predecessor (Microsoft claim); the 8.6K-tokens-per-solve figure above is the concrete realisation of it
- **3-bit on-device build:** Microsoft claims it retains "comparable coding performance to its full-precision counterpart on SWE-Bench Verified and Terminal-Bench 2.1" — **no separate number is published for the quantized weights.** A claim of parity, not a measurement.
- Predecessor MAI-Code-1-Flash (2026-06-02, for trajectory reference only): SWE-bench Verified 71.6% at 10.8K tokens, SWE-bench Pro 51.2%, SWE-bench Multilingual 65.5%, Terminal-Bench 2.0 54.8%, ArtifactsBench 36.4%, **GPQA Diamond 84.6%, HLE 18.0%, τ²-Bench telecom 71.7%**, ECI 138.56 (#42 of 398)
- SWE-bench Pro, SWE-bench Multilingual, ArtifactsBench, LiveCodeBench, SciCode, DeepSWE, Vibe Code Bench, IFBench: **no verified public score found for the 1.1-Flash checkpoint itself.** Microsoft's own model card explicitly redirects: *"For more general benchmarks, refer to MAI-Code-1-Flash model card here."* The predecessor's numbers are lineage, not measurements of this model.

### Normalized scores (1–100)

- **Tool use: 72/100** *(unchanged).* Terminal-Bench 2.1 at 62.9% is a real mid-tier terminal-agent number, and the +22% relative gain inside the actual Copilot CLI harness plus tool calling trained on the production harness is meaningful evidence of production agentic quality. The score does not move because **the evidence set did not move**: no new tool-use benchmark appeared, and the second pass established that the existing numbers are vendor-only rather than independently corroborated. Capped hard by the absence of Tau3, GDPval-AA, OSWorld, AutomationBench and any Claw/Toolathon/MCP-Atlas figure — there is no published evidence at all for research, office or MCP-style agentic work.
- **Reasoning: 55/100** *(unchanged, and still the report's heaviest caveat).* **Zero published GPQA Diamond, HLE, LCR, CritPt or AA Index numbers for this checkpoint**, from Microsoft or anyone else. The only supporting material is Microsoft's unquantified "competitive reasoning" claim and llm-stats' very-low-confidence index of 27.5 from two evals. Worth recording explicitly: the predecessor's model card *does* publish GPQA Diamond 84.6% and HLE 18.0%, so the family clearly can score on those — Microsoft simply did not report them for 1.1. That is an absence of disclosure, and it is scored as one. The 3-bit on-device parity claim covers only SWE-bench Verified and Terminal-Bench 2.1 and adds nothing here.
- **Context window: 82/100** *(up from 80).** **256,000 in / 128,000 out** — the first pass recorded the input figure and flagged "max output: not specified by any source"; that gap is now closed by two independent routes plus Microsoft's own 3-bit statement, and a 128K output ceiling removes what would otherwise be a material caveat on long agentic traces. Held at 82 because *zero* retrieval benchmarks exist — no MRCR, RULER, LongBench v2 or AA-LCR — so effective long-context quality remains entirely unmeasured, and 256K is upper-mid rather than top tier.
- **Multimodal: 65/100** *(unchanged).* Confirmed **image-in, text-out** with a stated screenshot-to-prototype capability and explicit image-reasoning support, now sourced to Microsoft's own model-card summary line rather than only a catalog field — solid in the "+image in = 60–70" band. Not higher because there is **no published multimodal benchmark** for this checkpoint, no video or audio path, and text-only output.
- **Coding: 72/100** *(unchanged).** SWE-bench Verified 72.6% at 8.6K tokens per solve and Terminal-Bench 2.1 62.9% at 17.0K tokens put it in the Claude Haiku 4.5 / GPT-5.4 mini tier — respectable, and genuinely competitive *within that price class*, with the 3-bit build extending the same performance to a $0 marginal-cost local path. But the second pass added two pieces of evidence that pull the other way: HokAI's independent framing places it **21st of 31** on SWE-bench Verified against a 77.2% peer median, and it remains well behind DeepSeek-V4-Flash-0731 (TB2.1 82.7%), SWE-2 (92.8%), GLM-5.3-Flash (TB2.1 84.3%) and Qwen3.8 Max (86.6%) on the same benchmark while costing more than several of them. Net: no change.
- **Cost efficiency: 94/100** *(up from 92).* **$0.20 in / $1.20 out with $0.02 cached reads** at a quarter of its predecessor's price already lands around the ~$0.60/$2.20 reference point. Two verified access facts added this pass push it up: **annual GitHub Copilot subscribers pay a 0.25× premium request multiplier** on this model, and **on-device inference carries zero inference charges** — for a user with 120GB+ of RAM the effective marginal cost of local inference is $0. Kept below 95+ because the $0 tier is conditional on hardware and on the still-experimental on-device rollout, and because there is no Free API tier and no standalone pay-per-token API outside Copilot/Foundry.
- **Overall Score: 69/100** *(unchanged).* Arithmetic: **(72 Tool + 55 Reasoning + 82 Context + 65 Multimodal + 72 Coding) / 5 = 346 / 5 = 69.2 → 69.** Cost efficiency (94) is excluded by the v4 rule. The Overall is flat only because two increases (Context +2) and the reasoning floor offset each other; the composition genuinely changed, with cost and context both better-evidenced than a month ago. Best fit: **inside GitHub Copilot, Microsoft Foundry, or — new — your own machine**, for everyday agentic coding in real repositories: feature work, refactoring, repo Q&A, .NET tasks and screenshot-to-prototype, where 62.9% Terminal-Bench 2.1 at ~$0.20/$1.20 with 25% fewer tokens is a genuinely good deal, and where the 3-bit local build removes per-token cost altogether. Do not pick it for frontier reasoning, research, multimodal analysis or hard autonomous coding; those need a frontier or open model that publishes more than two benchmark numbers.
