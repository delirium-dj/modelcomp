## Model card

- **Name:** DiffusionGemma 26B A4B
- **Short description:** Google DeepMind's **experimental open-weights text-diffusion model** — it keeps the Gemma 4 26B-A4B MoE body but **replaces autoregressive decoding with discrete diffusion**, "shifting from token-by-token autoregression to block-autoregressive multi-canvas sampling" and generating text "by iteratively denoising blocks of tokens (a 'canvas') in parallel" ([Google DeepMind model card](https://huggingface.co/google/diffusiongemma-26B-A4B-it)). The entire point is throughput: **15–20 tokens per forward pass, "per user generation speeds exceeding 1100 tokens per second in low batch size settings (H100, FP8)"**. This is a research artefact rather than a product, and the model card is unusually honest about what that costs. Distinct model; the autoregressive `gemma-4.26b-a4b`, `gemma-4-31b`, `gemma-4.12b-unified`, `gemma-4-e4b` and `gemma-4-e2b` all have their own folders.
- **Provider / access:** **Self-hosted only.** Weights on Hugging Face under **Apache 2.0**, runnable via Transformers (`DiffusionGemmaForBlockDiffusion`), vLLM, SGLang, Docker Model Runner, Colab and Kaggle; there is an NVIDIA NIM listing. Critically, the Hugging Face page states **"This model isn't deployed by any Inference Provider"** with 72 outstanding provider requests — **there is no hosted API and therefore no per-token price anywhere**. 683,956 downloads in the last month, 1.29k likes, 33 finetunes, 37 quantizations, 9 adapters.
- **Release / knowledge:** **June 2026** (llm-stats records 2026-06-10; the Hugging Face DiffusionGemma collection is dated Jul 21). **Training data cutoff: January 2025**, stated explicitly on the model card.
- **IDs:** `google/diffusiongemma-26B-A4B-it` (Hugging Face), `diffusiongemma-26b-a4b-it` (NVIDIA NIM). **Free in the only sense that matters here — Apache 2.0 weights, but you supply the GPU.**
- **Context window:** **Up to 256,000 tokens**, with a **1,024-token sliding window** and a **canvas length of 256**. Max output: no separate limit published; generation proceeds canvas by canvas.
- **Modalities:** The spec table lists **Supported Modalities: Text, Image**, while the prose describes "text, image, and video inputs to generate text output" — the reconciliation is that **video is handled as sampled frames**, capped at **60 seconds assuming one frame per second**. Interleaved multimodal input is supported, and Google advises placing image content *before* text. **Images support variable aspect ratio and variable resolution** via a configurable visual token budget of **70, 140, 280, 560 or 1120 tokens** — low budgets for classification, captioning and video; high budgets for OCR and document parsing. Reasoning: **yes, a configurable Thinking mode**, enabled by putting a `<|think|>` token at the start of the system prompt, emitting `<|channel>thought\n…<channel|>` (thoughts must not be replayed into later turns). **Function calling: "native support for structured tool use, enabling agentic workflows."** Native system-prompt support. **35+ languages out of the box, pre-trained on 140+.**
- **Pricing (as of 2026-10-08):** **None published — no inference provider serves this model.** Cost is entirely hardware: the card targets "low-latency, high-speed generation on a single capable accelerator."
- **Architecture:** The most interesting part of this model, and worth stating precisely. **25.2B total / 3.8B active parameters** (the "26B-A4B" name is rounded), **30 layers**, **262K vocabulary**, **8 active experts of 128 total plus 1 shared**, **~550M vision-encoder parameters**. It is **encoder–decoder**: an autoregressive encoder prefills the prompt and builds the KV cache, then a decoder applies **bidirectional attention over the generation canvas**, reaching context through cross-attention. At inference, "rather than generating one token at a time, the model iteratively denoises a full block of tokens using a diffusion sampler. Once a canvas is fully denoised, it is processed by the encoder and appended to the KV cache." Google specifies the sampler exactly: **Entropy-Bounded Denoising with Adaptive Stopping — max 48 denoising steps, temperature decaying linearly 0.8 → 0.4, lowest-entropy token selection under a mutual-information bound of 0.1, full renoising of non-selected tokens**, terminating early only when average canvas entropy drops below 0.005 *and* top predictions are identical across two consecutive steps. It also gets **adaptive inference-time computation for free**: "simpler prompts and structured tasks like code require fewer denoising steps."

### Raw benchmarks found

> **Two things make this benchmark set unusual.** First, Google publishes the **autoregressive Gemma 4 26B A4B alongside it in the same table** — a rare, deliberate disclosure of exactly what the diffusion approach costs. Second, the independent numbers and the vendor numbers **diverge sharply on agentic work and converge on HLE**, which is itself diagnostic. All vendor figures are "for instruction-tuned models, with the recommended **Entropy Bound (EB) sampler**" — sampler choice matters a great deal for a diffusion model, and is the most likely explanation for the GPQA gap below.

**Google's own table — DiffusionGemma vs. the autoregressive Gemma 4 26B A4B it is built on:**

|---|---|---|---|
| MMLU Pro | **77.6%** | 82.6% | −5.0 pp |
| MMMLU | **81.5%** | 86.3% | −4.8 pp |
| GPQA Diamond | **73.2%** | 82.3% | −9.1 pp |
| AIME 2026 (no tools) | **69.1%** | 88.3% | **−19.2 pp** |
| LiveCodeBench v6 | **69.1%** | 77.1% | −8.0 pp |
| Codeforces ELO | **1429** | 1718 | **−289 Elo** |
| Tau2 (average over 3) | **56.2%** | 68.2% | −12.0 pp |
| BigBench Extra Hard | **47.6%** | 64.8% | **−17.2 pp** |
| HLE (no tools) | **11.0%** | 8.7% | **+2.3 pp** |
| HLE (with search) | **11.9%** | 17.2% | −5.3 pp |

The only row DiffusionGemma wins is **HLE without tools (11.0% vs 8.7%)**, and it loses the with-search variant. Google publishing this table at all is to its credit.

- **Tau3-Banking: 6.6% Pass@1** — 119th of 176, 33rd percentile (field leader 50.3%)
- **GDPval-AA: 554 Elo** (547.26 in breakdown), **2.4% normalized** — 223rd of 352, 37th percentile
- **AA-Omniscience: −59.03** — deeply negative
- **CritPt: 0.3%**; **Agentic Index: 2.2**
- BenchmarkList's own head-to-head summary: **0 wins, 41 losses** across shared benchmarks against Fable 5.1, Opus 5, Kimi K3, Qwen3.8, MiMo-V2.6-Pro, Opus 5.5 and GPT-5.6 Sol; **last of 8**

**Documented capabilities without benchmarks:** object detection, document/PDF parsing, screen and UI understanding, chart comprehension, multilingual OCR, handwriting recognition, pointing, and video description by frame sequence. Safety: Google states DiffusionGemma "undergoes the same rigorous safety evaluations as our proprietary Gemini models", tested **without safety filters**, with "major improvements in all categories of content safety relative to previous generations of Gemma models… while keeping unjustified refusals low" — no numbers published.

### Normalized scores (1–100)

- **Tool use: 22/100.** The clearest finding in this report: **diffusion sampling appears to break long-horizon tool use.** Google advertises native function calling and reports Tau2 at 56.2%, but every independent agentic measurement collapses — **Agentic Index 2.2**, **Tau3-Banking 6.6% Pass@1** (33rd percentile against a 50.3% leader), **GDPval-AA 554 Elo / 2.4% normalized**, and **Terminal-Bench 2.1 at 12.4%**, 24th percentile against a 91.4% field leader. BenchmarkList records **zero wins and 41 losses** across shared benchmarks. A bidirectionally-attending canvas denoiser with a 1,024-token sliding window has no obvious mechanism for stable multi-step state, and the numbers match that intuition. Not zero, because function calling genuinely works and Tau2 56.2% is a real vendor figure.
- **Reasoning: 56/100.** Respectably mid-tier on static knowledge — **MMLU Pro 77.6%, MMMLU 81.5%, GPQA Diamond 73.2%, AIME 2026 69.1%** — and the configurable Thinking mode is real. But three things cap it hard. The independent **GPQA of 66.9% is 6.3 pp below Google's own figure**, which means published scores here are **sampler-contingent in a way autoregressive models are not**. **AA-Omniscience at −59.03** and **CritPt at 0.3%** indicate severe factual unreliability on hard material. And the vendor's own table shows the diffusion tax is worst exactly where reasoning depth matters: **−19.2 pp on AIME and −17.2 pp on BigBench Extra Hard** versus the autoregressive sibling. HLE 11.0% is the one honest win.
- **Context window: 46/100.** A nominal **256K window** is generous for a 25.2B model, and Google deserves credit for publishing a real retrieval number instead of a claim: **MRCR v2 8-needle at 128K = 32.0%**. But that is 12.1 pp below the autoregressive sibling's 44.1%, and independent **AA-LCR of 19.7%** (29th percentile) says usable long-context quality is poor. The **1,024-token sliding window** and 256-token canvas are architecturally at odds with long-range coherence. Scored on demonstrated retrieval quality, not on the headline number.
- **Multimodal: 62/100.** The strongest dimension, and legitimately so. **MATH-Vision 70.5%** is a good visual-reasoning result, **MMMU Pro 54.3%** is mid-tier, **MedXPertQA MM 49.0%** shows domain transfer, and the vision engineering is thoughtful — a ~550M encoder, variable aspect ratio, and **five selectable visual token budgets from 70 to 1120** that let you trade OCR fidelity against frame throughput. Capability coverage is broad: detection, PDF parsing, UI understanding, charts, multilingual OCR, handwriting, pointing. Capped because **MMMU Pro is 19.5 pp below the autoregressive sibling** — the largest percentage-point gap in Google's table — **OmniDocBench edit distance is 2.1× worse** (0.319 vs 0.149), video is frames-only at 60 seconds maximum, and output is text only.
- **Coding: 50/100.** A genuinely split result worth separating. On **self-contained generation it is strong — LiveCodeBench v6 69.1% and Codeforces Elo 1429** — and Google notes "structured tasks like code require fewer denoising steps", so code is where the throughput advantage is largest. On **agentic coding it falls apart: SciCode 34.3%, Coding Index 19.66, Terminal-Bench 2.1 just 12.4%** at the 24th percentile. The diffusion tax is also real here: −8.0 pp on LiveCodeBench and −289 Codeforces Elo against the autoregressive sibling. Fast code *generation*, not code *engineering*.
- **Cost efficiency: 74/100.** Hard to score because **no hosted price exists** — Hugging Face explicitly reports no Inference Provider deploys it, with 72 unanswered requests, so this is self-host or nothing. On its own terms the efficiency argument is excellent: **Apache 2.0, 3.8B active of 25.2B total, engineered for a single accelerator, and >1,100 tokens/second per user on one H100 at FP8** with adaptive step counts that make easy prompts cheaper still. 683,956 monthly downloads and 37 quantizations show the ecosystem took it seriously. Docked for the complete absence of a managed endpoint, and because tokens-per-second is only a bargain if the tokens are good enough — which, agentically, they are not.
- **Overall Score: 47.2/100.** Mean of the five non-cost dims (22 + 56 + 46 + 62 + 50) / 5 = 47.2. This is a **research model that trades accuracy for throughput, and Google says so by printing the autoregressive baseline next to every number**. Best fit: **high-throughput single-accelerator text and vision generation where latency dominates and no tool loop is involved** — bulk OCR and document parsing, captioning, screen understanding, summarization, one-shot code generation, and diffusion-LM research. Do not use it for agents: Agentic Index 2.2, Tau3-Banking 6.6% and Terminal-Bench 12.4% are disqualifying. Do not trust it on facts (Omniscience −59.03). And be aware that **its published scores depend on using the Entropy Bound sampler** — independent GPQA came in 6.3 pp lower without it, so reproduce Google's sampling configuration exactly or expect worse than the card promises.
