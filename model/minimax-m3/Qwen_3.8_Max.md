## Model card

- **Name:** MiniMax M3
- **Short description:** **Shanghai-based MiniMax's open-weight frontier coding/agent model** (released **2026-06-01**), pitched as *"the first open-weight model to combine frontier-level coding, a 1M-token context window, and native multimodality (text, image, video) in one system."* It is a **428B-parameter sparse MoE (~22-23B active/token)** on a Grouped-Query-Attention backbone with **MiniMax Sparse Attention (MSA)** — block-level selection over *uncompressed* KVs that MiniMax reports cuts long-context per-token compute to **~1/20** of the prior generation (**~9.7× faster prefill, ~15.6× faster decode vs M2**), which is the real engineering story: it makes the huge window *economically usable* in an agent loop. Coding claims are strong — **SWE-bench Pro 59%** (framed as the **first open-weight model to clear 59%**, beating GPT-5.5 and Gemini on that board) and **SWE-bench Verified 80.5%** — at dramatically low cost. ⚠ **The decisive caveat: every benchmark is vendor-reported** (run on MiniMax infra, reportedly with Claude Code scaffolding) and **M3 had not yet appeared on neutral boards like DeepSWE**, so its standing vs the newest closed releases is *"genuinely unproven."* Weights are under the **non-standard MiniMax Community License** (not Apache/MIT).
- **Provider / access:** **MiniMax** (Shanghai). **Open weights on Hugging Face** (`MiniMaxAI/MiniMax-M3`; technical report arXiv:2606.13392) + MiniMax platform API + OpenRouter (12 providers). **Paid only** (`noFreeId`). Self-hosting is **server-class** (~214GB+ at 4-bit → multiple high-memory GPUs; NVIDIA has published deployment guidance) — not a laptop model. First-party agent product **MiniMax Code** uses a **Producer + Verifier** self-correction loop.
- **Release / knowledge:** Released **2026-06-01**. Knowledge cutoff not stated in the sources reviewed.
- **IDs:** `minimax-m3` / `minimax-ai/minimax-m3` (line: M2.5 < M2.7 < **M3** < M3.1-flash-preview).
- **Context window:** **"Up to 1,048,576 (1M) tokens, with a minimum of 512K guaranteed"** (the official framing is a ceiling, not a flat 1M) and a **very large 512K max output** — the highest output cap in this dataset. MSA is what makes the window economically usable rather than a spec-sheet number.
- **Modalities:** **Text, image, video in → text out** (native multimodality; no audio, text-only output). No dedicated multimodal/vision benchmark was published in the sources reviewed.
- **Pricing (as of 2026-10-23):** **meta.json lists a $0.30 / $1.20 per 1M promo**; MiniMax's **standard API rate is $0.60 / $2.40** (the launch-week half-price promo has likely expired — **verify the current rate card**). Either way it is a **fraction of Claude Opus / GPT-class pricing** (~5% of Opus cost per task per one review), and self-hosting removes per-token cost entirely (for compute). Promotional pricing + lighter enterprise support = fewer deployment guarantees.
- **Architecture:** **428B sparse Mixture-of-Experts, ~22-23B active/token**, Grouped-Query Attention + **MiniMax Sparse Attention (MSA)** — block-level pre-filtering on real, uncompressed key-values (a different bet from KV-compression approaches that trade long-context precision). Supports claimed **8+ hour autonomous coding sessions** and tool-calling/function invocation as core capabilities.

### Raw benchmarks found

Coding / agentic (MiniMax **vendor-reported**, run on MiniMax infra with Claude Code scaffolding; **not yet neutral-board-verified**):

- **SWE-bench Pro: 59.0%** — framed as the **first open-weight model to clear 59%**, ahead of GPT-5.5 and Gemini on that board (ofox.ai / mindstudio / datanorth coverage)
- **SWE-bench Verified: 80.5%** (meta.json; for context, Claude Sonnet 5 = 82.1%, MiMo-V2.6-Flash = 92.0%, Ember-1 = 92.2%, Claude Opus 5 = 97.0%)
- **MCP Atlas (tool use): 74.2%** — vendor-reported
- Also cited: **Terminal-Bench** and **BrowseComp** results (vendor-reported; absolute figures not consistently transcribed)
- **MSA efficiency (vendor-reported):** ~1/20 long-context per-token compute vs prior gen; ~9.7× faster prefill, ~15.6× faster decode vs M2

> Provenance: **All M3 capability figures are MiniMax vendor-reported** — the official model card, technical report (arXiv:2606.13392) and launch coverage (verdent.ai, ofox.ai, mindstudio.ai, datanorth.ai, saascity.io, OpenRouter), run on MiniMax's own infrastructure reportedly with **Claude Code scaffolding**. Per the verdent.ai engineering read (verified against MiniMax's model card/technical report, June 2026), **"M3 hadn't yet appeared on neutral evaluation boards like DeepSWE that would strip away the vendor's own scaffolding,"** so *"the performance picture is MiniMax's own"* and its standing vs the newest closed releases (Opus 4.8, latest GPT/Gemini) is **unproven**. Per methodology these cells are treated as an **upper bound and discounted**. The **1M-ceiling/512K-guaranteed context, 512K output, text/image/video→text modality, $0.30/$1.20 promo pricing and 428B/23B MoE** come from the folder meta.json, corroborated by verdent.ai (which notes standard pricing is $0.60/$2.40 and the promo likely expired). The **MiniMax Community License** (non-standard, not Apache/MIT) is a real commercial-use compliance caveat. No benchmark was invented; where a figure was vendor-claimed but not neutrally verified I say so explicitly.

### Normalized scores (1–100)

- **Tool use: 84/100.** Purpose-built for the agentic loop — tool-calling/function invocation as core capabilities, **MCP Atlas 74.2%**, claimed **8+ hour autonomous sessions**, and the **Producer + Verifier** self-correction loop in MiniMax Code. Held below the frontier because the tool-use evidence is **entirely vendor-reported** (with Claude Code scaffolding), unvalidated on neutral boards, and verdent explicitly advises testing tool reliability on your own harness rather than inferring it from the benchmark.
- **Reasoning: 83/100.** Strong long-horizon task decomposition and multi-step autonomous reasoning are the design center, and **SWE-bench Pro 59%** implies genuine reasoning depth. Capped because **no independent reasoning benchmark (GPQA/HLE/math) was published**, the multi-step claims are vendor-asserted (the 8-hour figure is "a capability assertion, not a verified guarantee of output quality"), and nothing is neutral-board-verified.
- **Context window: 89/100.** A genuine standout — **up to 1M tokens (512K guaranteed minimum)** plus the **largest output cap in the dataset (512K)**, and crucially the **MSA architecture that makes long context economical** (~1/20 compute, ~9.7×/15.6× faster prefill/decode), turning "1M" from marketing into usable repo-scale context. Scored just below the very top because the window is a **ceiling, not a flat guarantee** (512K min), and the MSA economy figures are **vendor-reported**, not independently measured.
- **Multimodal: 80/100.** Native **text + image + video input** (video is a genuine differentiator few coding models have) → **text-only output**. Held below the omnimodal leaders (muse-wonder / mimo-v2.6 at 82, which add audio) because there is **no audio input, no generative output, and no published multimodal/vision benchmark** to verify quality — modality breadth is documented but unproven.
- **Coding: 86/100.** The headline strength — **SWE-bench Pro 59%** (framed as the **first open-weight model over 59%**, ahead of GPT-5.5 and Gemini on that board) and **SWE-bench Verified 80.5%**, with frontier-grade long-context repo work as the target. Discounted from the high-80s because **SWE-V 80.5% trails the 92% open-weight peers** (MiMo-V2.6-Flash, Ember-1) and Sonnet 5's 82.1%, and — decisively — **every coding figure is vendor-run with Claude Code scaffolding and unconfirmed on neutral boards like DeepSWE**, so the "beats GPT-5.5/Gemini" claim is MiniMax's own testing.
- **Cost efficiency: 95/100.** The other standout — **$0.30/$1.20 promo (or $0.60/$2.40 standard)** is a **fraction of closed-frontier pricing (~5% of Opus per task)**, MSA makes long-context calls ~1/20 the compute, and **open weights let you self-host to remove per-token cost entirely**. The best value proposition among frontier-claimed coding models. Minor caveats: promotional pricing may expire (verify the rate card), self-hosting needs server-class hardware (~214GB+ at 4-bit), and the non-standard license adds compliance friction. Scored but **not** counted in the Overall per methodology.
- **Overall Score: 84/100.** Mean of Tool 84 + Reasoning 83 + Context 89 + Multimodal 80 + Coding 86 = 422/5 = 84.4 → 84. Best fit: **long-context, cost-sensitive, self-hostable coding-agent work** — large-repo migrations, multi-file reasoning and high-volume agent loops where the MSA-economical 1M window, open weights (data residency) and ~5%-of-Opus cost address needs the closed API models structurally can't. **Hold off** if you require neutral-board-verified performance before procurement, need a locally-runnable model, or want the most proven closed-frontier quality. Independent read: my **84 sits below the queue's curated 86.6** — the discount is driven by the **entirely vendor-reported, neutral-board-unverified** benchmark picture (verdent's central caution), the **non-standard license**, the **1M-is-a-ceiling** context nuance, and **SWE-V 80.5% below the 92% open-weight peers**, weighed against genuinely excellent context economics, multimodal input and best-in-class cost. Internally consistent: M3 (84) clusters with the other open-weight/efficiency value plays I've scored (ember-1 84, mimo-v2.6-free 84) and sits just below claude-sonnet-5.4 (85) and muse-wonder-1.0 (85), which have family-anchored or independent (AA) verification M3 lacks — an accurate portrait of a compelling but not-yet-independently-proven open-weight wildcard.
