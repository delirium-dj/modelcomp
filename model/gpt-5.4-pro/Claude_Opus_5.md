## Model card

- **Name:** GPT-5.4 Pro — OpenAI's documentation describes it as the "version of GPT-5.4 that produces smarter and more precise responses", using more compute to think harder. No free tier of any kind. Variant/alias flag: **not an independently trained model** — it is the GPT-5.4 base with additional inference-time compute, so GPT-5.4 base results are the correct floor and are labelled as such below. **Superseded by `gpt-5.5-pro` at the identical $30/$180 price**, which matters for every purchasing conclusion here.
- **Short description:** The maximum-compute tier of the GPT-5.4 family, snapshot-dated **2026-03-05**. OpenAI warns that "some requests may take several minutes to finish" and recommends background mode to avoid timeouts. Independent anecdotal evidence confirms the latency cost: on a 5,000-year procedural harbour-town simulation, **GPT-5.4 Pro took 33 minutes where GPT-5.5 Pro completed it in 20** with cleaner code.
- **Provider / access:** OpenAI, **Responses API only** — and more restrictively than its own successor, **the Batch API is also unsupported**, where `gpt-5.5-pro` supports Batch. Chat Completions, Realtime, Live, Assistants, fine-tuning, embeddings, image/video/speech generation, moderation and legacy completions are all unsupported. Supported features: streaming, function calling, file search, image input, image generation, MCP, web search — **note that `structured_outputs` and `prompt_caching` are absent from the feature list**, both of which GPT-5.5 Pro supports. Responses-API tools: function calling, web search, file search, **tool search**, image generation, **apply patch**, **computer use** and MCP — but **no `code_interpreter`, no `hosted_shell` and no `skills`**, a materially narrower agentic surface than GPT-5.5, GPT-5.6 or GPT-6 Astra.
- **Release / knowledge:** Snapshot dated 2026-03-05. **Knowledge cutoff 2025-08-31** — the same as GPT-5.2 and the oldest in the OpenAI range covered here.
- **IDs:** `gpt-5.4-pro`, with a **dated default snapshot `gpt-5.4-pro-2026-03-05`** — pinnable for reproducibility. Standard sibling for routing: `gpt-5.4` ($2.50 / $0.25 cached / $15). **No free-tier ID.**
- **Context window:** **1,050,000 tokens with 128,000 max output.** OpenAI lists **no separate maximum-input cap** for this model (matching GPT-5.5, unlike GPT-5.6 Sol/Terra and GPT-6 Astra, which cap input at 922,000). But the window is penalised three ways over — see pricing and rate limits — and **no retrieval benchmark of any kind has been published** for it.
- **Modalities:** Input: **text and image only**. Output: text only. No audio or video in either direction. Reasoning: yes, with reasoning-token support and **only three effort levels — `medium` (default), `high`, `xhigh`** (no `none`, `low` or `max`), so thinking cannot be switched off. Tool calls: yes, including **computer use** — a vision-grounded capability its own successor `gpt-5.5-pro` does not list. JSON mode / structured outputs: **not listed as a supported feature.**
- **Pricing (as of 2026-10-03):** **$30 / 1M input, $180 / 1M output — and no cached-input discount is offered at all.** Three further penalties, all documented by OpenAI: **prompts over 272K input tokens reprice the entire *session* at 2x input and 1.5x output across standard, batch and flex**; **regional processing (data residency) endpoints carry a 10% uplift**; and there is **no Batch API**, so the usual 50% batch discount is unavailable. For context from OpenAI's own comparison table: GPT-5.4 base is $2.50 / $15 — **12x cheaper on both meters** — and even o3-pro at $20 / $80 undercuts this model.
- **Rate limits — the harshest in this dataset:** Standard **Tier 1 is just 50 RPM / 50,000 TPM**, rising only to 1,500 RPM / 4M TPM at Tier 5. The separate **Long Context schedule for >272K input requests is more restrictive still: Tier 1 drops to 20 RPM / 40,000 TPM**, meaning a single 272K-token request would consume roughly seven times a Tier-1 minute's entire token budget. For comparison, GPT-5.6 Sol and Terra start at 500 RPM / 500K TPM.
- **Architecture:** Proprietary, closed weights. Parameter count and topology: not disclosed.

### Normalized scores (1–100)

- **Tool use: 82/100.** The base floor is respectable — **Tau2-Bench Telecom 92.8%** clears the Tau-family reference, **GDPval wins-or-ties 83.0%** beats Claude Opus 4.7, Terminal-Bench 2.0 at 75.1% and OSWorld-Verified at 75.0% are solid mid-to-upper results, and uniquely among the Pro-tier models here **`computer_use` is a supported tool**, giving it a vision-driven agentic path that `gpt-5.5-pro` lacks. Four deductions keep it well below the frontier band: **no Pro-specific agentic benchmark exists at all**; the Responses tool surface is **materially narrower than its successors — no `code_interpreter`, no `hosted_shell`, no `skills`**; **Tau3-Banking, Claw-Eval, Toolathon and MCP-Atlas are all unreported** (explicit methodology penalty); and the operational envelope is actively hostile to agent loops — **Responses-only with no Batch, multi-minute responses, and Tier 1 capped at 50 RPM / 50,000 TPM** (20 RPM / 40,000 TPM once a request crosses 272K input).
- **Reasoning: 92/100.** The best-evidenced dimension and the only one where Pro-specific measurements exist — and all three are strong. **GPQA Diamond 94.60 ranks #2 of 253 models** and clears the 90%+ reference decisively; **CritPt 30 ranks #9 of 204 and is the highest research-level-physics figure found anywhere in this research pass**, roughly 12 points above Muse Spark 1.2's 18; and **FrontierMath 50 ranks #3 of 60**. Capped at 92 rather than higher because the base model's **HLE at 39.8% without tools falls just short of the 40%+ reference**, **MRCR/LCR and any Intelligence Index value are absent**, **no hallucination measurement exists**, the knowledge cutoff is 2025-08-31, and the three Pro figures come from a single third-party aggregator with no vendor or Artificial Analysis corroboration found.
- **Context window: 92/100.** The nominal **1,050,000-token context with 128,000 output** reaches the ≥1M tier, and like GPT-5.5 it is better specified than its own successors in one respect — **OpenAI documents no maximum-input sub-cap**, where GPT-5.6 Sol/Terra and GPT-6 Astra all limit input to 922,000. But the window is penalised more severely here than for any other model in this dataset. **There is no cached-input discount whatsoever**, so re-reading a 500K-token prefix costs $15 every single turn with no mitigation; the **272K threshold reprices the full session at 2x input and 1.5x output across standard, batch and flex**; and **long-context requests are rate-limited to 20 RPM / 40,000 TPM at Tier 1** — a single 272K-token request exceeds roughly seven minutes of Tier-1 token budget, making the long window effectively unusable below Tier 4. With **no retrieval benchmark published** to demonstrate the window works, 92 reflects a nominal capability that is commercially and operationally throttled.
- **Multimodal: 68/100.** Input is **text and images only** with text-only output and no audio or video, placing it in the methodology's "+image in = 60–70" band. It sits two points above the floor-of-band reading rather than at the ceiling for a clear reason: **not a single multimodal benchmark exists for either variant** — no MMMU, no chart or document-understanding result, no vision figure of any kind — so the image capability is documented and entirely unquantified. The partial offset is that `computer_use` is a *supported tool* here, which means the vision path can actually be driven agentically (unlike GPT-5.5 Pro), and `image_generation` appears as both a feature and a tool; against that, **`structured_outputs` is not listed as supported**, which limits reliable extraction from visual documents.
- **Coding: 80/100.** No Pro-specific coding benchmark has been published, so the score rests on the GPT-5.4 base floor plus the structural argument that extra test-time compute should not reduce coding quality. That floor is mid-tier: **Terminal-Bench 2.0 at 75.1%** is 7.6 points below GPT-5.5's 82.7%, **SWE-Bench Pro at 57.7% loses to Claude Opus 4.7's 64.3%** by 6.6 points, and Expert-SWE at 68.5% is internal and uncomparable. Two further deductions: the tool surface **lacks both a hosted shell and a code interpreter**, which removes the execute-test-iterate loop that modern agentic coding depends on (only `apply_patch` survives); and **SWE-bench Verified, DeepSWE, LiveCodeBench, SciCode and Vibe Code Bench are all absent**, so none of the methodology's coding references can be checked.
- **Cost efficiency: 10/100.** The worst value in this dataset, and the reason is not merely the headline price. **$30 / $180 is 3x the input and 3.6x the output of the $10/$50 anchor that already maps to only ~30**, and **12x its own base sibling's $2.50/$15**. Four aggravating structural facts compound it: **no cached-input discount exists**, so the long-context agent patterns this model is nominally sold for bill at full rate every turn; **there is no Batch API at all**, removing the 50% discount that even `gpt-5.5-pro` offers; the 272K cliff reprices the **full session**; and data-residency endpoints add 10%. The decisive point is that it is **strictly dominated by a same-priced successor** — `gpt-5.5-pro` costs exactly $30/$180, *does* support Batch, and completed the same long-horizon task in 20 minutes where this model took 33. OpenAI's own comparison table even lists **o3-pro at $20/$80**, cheaper on both meters. There is no workload for which this model's price is the right answer.
- **Overall Score: 82.8/100.** Mean of the five non-cost dimensions (82 + 92 + 92 + 68 + 80) / 5 = 82.8 — a genuine reasoning specialist with no remaining commercial rationale. Its capability case is narrow but real: **graduate-level science (GPQA Diamond 94.60, #2 of 253), research-level physics (CritPt 30, #9 of 204 and the best such figure in this dataset) and advanced mathematics (FrontierMath 50, #3 of 60)** — three independently ranked Pro-specific results that most models here cannot match. Everything else argues against it. Do not choose it for agentic work (no Pro agentic benchmark; no hosted shell or code interpreter; 50 RPM / 50K TPM at Tier 1; no Batch), for repository coding (base SWE-Bench Pro loses to Claude Opus 4.7), for any multimodal task (zero vision benchmarks), for long-context work (no cache discount, full-session repricing above 272K, 20 RPM long-context limit), or for anything cost-sensitive. And above all, **route to `gpt-5.5-pro` instead**: identical $30/$180 pricing, Batch support, a broader tool surface, a newer knowledge cutoff and demonstrably faster completion of the same hard task. The only reason to run this model is a requirement to pin the `gpt-5.4-pro-2026-03-05` snapshot specifically.
