## Model card

- **Name:** Solar Mini 4 (Upstage API model id **`solar-mini4`**, dated build **`solar-mini4-260922`**, OpenRouter **`upstage/solar-mini4`**, Artificial Analysis id **`solar-mini4`**, curated id `opencode/solar-mini-4`; the registry slug hyphenates a name Upstage does not)
- **Short description:** Upstage's **agent-optimized compact MoE**, "an **agent-optimized model pretrained from the ground up by Upstage**" that "**activates just 3B of its 35B total parameters per token**". Its stated purpose is not leaderboard position but unit economics: "designed to handle **repetitive tasks—including information retrieval, structured output generation, and tool use—using less compute and at lower cost**". Curated framing ("efficient lightweight model optimized for high-throughput enterprise tasks and fast inference") is directionally right.
- **Provider / access:** **Proprietary** (AA: "License: Proprietary, with weights not released"; "no open release announced"). Served four ways: **Upstage Console API** (`https://api.upstage.ai/v1`, OpenAI-SDK compatible), **Solar Chat**, **OpenRouter**, plus **on-premises deployment by contact** — the last is a commercial arrangement, not an open weight drop: "**although only 3B parameters are active per token, the full 35B model weights must still be loaded into memory**; for on-premises deployment, the **quantized model can run on a single H100 80GB GPU**". **No free tier** (`noFreeId` correct) but promotional access exists and is dated: **70 % launch discount through October 10 UTC** with **standard pricing effective October 1**, and **"free to use on Hermes Agent for a limited time starting October 5"**. API surface for agents is fully documented: **`tools`, `parallel_tool_calls=True`, JSON mode, JSON Schema structured output**, and **`reasoning_effort`** — with the important behavioural note that "**Solar Mini 4 does not use reasoning by default**"; it is a **hybrid** model that must be switched on. Languages: **Korean, English, Japanese**. **Artificial Analysis' provider table shows only a single self-serve endpoint** (listed under `2 Providers (524,288 context window)`), and the sibling registry folder `model/solar-open-2/` is the same vendor's open-weight flagship.
- **Release / knowledge:** **Released September 2026** (AA: "Released September 2026"; dated build `solar-mini4-260922` ⇒ **September 22, 2026**; third-party launch coverage dated September 28–30). **Knowledge cutoff: February 2026** (AA) — one of the few models in this batch with a published cutoff, and it is the *same* cutoff as Upstage's `Solar-Open2-250B`.
- **IDs:** `solar-mini4` / `solar-mini4-260922` (Upstage), `upstage/solar-mini4` (OpenRouter), `solar-mini4` (AA), `opencode/solar-mini-4` (curated). **Aggregator coverage:** **BenchLM has no page — 404** (a genuine negative finding: this model has no BenchLM composite at all, so there is no cross-check against my dimensions). **Artificial Analysis has a live page, fully measured on all four units** (intelligence, speed, cost, verbosity — 4/4, 4/4, 2/4, 4/4), plus a **launch analysis article** (September 30, 2026) carrying per-evaluation numbers, and a **Finance & Accounting Index** entry. Provider benchmark table exists but lists **0 providers** under its own API-provider runs.
- **Context window:** **524,288 tokens in / 131,072 out** — the vendor states "**512K context window**: Supports up to 512K tokens of context and up to 128K output tokens", and the exact limits are **524,288 / 131,072**. There is a live conflict against Artificial Analysis' headline, which states "**Context window 1M**" and "**Maximum output tokens 262k**" — while AA's *own provider table* records endpoints at **524,288**. I score the vendor-documented **524,288 / 131,072** and record the 1M/262k figures as an unresolved aggregator-vs-vendor discrepancy. Curated `meta.json` says "**65,536 total (16,384 out)**" — **wrong by 8×** on both numbers. The **128 K max output is above the 64 K bar**, so no output-side caveat applies, and the window is large enough that Upstage's own guidance is a warning rather than a spec: "a large window also does not guarantee perfect recall across a long document" — but here recall *was* measured (**AA-LCR 83.3 %**).
- **Modalities:** **text in / text out only** (AA: "Modalities: Text input and output only"; vendor/API likewise). No image, audio, video or document-native input — notable because Upstage's *other* products (`Document Parse`, `Information Extract`, `Syn Pro`) do handle documents, and the blog explicitly positions Solar Mini 4 as the **validation layer downstream of them** rather than as a reader. Curated "Text in/out" is **correct**.
- **Pricing (as of 2026-10-08):** **$0.10 per 1M input, $0.01 per 1M cached input (90 % discount), $0.40 per 1M output, standard rates effective October 1, 2026, excluding VAT** (vendor + AA + launch coverage all agree; AA: "cuts per-token pricing by a third to $0.10/$0.40", i.e. the previous generation's rate was ~$0.15/$0.60). A **50 % offer runs on OpenRouter through October 22** (which is why the router page shows $0.05/$0.20). **But the cheap per-token price does not translate into a cheap task**: Artificial Analysis measures **$0.36 per Intelligence-Index task, ranked #161 of 226 in its class against a median of $0.27** — "not priced efficiently for the AI Index vs other models of similar intelligence". AA decomposes it: **$0.30 of that $0.36 is uncached input**, only **48 % of repeated context was actually served from cache** (vs 99 % for GPT-6 Luna max), and reasoning+answer tokens add ~$0.04. Curated `meta.json` says **"$0.20 / $0.80 per 1M tokens"**: **exactly 2× the real standard rate** — stale or promo-inverted; correct before sync.
- **Architecture:** **35 B total / 3 B active per token, sparse Mixture-of-Experts**, proprietary weights, **pretrained from the ground up by Upstage** (no distillation claim made either way). Agent-workload efficiency is the design thesis, with published throughput evidence: internal testing sustained **>70 tokens/s per request at 32 concurrent requests on two H100s** (4 K in / 1 K out, **no prefix caching**, >600 s continuous load); deployment floor is **one H100 80 GB quantized**. AA independently measures **207.9 output tokens/s — #5 of 226** in its class (median 75). The hidden cost is token volume: **88 M tokens to complete the Intelligence Index (#50/226 vs median 81 M)**, of which **88 k output tokens per task, 72 k of them reasoning tokens**, giving **7.1 minutes average decode time per task** — slower per task than GPT-6 Luna (max) at 5.8 min despite Luna's lower 152 tok/s, and more than double Inkling (xhigh)'s 2.8 min.
- **Identity flags:** (1) **Three-way context-window conflict:** curated **65,536** vs vendor **524,288** vs AA headline **1,000,000** — resolved in this report to the vendor figure, with AA's own provider table (524,288) as corroboration. (2) **Pricing is 2× stale** in curation ($0.20/$0.80 vs $0.10/$0.40). (3) **Hybrid reasoning, off by default** — "does not use reasoning by default; set `reasoning_effort`". Any comparison that assumes thinking-mode is on (including most AA Index runs, which used it: 72 k reasoning tokens/task) describes a **different operating point** than the API default a buyer inherits. (4) **Vendor-vs-aggregator agentic split is extreme and must be reported honestly:** Upstage headlines "**47.2 on τ³-Banking**" and "**22.3 % on AutomationBench-AA**", while Artificial Analysis measures the *same* model at **1 % on Terminal-Bench 4.0** — a near-total failure on agentic terminal work, and AA's own summary says flatly "**Agentic coding is a relative weakness**". (5) **Parameter claims are not verifiable:** "as a proprietary model, its size cannot be independently verified" (AA) — the whole "Pareto-optimal for 3B active" framing rests on Upstage's own number. (6) **No BenchLM page**, so no second aggregator exists to triangulate. (7) **Slug check:** folder `solar-mini-4` vs model id `solar-mini4` (no hyphen) vs AA `solar-mini4` — hyphenation drift, but no duplicate folder exists for it (rule-7 otherwise clean); pair with `model/solar-open-2/` (same vendor, same Feb-2026 cutoff, open-weight).

### Normalized scores (1–100)

- **Tool use: 45/100.** This is the model's advertised reason for existing — "**agent-optimized**", "designed to handle … **tool use**", with **`tools`, `parallel_tool_calls`, JSON mode and JSON Schema all documented**, and a vendor **τ³-Banking 47.2** that would sit in this registry's mid-to-upper band if anyone else had reproduced it. The measured picture is much worse, and the gap is the finding: **AutomationBench-AA 22.3 %** (AA-run, real SaaS workflows), **GDPval-AA 1,072 Elo** and **AA-Briefcase 872 Elo** (both far under the ~1,750-Elo frontier anchor this dimension's 90+ band uses), and **Terminal-Bench 4.0 at 1 %** — a near-total failure of agentic terminal work that makes AA state plainly that "**agentic coding is a relative weakness**". No **BFCL / MCP-Atlas / Toolathlon / OSWorld / τ² row** exists independently. So: correct API plumbing, unproven (and partly contradicted) competence — the schema-valid-output, high-volume-retry use case Upstage actually sells is credible; multi-step policy-following at frontier quality is not.
- **Reasoning: 58/100.** **AA Intelligence Index 24.1** is inside this methodology's 20–35 mid band (→ 55–65) but **below its own class median of 26** (#114/226), which is why it lands mid-band rather than at the top of it. Supporting rows are mixed in the same way: **AA-LCR 83.3 %** is genuinely strong, **SciCode 47.6 %** respectable, **HLE 25.8 %** soft. Faithfulness is the interesting part and is scored honestly: **AA-Omniscience Index −11 with 18 % accuracy** is a *negative* index — more wrong than right when it does answer — but the **64 % non-hallucination rate with ~half the questions abstained** is the best behaviour profile in this vendor's batch (compare the 96.7 % hallucination rate recorded for `model/ling-2.6-flash/`), and AA reads it exactly that way: "**low knowledge accuracy rather than a low non-hallucination rate**". Practical consequence for the site: it is **safe-but-ignorant** — usable as a router/extractor, not as a factual answer engine. One structural caveat: **reasoning is off by default**, so the 24.1 describes an operating point the API does not give you unless you set `reasoning_effort`.
- **Context window: 86/100.** **524,288 in / 131,072 out** per the vendor, corroborated by AA's own provider table, putting it in this registry's **500 K–1 M band (85–94)** — and unlike most models at this size claim, the long-context behaviour was **independently measured**: **AA-LCR v1.1 83.3 %**, which AA flags as the model's relative strength, matching MiniMax-M3 and GPT-6 Luna (max) and beating Gemini 3.8 Flash (high) and GPT-6 Astra (max) at 81 %. Output is **128 K**, clear of the sub-64 K penalty. It is held at 86 rather than higher because (a) **83.3 % is not the ≥98 % retrieval rate the 95–100 band requires at 512 K+**, (b) there is **no MRCR / AI-Needle position-sweep** to show front/middle/back recall, and (c) the window figure itself is **contested** — AA's headline says 1M, the vendor says 512K, curation says 64K — an ambiguity the registry must resolve in `meta.json`, not in prose.
- **Multimodal: 15/100.** **Text in, text out, full stop** (AA modality line; no image/audio/video path in the API; no MMMU-Pro row — "Not publicly available"). Upstage's document and vision work is productized separately (`Document Parse`, `Information Extract`, `Syn Pro`, `Studio`), and the launch post positions Mini 4 as the **text validator downstream of those tools**, which confirms rather than softens the gap: you must arrive with text already extracted. No audio input, no image output, no on-model OCR. 10–20 band, no lift.
- **Coding: 38/100.** The one real signal is **AA-SciCode 47.6 %** — scientific problem-solving in code, mid-band (the registry's frontier anchor for this dimension is SciCode 55+), and **Terminal-Bench 4.0 at 1 %**, which is not a weak score but a broken one for repo-in-a-terminal work. There is **no SWE-bench Verified/SWE-Pro/Multilingual row, no LiveCodeBench, no DeepSWE, no SWE-Marathon, no AA Coding Index** for this ID, and the vendor's coding evidence is an **internal three-task "code analysis and review" cost comparison** ($1.25 vs MiMo-V2.5's $2.20 per 1,000 task sets) — a **price** study, not a correctness study. Upstage's own framing is consistent: it markets **code *review* and *classification*** volume work, not feature implementation. Scored low-mid: competent at generating scientific code snippets, unmeasured-to-failing at agentic software engineering.
- **Cost efficiency: 84/100.** On paper this is one of the cheapest capable models on the market: **$0.10 in / $0.01 cached (90 % discount) / $0.40 out per 1M**, standard since October 1, with a **70 % launch discount to October 10**, a **50 % OpenRouter offer to October 22**, and **free Hermes Agent access from October 5**; on the vendor side it is **35 B/3 B MoE that runs quantized on a single H100 80 GB** and sustains **>70 tok/s/request at 32 concurrency on 2× H100**, and AA independently ranks its served speed **5th of 226 (207.9 tok/s)**. The deduction is entirely about what the tokens *do*: **$0.36 per Intelligence-Index task ranks #161/226 — worse than the $0.27 class median**, and "not priced efficiently for the AI Index vs other models of similar intelligence". AA shows why: **88 k output tokens per task, 72 k of them reasoning**, **88 M tokens for the whole Index run ("very verbose")**, only **48 % of repeated context actually cache-hit** (vs 99 % for GPT-6 Luna max at $0.07/task), and **7.1 minutes decode per task**. So a buyer gets frontier-class *rates* and above-median *per-task cost* — cheap extraction, expensive thinking. Curated $0.20/$0.80 must be corrected to **$0.10/$0.40 ($0.01 cached)**.
- **Overall Score: 48/100.** Mean of the five quality dimensions (45 + 58 + 86 + 15 + 38) / 5 = 242 / 5 = 48.4 → 48; Cost excluded per `RULES.md`. Best fit: **high-volume, schema-shaped text work inside a pipeline that already did the hard reasoning** — extraction from parsed documents, classification and routing, JSON/table generation, policy-application over short defined state, retrieval-summarization loops in Korean/English/Japanese, and any agent step where **parallel tool calls and 512 K input matter more than multi-step planning**, at $0.10/$0.40 with a 90 % cache discount. Unfit for **agentic coding or terminal automation** (**TB 4.0 1 %**, AutomationBench 22.3 %, no SWE/LCB row), for **factual Q&A** (**Omniscience −11 / 18 % accuracy** — though its 64 % non-hallucination makes abstention safe), and for **multimodal or document-native work** (text-only; use Upstage's `Document Parse` in front of it). Two operating notes a site reader needs: reasoning is **off by default**, and the advertised cheapness is **per token, not per task**. **Curation fixes before sync:** `contextWindow` → **524,288 in / 131,072 out** (and reconcile AA's 1M/262k claim); `pricingNote` → "**$0.10 / $0.01 cached / $0.40 per 1M in/out (standard from Oct 1 2026; 70 % launch discount to Oct 10)**"; `short` → name the **35 B/3 B MoE agent-workload** framing and the **τ³-Banking 47.2 vs Terminal-Bench 4.0 1 %** split.
